直しは v3.1.0（アプリ内の歌詞取得）が仕上がってから、v3.1.1 としてまとめて入れる。

## 結論

- 任意のプログラムを動かす・外へデータを送る・データフォルダの外へ書く、に直結する穴は見つからなかった
- XSS（曲名・歌詞のスクリプト）、SQL 注入、explorer の引数注入、zip slip（`..` や絶対パス）、ジャンクションのループは、試した範囲で塞がっていた
- 見つかったのは「細工したファイルで落ちる・固まる・メモリを食い尽くす」と「設定 zip 経由の想定外の動き」

## 直さないもの（情報）

- アートワークの鍵が FNV-1a 64bit（衝突を作れればサムネが差し替わる）。暗号用途でないため今回は見送り
- `Command::new("explorer.exe")` がアプリのフォルダを先に探す（隣に偽 explorer.exe を置ける相手なら exe 自体も置き換えられる）
- ログ行の改行（ログの偽造ができる程度）
- `name.contains("..")` が `a..b.png` も捨てる（アプリ自身は `bg-<hash>` で書き出すので実害なし）
- 巨大な中身ゼロの mp3 で `read_track` が約15秒（取り込み経路では先に弾かれる）
- WebView2 ランタイム自体の更新確認は、このアプリの外
