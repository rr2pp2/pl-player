## 0. この表で見たもの・見ていないもの

**見たもの（作者の作業ルール「落とす前」）：**配布元が公式か／最終更新／利用実績（直近の取得数）／ライセンス／入れるときに走るスクリプトの有無（npm のみ）／公開情報から分かる通信。
**見ていないもの（「落とした後」）：****実行されるファイルの全読み・通信箇所の grep・秘密情報に触る箇所・難読化の確認は、落としていないのでできない。**
落としたあと、動かす前に実装担当（または検査担当）が行う。**その結果で外す依存が出たら、ここへ戻る。**

**v3.2.0 の miniz_oxide の注：**人が Windows のエクスプローラーなどで作った zip は項目が圧縮（deflate）されていて、設定の zip 用の自前の部品（無圧縮だけ）では読めない。戻す部品は Cargo.lock に `miniz_oxide` 0.8.9（`png` が使う）と 0.9.1（`flate2` が使う）の2つがもとからあった。0.8.9 を選んだのは、`decompress_to_vec_with_limit`（戻した大きさが上限を超えたら止める）が1回の呼び出しで使え、`flate2` を足すより名指す部品が少ないため。機能は既定（`with-alloc`）のままで、`png` が有効にしている `simd` の部品（`simd-adler32`）ももとから lock にある。Cargo.lock の変化は、pl-player の依存の欄に1行増えただけ。新しい取得が起きないことは `cargo build --offline` が通ることで確かめた。外への通信は無い（展開の計算だけの部品）。

**ライセンスの注意：**symphonia は **MPL-2.0**（ファイル単位の弱いコピーレフト）。改変して配布するときだけ、その改変したファイルの公開が要る。**改変せずに使う前提**にする。

| いつ | どこへ | 何を |
