## 1. 全体の形

```
┌──────────────── 画面（React + TypeScript、WebView2 の中） ────────────────┐
│ 背景レイヤ → 覆いとぼかし → UI（サイドバー／上の検索／曲一覧／下の再生バー）     │
│ 状態は「表示用の写し」だけを持つ。再生の正しい状態は Rust 側にある              │
└──────────────┬──────────────────────────────▲────────────────────────────┘
               │ 命令（invoke）                │ 通知（event）
┌──────────────▼──────────────────────────────┴────────────────────────────┐
│ commands：画面との窓口。薄く保ち、判断を持たない                               │
├───────────────────────────────────────────────────────────────────────────┤
│ playback（再生の進め方）：キュー・シャッフル・リピート・前後の曲・状態の保存     │
│   ▲ 画面・SMTC・ホットキー・タスクバー・トレイの操作は、全部ここを通る           │
│   ▼ 音を出す指示だけを audio へ                                               │
├──────────────────────┬────────────────────────────────────────────────────┤
│ audio（音声エンジン）  │ library（取り込み・タグ）／db（SQLite）／settings     │
│ 専用スレッドで動く     │ platform/windows（SMTC・サムネイルボタン・デバイス通知）│
└──────────────────────┴────────────────────────────────────────────────────┘
```

**UI と音声エンジンを密結合させない（原文「重要」）ための決まりは3つ。**

1. **画面は audio を直接呼ばない。**必ず playback を通す。SMTC・ホットキー・サムネイルボタン・トレイも同じ
2. **audio は「次の曲」を知らない。**渡された1曲を鳴らす・止める・位置を変える・出力先を変える、だけ。曲順は playback が持つ
3. **audio とのやりとりは、命令の通り道（チャネル）と通知の通り道の2本だけ。**audio の中の型を外に出さない

## 3. 画面

### 3-1. 層（原文2通目の3層）

| 層 | 中身 | 作り |
|---|---|---|
| 1 | 背景画像 | `object-fit: cover` を既定にする。画像は Tauri の asset プロトコルで読み、読める範囲はアプリのデータフォルダと、ユーザーが選んだ背景ファイルだけに絞る |
| 2 | 覆い＋ぼかし | 暗さ・ぼかし・UI の透明度は設定値。CSS 変数で渡す |
| 3 | UI | パネルは `rgba(15,15,22,0.70)`（Dark）。文字の読みやすさは「覆いの濃さ」で守る |

### 3-2. 色とテーマ

- **色・角丸・影・動きの時間は、全部 CSS 変数（`theme\tokens.css`）にする。**原文2通目の値をそのまま既定値に入れる
- Dark と Light は、変数の値を差し替えるだけの別ファイル。**テーマを足すときはファイルを1つ足すだけ**（原文「将来的に拡張できる構造」）
- **Light の「反転」の具体的な色は、原文に値が無い。**実装担当が Dark の値から反転で作り、画面で見せて確かめる
- 動きは 100〜250ms。hover・パネル・ページ・背景・再生状態の切り替えにだけ使う。常に動くものは置かない

### 3-3. 幅が狭くなったとき（原文の順番をそのまま実装する）

| 幅（目安） | 減らすもの |
|---|---|
| ウィンドウの幅 1100px 未満 | 1. サイドバーをアイコンだけに縮める（手動の折りたたみとは別に自動でも） |
| 曲一覧の側の幅 806px 未満 | 2. 列を減らす：Genre を隠す（726px 未満で Album も） |
| 曲一覧の側の幅 626px 未満 | 3. ジャケットを縮める（44px → 36px）。自動のコンパクト表示・上の帯のファイル・フォルダの文字も同じ段 |
| 曲一覧の側の幅 518px 未満 | 4. 行の高さを縮める（60px → 48px） |

**幅の数字は原文に無い。**ここに書いたのは置き値で、実装担当が画面で当てて決める。
**レイアウトは CSS Grid と Flex だけで組む。**絶対座標は使わない（原文の禁止事項）。
ウィンドウの最小サイズは `tauri.conf.json` で 480×480（v3.8.0。3.7.0 までは 480×360）。
v3.8.0 「詳細」（ミキサーを出しておく表示）では、曲一覧の側の幅がミキサーのぶん狭くなる。上の表の 2〜4 はその幅で決まる（だから曲一覧の側の幅で決める作りにした）。

**v3.8.0 で変えた所**（同時再生と配信モード。元の案は「ウィンドウの幅 900・820・720・600px」と「ジャケット 48px・行 64px」）：
- 2〜4 は、ウィンドウの幅ではなく**曲一覧の側（`.main`）の幅**で決める（`src\layout\density.ts` の `LIST_BELOW`。あとの版で曲一覧の横に別の欄を並べたとき、曲一覧だけが狭くなるため）。境目は、サイドバーが自動でたたまれる窓では「曲一覧の側の幅＝ウィンドウの幅 − 94」なので、元の値をこの式で置き換えた。行の高さだけは、窓の幅 600px 未満で外の余白が縮む都合で、窓の幅 600〜611px のときに 3.7.0 と違う（48px）
- ジャケット 44px・行 60px は v3.7.0（デザインの見直し）の値
- 再生バーは幅の段で縮めない。再生バーの幅に中身が入るかどうかで、3列と1段（高さ 76px）を切り替える（`src\layout\playerLayout.ts`。README の「再生バーの形」）

### 3-4. ショートカット

- **アプリ内**（Space・Ctrl+→ など原文の10個）：画面側の `shortcuts\` で受ける。検索欄などに文字を打っている間は効かせない
- **グローバル**（バックグラウンドでも効く）：Rust 側の `platform\windows\hotkeys.rs` で登録する。**既定では1つも登録しない**（Space などをグローバルに取ると他のアプリが壊れるため）。ユーザーが設定画面で個別に決める
- 登録に失敗したら（他のアプリが使用中）、そのキーを赤く示し、日本語で「このキーは他のアプリが使っています」と出す

## 4. 音声エンジン（`src-tauri\src\audio\`）

**「デコード」と「出力」を分ける。**ここがデバイス切り替えで作り直しにならないための要。

```
デコードのスレッド：Symphonia（＋libopus）で読む → rubato で出力先のレートへ変換 → 受け渡しの輪（リングバッファ）
出力のコールバック：cpal（WASAPI）が輪から取り出して鳴らす。鳴らしたフレーム数を数える
```

| 場面 | 動き |
|---|---|
| 再生位置 | **「実際に鳴らしたフレーム数」から出す。**デコードした位置ではない。だから切り替えても位置がずれない |
| シーク | デコーダを指定位置へ動かし、輪を空にする |
| デバイスの切り替え | 出力だけを止める → 鳴らした位置を覚える → 新しいデバイスで cpal のストリームを開く → レートが違えば変換器を作り直す → 覚えた位置へシークして再開。**曲も位置も保たれる** |
| 切断（`DeviceNotAvailable`／`StreamInvalidated`） | 既定のデバイスへ切り替え、上と同じ手順で続ける。画面に「◯◯が切断されたので、△△で再生を続けます」と出す。既定デバイスも無ければ一時停止して知らせる |
| 一覧の更新 | `platform\windows\device_watch.rs` が Windows の通知を受け、**コールバックの中では何も待たずに**通知の通り道へ流すだけ（公式の制約） |
| 通知の頻度 | 再生位置は 1 秒に 4 回ほど。状態の変化・曲の終わり・エラーはその都度 |

**音量とミュートは audio の中で掛ける**（OS の音量ミキサーは触らない）。

### 4-1. v3.8.0 の同時再生（出力先3つまで。音の側）

正は仕様書「同時再生と配信モード」（非公開）の 2章・13章。上の表のうち「再生位置」「デバイスの切り替え」「切断」は、v3.8.0 で次のように変えた。

```
デコード：Symphonia（＋libopus）→ 曲の側の輪（2ch・曲のレート・2秒ぶん。song_ring.rs）
出力ごと（lane.rs）：曲の側の輪の「時計 − 遅らせ量」の位置から読む → 倍率を動かせる変換器（同じレートは rubato の Slip、違うレートは Async）
                     → 2ch を出力のチャンネル数へ（1ch は左右を足して半分）→ 出力の受け渡しの輪（0.5 秒）
出力のコールバック（output.rs）：自分が書くフレームの番号を数え、門（base）より前は無音、遅れた分は読み捨てる。
                     音量を掛け、メーターの値（左右の最大）を原子変数に残す。ロック・確保・ログ出力はしない
```

| 場面 | 動き |
|---|---|
| 再生位置・曲の終わり | **仮想の再生時計**（QPC の上。sync.rs の `Clock`）が決める。出力が無くても（全部オフでも）進む。曲の終わりは「曲の長さ＋オンの出力の遅らせ量の最大」 |
| 時計の速さ | 基準の出力1つに寄せる（開いて約2秒の揺れがいちばん小さいもの。差が 0.2ms 未満なら枠の番号が小さいほう）。基準は伸び縮みさせない＝**出力が1つなら 3.7.0 と同じ音**（同じレートなら Slip の倍率 1.0 は入力そのまま）。基準を失っても時計は直前の速さのまま、位置は跳ばない |
| ほかの出力のずれ | 書くフレームが鳴る時刻（コールバックの時刻を直線で当てはめたもの）と、そこで鳴るべき曲の位置（時計 − 遅らせ量）を比べ、約100ms ごとに倍率を決め直す。速さの項（長い当てはめの傾き）＋位置の項（PI 制御。不感帯 ±1ms）、倍率は ±0.1% で頭打ち。20ms を超えたら入り直す |
| 開始時刻の門 | 再生開始・再開・シーク・曲の切り替え・途中でオン・戻ってきた出力は全部、「今＋80ms」に鳴るフレームから、その時刻の時計の位置を鳴らす（約10ms で音を上げる）。開いた直後の出力は約200ms 測ってから |
| 輪を空にする | 世代番号（原子変数）を上げ、コールバックが空にして世代を返す（3.7.0 の Mutex と `try_lock` をやめた） |
| 切断 | その枠だけ「切断中」にして手放す。既定のデバイスへは移らない。知らせの直後、0.5・1・2 秒あけて試し、そのあと一覧にある間は 5 秒おき。戻ったら「○○が戻りました」。オンの出力が全部鳴らせなくなったら一時停止（戻っても自動では再生しない） |
| 開けません | 一覧にあるのに開けない（形式が使えない・ほかのアプリが独り占め・それ以外）。切断中か開けませんかは、cpal のエラーの種類ではなく、開けなかったときに一覧を引き直して決める。デバイスの既定の形式（F32・F64・I16・I24・I32・I64・U8）のまま開く |
| デバイスを開く | 別のスレッド（`pl-audio-open`）が開き、開けたストリームを音声スレッドへ渡す。開くのに時間がかかる機器（Bluetooth など）や、5 秒おきのつなぎ直しでも、鳴っているほかの出力への書き込みを止めない。開いている途中にオフ・差し替えをしたら、届いた結果は捨てる（デバイスを手放す）。開く役の中で部品が panic しても開く役は止まらず「開けません（その他）」として返し、開く役がいなければ頼んだ印を残さず試し直しに回す。開く役が実際に開き始めてから 10 秒たっても結果が来なければ「開けません（その他）」と出し、鳴らせる見込みとしては数えない（`tuning::OPEN_TIMEOUT_MS`。暫定）。ただし頼みは取り消さず、新しい頼みも積まない。結果が届けば、その枠がまだ同じデバイスを欲しがっている限り採るので、10 秒を超えて開く機器もいずれつながる。音声スレッドは枠ごとに「今欲しい頼みの番号」を開く役と共有し、開く役は番号の合わない古い頼みを開かずに捨てる（捨てる結果のためにデバイスを一瞬掴まない）。**残る制限**：開く役は1つなので、ドライバが返らない機器が1台あると、ほかの枠の開く頼みもその後ろで待つ（音声スレッドと、開いている出力は止まらない）。そのあいだにオンにした枠は、開く役が開き始めないので 10 秒の上限も数えられず、状態は「正常」のまま鳴らない（鳴らせる見込みとして数えるので一時停止もしない。2026-11-16 の検査で分かり、直さずに出す）。また、既定のデバイスの重複の確かめと、曲を開く前の「一覧にあるか」の確かめは、音声スレッドで一覧を引く（開くより短いが、デバイスの知らせ・出力先の変更のときに少し止まりうる） |
| 重複 | 既定のデバイスを選んでいる枠が、ほかの枠と同じデバイスになったら鳴らさない |
| 仮の値 | 不感帯 ±1ms・倍率の上限 1.001・輪 1000ms などは `audio\sync.rs` の `tuning` の1か所。作者の実機の計測で決め直す |

**出力先の設定**（`playback\outputs.rs`）は DB の settings 表のキー `outputs`（JSON）に置き、**Rust だけが書く**（画面は細かい操作のコマンドを送るだけ。変わるたびに `pl://outputs` で全部を送る）。表示のモード（通常／詳細）はキー `mode`。3.7.0 から上げたときは、今のデバイスを出力先1・オンで入れ、今の音量を通常用・詳細用の両方の全体の音量にする。外した出力先は、デバイスごとに新しいものから 32 件覚える（期限なし。デバイスを差し替えたときの前の設定も）。

**メーター**（`commands\outputs.rs`）は、画面が Tauri の Channel を渡している間だけ、約 33ms ごとに枠3つの左右の最大を送る（窓が最小化・隠れている間は送らない）。dB への換算・最大の線・音割れの印は画面側。**黄の帯（-20〜-9 dB）の色は、新しい変数を足さず `--c-favorite` を使い回す**。

**画面の側**：
- 出力先の写しは `src\stores\outputs.ts`（`pl://outputs` を受けるだけ。書くのは Rust）。メーターは同じファイルの `subscribeMeter` が受け口で、見ている部品（ミキサー・出力のプルダウン）が1つでもある間だけ `meterStart`、いなくなるか窓が見えなくなったら `meterStop`。dB・帯の動き（OBS の既定と同じく、上がるときはすぐ、下がるときは 40 dB / 1.7 秒）・直前の最大の線（20 秒）・音割れの印（2 秒）は `src\layout\meter.ts`（枠ごとに1つだけ持ち、どの部品にも同じ値を渡す）。開始と停止には画面が通し番号を付け、Rust（`commands\outputs.rs` の `MeterControl`）はいちばん大きい番号だけを効かせる（非同期のコマンドの実行が入れ替わっても、遅れて着いた停止が新しい開始を止めない）。開始に失敗したら、見ている部品が残っていれば 1 秒後に試し直す。描くのは `src\components\Meter.tsx` で、形は1回だけ描き、値が来るたびに参照から style と文字を直接書く（React の再描画を起こさない）
- 再生バーの出力ボタンとプルダウンは `src\layout\OutputButton.tsx`、詳細のミキサーは `src\layout\Mixer.tsx`。名前・アイコン・状態の文字・選べるデバイスの決まりは `src\layout\outputs.ts`
- 詳細の配置（左右か上下か・ミキサーの幅と高さ・流れる歌詞の列を自動で隠すか）は `src\layout\detailLayout.ts`（純粋な関数）。ミキサーは `.app` の格子に1つ足す（左右は3列目、上下は曲一覧の下の行）。詳細かどうかは Rust が持ち（キー `mode`）、表示の通常／コンパクト（`ui.compactList`・`ui.compactAuto`）とは別の値なので、詳細を抜けると入る前の表示がそのまま出る

## 5. データベース（`src-tauri\src\db\`）

SQLite（rusqlite の `bundled`）。**WAL モード**にして、読み込み中でも書き込みで画面が止まらないようにする。

| 表 | 主な列 | 要点 |
|---|---|---|
| `library_folders` | path・サブフォルダを含むか・追加日時 | 「フォルダ追加」の記録。再走査に使う |
| `tracks` | id・**path（一意）**・大きさ・更新日時・形式・長さ・タグ10項目・アートの有無・追加日時・最終再生日時・再生回数・お気に入り・**見つからない印** | **音声ファイルはコピーしない。パスを持つだけ**（原文） |
| `tracks_fts` | title・artist・album | FTS5（trigram）。`tracks` と同期させるトリガを置く |
| `playlists` / `playlist_items` | 名前・並び順／プレイリストID・位置・曲ID | 並び替えは位置の振り直し |
| `queue_items` | 位置・曲ID | キュー |
| `playback_state` | 現在の曲・位置・音量・ミュート・シャッフル・リピート・出力デバイスID | 1行だけ |
| `settings` | キー・値（JSON） | テーマ・背景・UI・ショートカット・ホットキー・トレイの振る舞い |
| `album_art_overrides` | アルバムの鍵・画像の保存先 | 外部画像を設定したアルバム |

**検索：**曲名・アーティスト・アルバムを、打つたびに引く（原文「リアルタイム検索」）。
3文字以上は FTS5、**1〜2文字は LIKE**（trigram が3文字未満を引けないため）。画面側で 120ms ほど待ってまとめて引く。
**索引：**artist・album・genre・追加日時・最終再生日時・お気に入りに張る。

**画像は DB に入れない。**埋め込みアートの縮小版と、ユーザーが設定した外部アート・背景は、アプリのデータフォルダ（`%APPDATA%\<識別子>\`）の下に保存する。
**音声ファイルはコピーしない。画像だけは複製する**（設定の書き出しで持ち運べるようにするため）。

## 6. 取り込みとタグ（`src-tauri\src\library\`）

- **取り込み**：ファイル選択・複数選択・フォルダ追加（サブフォルダまで）・ドラッグ＆ドロップの4経路を、全部同じ `import.rs` に流す。走査は別スレッドで行い、進み具合を画面へ通知する
- **対応形式の判定**：拡張子で候補を絞り、中身は Symphonia で確かめる。開けないものは「非対応形式」として数え、最後にまとめて知らせる
- **タグの書き込み**：`技術調査.md` 7章の5段階（同じフォルダに一時ファイル → 書く → 読み直しと復号で確かめる → `ReplaceFileW` → 失敗なら一時ファイルを消す）
- **再生中の曲のタグを書くとき**：差し替えの前に、その曲のデコーダを閉じて位置を覚え、差し替え後に開き直す

## 8. 状態の保存と、設定の書き出し

- **保存の時機**：終了するとき・曲が変わったとき・10秒ごと（位置）。**落ちても最後の数秒しか失わない**
- **復元**：起動時に `playback_state`・`queue_items`・ウィンドウの位置と大きさを戻す。**自動では再生しない**（一時停止で位置だけ戻す）
- **書き出し**：テーマ・背景・UI 設定・ショートカット・プレイリスト・お気に入り・ライブラリ設定を、1つの zip（中身は JSON と背景画像）にまとめる。曲は**パス**で持つので、別の PC で読み込むと見つからない曲が出る。読み込みのときに件数を知らせる
- **出力先の設定（v3.8.0）**：zip に `outputs.json` として入れる（登録したデバイスの ID と名前・外した出力先の覚えも全部）。読み込むときは、ほかの JSON と同じく全部を確かめてから書き（枠は3つまで・同じデバイスが2つの枠に無い・遅らせ量 0〜1000・音量 0〜1・覚えは32件まで・名前と ID の長さ。外れたら zip 全体を断る。知らないアイコンは自動に読み替える）、**一時停止して出力先を全部オフで入れる**（自動では再開しない）。`outputs.json` の無い zip（3.7.0 まで）では出力に触らず、一時停止もしない。表示のモード（通常／詳細）は入れない
