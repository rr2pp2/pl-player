作成：2026-11-12

## 0. 前提

- アプリは外へ一切通信しない。今回も通信の部品を入れない（**v3.1.0 で例外を1つ足した**：設定でオンにしたときだけ LRCLIB から歌詞を取る。既定はオフ。10章）
- **依存を新しく足さない。**版はロックファイルで固定している
- 曲ファイルには書き込まない。歌詞のタグは読むだけ。既存のタグ書き込み処理（`tags_write.rs`）につながない
- 既存の決まりごとを守る：操作は `playback` を通す／`audio` は触らない／`commands` は薄く／画面から Rust を呼ぶのは `src/ipc/` だけ／日本語の文は `src/messages/ja.ts`
- 歌詞をネットから取る一括スクリプトは、この作業の範囲外（当時は別の非公開スクリプトで行った。v3.1.0 でアプリの中に入れた：10章）

## 2. 歌詞の持ち方

### 2.1 ソースと優先順

| 優先 | 種類 | どこから | 保存 |
|---|---|---|---|
| 1 | `manual` | 歌詞の編集画面で保存したもの | SQLite |
| 2 | `external` | 受け渡しフォルダから取り込んだもの | SQLite |
| 3 | `embedded_tag` | 曲ファイルの歌詞タグ | 保存しない。表示のたびに読む |

- `manual` があれば必ずそれを出す。外部の取り込みは `external` だけを更新し、`manual` に触らない
- `manual` を消すのは「手動の歌詞を削除」だけ（確認を挟む）。消したら `external`、次に `embedded_tag` に戻る
- 曲ごとの時刻補正（`user_delay_ms`）は歌詞とは別に持つ

### 2.2 SQLite（移行 2）

`db/mod.rs` の `MIGRATIONS` に `(2, include_str!("migrations/002_lyrics.sql"))` を足す。

```sql
CREATE TABLE IF NOT EXISTS lyrics_sources (
    id          INTEGER PRIMARY KEY,
    track_id    INTEGER NOT NULL REFERENCES tracks(id) ON DELETE CASCADE,
    source_kind TEXT NOT NULL CHECK (source_kind IN ('manual', 'external')),
    raw_text    TEXT NOT NULL,
    format      TEXT NOT NULL CHECK (format IN ('timed', 'plain')),
    updated_at  TEXT NOT NULL,
    UNIQUE (track_id, source_kind)
);
CREATE TABLE IF NOT EXISTS track_lyrics_settings (
    track_id      INTEGER PRIMARY KEY REFERENCES tracks(id) ON DELETE CASCADE,
    user_delay_ms INTEGER NOT NULL DEFAULT 0,
    updated_at    TEXT NOT NULL
);
```

- `raw_text` は読み込んだ原文（改行だけ LF にそろえたもの）。語ごとの時刻なども消さない
- 既存の表・FTS5・トリガには手を入れない。移行中に全曲を読み込まない

### 2.3 曲ファイルの歌詞タグ

- lofty 0.25.4 で読む。MP3 の USLT は `ItemKey::UnsyncLyrics`、M4A の `©lyr` は `Lyrics`／`UnsyncLyrics`
- 空でない最初の1件を使う。言語での選び分けはしない
- 読めなくてもエラー画面にしない。警告にとどめ、歌詞なしとして扱う
- 中身に時刻タグがあれば時刻つきとして読む

## 3. 受け渡しフォルダ（外部ツール → アプリ）

```text
<データフォルダ>\lyrics\
├─ inbox\       外部ツールが書く
├─ processed\   取り込み済みを移す
└─ rejected\    取り込めなかったものを移す
```

- `PL_PLAYER_DATA_DIR` があればその下
- ファイル名は `{曲ID}.lrc`（時刻つき）か `{曲ID}.txt`（時刻なし）だけ。正規表現 `^[0-9]+\.(lrc|txt)$` に合わないものは読まずに残す（書きかけの一時ファイルを拾わないため）
- 文字コードは UTF-8。BOM があれば外す。改行は CRLF・CR・LF のどれでも LF にそろえる
- 1ファイル 1MiB まで

取り込みは**ボタンを押したときだけ**行う。フォルダの監視はしない。

| 場合 | 扱い |
|---|---|
| 曲 ID が `tracks` に無い | `rejected` へ |
| 同じ曲 ID に `.lrc` と `.txt` の両方がある | 両方 `rejected` へ |
| UTF-8 として読めない | `rejected` へ |
| 空・空白だけ・1MiB 超 | `rejected` へ |
| 取り込めた | `external` に上書き保存し、`processed\{曲ID}-{yyyyMMdd-HHmmss}.{拡張子}` へ移す |
| 取り込めたが、その曲に `manual` がある | 同じく保存して移す。表示は `manual` のまま。件数を分けて数える |
| DB への保存に失敗 | ファイルは `inbox` に残す |

- 拡張子は目安で、中身に有効な時刻タグがあれば時刻つきとして扱う
- 結果は件数で返す：取り込み／手動が優先のため表示は変わらない／曲 ID なし／重複／文字コード／空・大きすぎ
- 取り込んだあと、表示中の曲が対象なら歌詞を読み直す

## 4. LRC の読み方（`lyrics/lrc.rs`、ファイルも DB も触らない関数）

### 4.1 時刻タグ

- `[m:ss]`・`[mm:ss]`・`[mm:ss.f]`・`[mm:ss.ff]`・`[mm:ss.fff]`。分は1桁以上（60以上も可）、秒は 00〜59
- 小数は右を0で埋めて読む（`.2`→200ms、`.02`→20ms、`.250`→250ms）
- 1行に時刻が複数あれば、同じ文の行をそれぞれの時刻で作る
- 秒が60以上・小数が4桁以上などは、その時刻を使わず警告。原文は残す
- 時刻の昇順に並べ替える（同じ時刻は元の順を保つ）。並べ替えが起きたら警告
- 有効な時刻が1つも無ければ時刻なし（全文）として扱う

### 4.2 情報行

- `[ti:]` `[ar:]` `[al:]` `[by:]` `[au:]` `[re:]` `[ve:]` `[length:]` `[id:]` `[la:]` `[offset:]` は表示しない。キーの大文字小文字は区別しない
- そのほかの `[英字:値]` の行も情報行として表示しない
- `[offset:]` は最初の有効な値を使う。**正の値は歌詞を早める。**表示に使う時刻は `max(0, 元の時刻 - offset + 曲ごとの補正)`。0 未満になったら 0 にして警告

### 4.3 そのほか

- 時刻つきで本文が空の行（`[00:30.00]` だけ）は「今の行を消す」合図。行としては表示しない
- 時刻つきの中に混ざった時刻なしの本文行は捨てない。末尾に「時刻なしの行」としてまとめて出す（同期・クリックの対象外）。警告を付ける
- 時刻なし（全文）では空行をそのまま残す
- 行の中の `<mm:ss.xx>`（語ごとの時刻）は表示から外す。原文には残す

### 4.4 単体テスト（歌詞はダミーの文を使う）

| 入力 | 期待 |
|---|---|
| `[00:12.00][01:30.00]同じ場所へ戻る` | 12000ms と 90000ms の2行。警告なし |
| `[offset:+200]` ＋ `[00:10.00]遠くで音がする` | 9800ms |
| `[01:02]一` `[01:02.2]二` `[01:02.02]三` `[01:02.250]四` | 62000・62200・62020・62250。並びは 一→三→二→四 |
| `[ti:…]` `[ar:…]` `[al:…]` `[by:…]` ＋ `[00:01.00]夜が明ける` | 表示は1行。情報は保持 |
| `[00:10.00]後` `[00:05.00]先` | 先→後。並べ替えの警告 |
| `[00:01.00]一行目`・空行・`[00:02.00]`・`[00:03.00]三行目` | 1秒「一行目」、2秒「消す」、3秒「三行目」 |
| `[00:07.25]<00:07.25>小さな <00:07.70>光が <00:08.10>揺れる` | 7250ms、表示は「小さな 光が 揺れる」、原文はそのまま |
| CRLF 版と CR 版 | 同じ結果 |
| UTF-8 BOM つき | BOM を外して正しく読む |
| `[00:61.00]秒が範囲外`・`[00:10.1234]小数が長い` | どちらも時刻として使わない。警告。ほかに時刻が無ければ全文扱い |
| `[123:45.678]長い曲` | 7425678ms |
| `[offset:+500]` ＋ `[00:00.20]先頭` | 0ms にそろえて警告 |
| `[1:02.5]一桁の分` | 62500ms |
| 時刻の無い文と空行が続く全文 | 全文。空行を保つ |

## 5. 再生位置との同期（画面側）

- 新しい通知は足さない。既存の `pl://playback`（曲・状態・位置をまとめた写し）と `pl://position`（250ms ごと）を使う。`src/stores/playback.ts` の `playback` と `position` から読む
- 画面側で `requestAnimationFrame` と `performance.now()` を使って位置を補う。再生中は「最後に届いた位置 ＋ 経過時間」、止まっていれば最後の位置のまま。曲の長さで頭打ちにする
- 補った位置は画面にだけ使う。毎フレーム store に書かない。今の行が変わったときだけ表示を更新する
- 今の行は「表示時刻が今の位置以下の、最後の行」。同じ時刻の行はまとめて強調する。「消す」合図の後は強調なし
- 曲が変わったら古い歌詞をすぐ消して読み直す。読み込みの世代番号で、前の曲の遅い返事を捨てる
- 行をクリック（Enter も）すると、その行の表示時刻へシークする。既存のシークの呼び出しを使う

自動追従：

- 最初は追従する。今の行が変わったときだけ、その行を中央付近へスクロールする
- ホイール・タッチ・PageUp/PageDown/Home/End・スクロールバーで動かしたら追従を止め、上に「追従を止めています ／ 追従再開」を出す
- 最後に手で動かしてから 8 秒で戻る。「追従再開」ですぐ戻る。行クリックのシークは手の操作に数えない
- 動きを減らす設定（`prefers-reduced-motion`）では、スクロールをなめらかにしない

## 6. 画面

### 6.1 開き方・閉じ方

- 中央の画面に `LyricsView` を足す（曲一覧などと同じ扱い）。サイドバーには項目を足さない
- 開く：再生バーの「歌詞」ボタン、またはショートカット `Ctrl+L`（既存のショートカット設定に「歌詞を開く／閉じる」として足し、変更できるようにする）
- 閉じる：歌詞画面の戻るボタン、`Escape`、もう一度 `Ctrl+L`。開く前の画面へ戻る
- 文字入力中（検索欄・編集画面）はショートカットを発火させない（既存の決まりどおり）

### 6.2 並び

1280px（広いとき）：

- 左の列（約 220〜250px）：ジャケット、曲名、アーティスト、出どころの印（手動／外部／曲のタグ）、形式の印（時刻つき／時刻なし）、曲ごとの補正（`−100ms`・`リセット`・`+100ms`、今の値、「＋は歌詞を遅らせます」）
- 右：歌詞のカード。時刻つきは各行の左に小さく時刻を出し、今の行を強調。時刻なしは全文
- 上：見出し「歌詞」、状態の印（同期あり／同期なし）、「歌詞を編集」ボタン、追従の状態

600px（狭いとき）：

- 1列。曲情報は 36px のジャケットと曲名・アーティストを横1行に
- 補正は見出しの下に小さく1行（`−100ms`・値・`+100ms`）
- 歌詞の文字は 14px を下回らない

再生バー：

- 時刻つきのとき、アーティスト名の下に今の行を1行（はみ出しは省略記号）。クリックで歌詞画面を開く
- 今の行の右に、次の行を薄く出す（v3.0.1。作者の要望「次の歌詞が見えるのが遅い」）
  - 次の行：時刻の順で、今の行（同じ時刻のまとまりならその最後）より後ろにある、最初の表示する行。「消す」合図と空の行は飛ばす。次の行が同じ時刻のまとまりなら、今の行と同じく「 ／ 」でつないで出す
  - 表示時刻は今の行と同じ式（曲ごとの補正を足したあと。`src/stores/lyricsTime.ts` の `findNext`）
  - 最後の行のときは出さない。最初の行より前と「消す」合図の後（今の行が無いあいだ）は、次の行だけを出す
  - 見た目：色は `--c-secondary`、大きさは今の行と同じ `--fs-small`。区切りは「›」と左右 8px の間。新しい色の値は使わない
  - 今の行と次の行で1つの行。はみ出しは右から省略記号で切るので、次の行から隠れる。719px 以下（再生バーが詰まる幅）では、今の行があるとき次の行を出さない
  - 時刻なし・歌詞なしのときは変わらない。歌詞画面も変わらない
- 時刻なしのときは「時刻同期なし」を小さく。歌詞なしのときは何も出さない
- 「歌詞」ボタンを右端に。600px で既存の部品とぶつからないこと
- v3.0.2：流れる歌詞の列（6.5）がオンの間は、この1行を出さない。「歌詞」ボタンのすぐ左に列のオン・オフのボタンを足した。括弧の中は一段薄く出す（6.5）

### 6.3 状態ごとの見た目

| 状態 | 表示 |
|---|---|
| 歌詞なし | 「この曲の歌詞はありません」。ボタン「歌詞を貼り付ける」「外部歌詞を取り込む」 |
| 時刻なし | 全文。強調・追従・クリックなし |
| 時刻つき | 今の行を太字＋左のアクセント線＋選択色の背景。前後は薄い色 |
| 読み込み失敗 | 「歌詞を読み込めませんでした」と理由。ボタン「再試行」「原文を編集」。再生は止めない |
| 一部の時刻が読めない | 読めた分を表示し、上に「一部の時刻を読み取れませんでした。原文はそのまま残しています」 |

### 6.4 見た目の決まり

- 色・文字・角丸・影・動きは既存の変数を使う：`--c-primary`（本文）・`--c-secondary`（補足・時刻）・`--c-accent`（線・印）・`--c-selected`（今の行の背景）・`--c-border`・`--c-danger`・`--fs-*`・`--radius*`・`--dur-*`・`--ease`。新しい色の値を足さない
- パネルは `rgba(var(--c-panel-rgb), …)`。歌詞カードだけ不透明度を約 0.92 に上げ、背景画像が明るくても暗くても読めるようにする
- 今の行は色だけでなく太さ・線・`aria-current` でも示す
- 行はボタン相当でフォーカスできる。フォーカスの枠を消さない
- Dark・Light の両方で確かめる

### 6.5 流れる歌詞の列（v3.0.2）

デザインの元は、外部の AI に出してもらった見本（非公開）。下の「見本から変えたこと」は作者の指示。

置き場所と大きさ：

- 再生バー（80px。v3.6.0 までは 84px。719px 以下は 76px）の**下**に、高さ 48px（`--lyrics-row-h`）の列を足す。再生バーの高さと中身の並びは変えない
- 列を出している間は、再生バーの行を 48px 伸ばし（`.app.lyrics-row-on`）、中央の画面とサイドバーの下端をちょうど 48px 上げる。再生バーと列の間にすき間は作らず、再生バーの下の角を四角にして列とつなぐ。境目は列の上の `--c-border` の 1px
- 通知（右下）は列の上に出す

並べるもの（`src\stores\lyricsTime.ts` の `buildRowUnits`・`buildRow`。画面に依存しない関数。テストは `scripts\lyrics-time.test.mts`）：

| 状態 | 列 |
|---|---|
| 時刻つき・今の行がある | 歌い終わった行（3つまで）・今の行・次の行・その先（10個まで）。最後の行では次を出さない |
| 曲の冒頭（最初の行より前。先頭が「消す」合図でも、まだ何も歌っていないとき） | 「まもなく歌詞が始まります」＋最初の行から |
| 間奏（今の行が無く次の行がある。「消す」合図の後・空白だけの行） | 「♪ 間奏」＋次の行から |
| 最後の「消す」合図の後（今の行も次の行も無い） | 歌い終わった行＋「♪ 後奏」（見本に無い。次を出さない、の延長） |
| 時刻なし | 「時刻同期なし」＋「全文歌詞は Ctrl+L で表示できます」（キーは設定の値。未設定なら「歌詞」ボタン） |
| 歌詞なし | 「この曲には歌詞がありません」 |
| 時刻つきだが、表示する行が無い（「消す」合図と空白だけ） | 「表示できる歌詞の行がありません」 |
| 読み込み失敗 | 「歌詞を読み込めませんでした」 |
| 読み込み中・曲が無い | 何も並べない（「歌詞がありません」と区別する） |

- 並べる単位は「同じ表示時刻の、表示する行のまとまり」。再生バーの `rangeText` と同じく「 ／ 」でつないで1つにする。「消す」合図と空白だけの行は単位にしない
- 表示時刻は今の行と同じ式（`shownTime`：補正を足してから 0 にそろえる）。今の行・次の行は既存の `findActive`・`findNext` で決め、その単位を引く
- 1つの単位の文は 300 字で切って「…」（表示は省略記号で切れるので、極端に長い行で描くのが重くならないよう先に切る）。切る位置は文字を壊さないところまで戻す：絵文字などのサロゲートペアの途中、結合文字・異体字セレクタ・ゼロ幅接合子・肌の色の修飾の手前では切らない（`safeCut`。直し1回目）
- 単位の一覧は歌詞か補正が変わったときだけ作る（行数に比例）。並びは今の行・次の行が変わったときだけ作り直す（`activeLine`・`nextLine` が変わったときだけ。毎フレームは何もしない）。並べる要素は多くて 15 個で、何万行でも変わらない

動き：

- 行が変わったときだけ、列全体を `--dur-panel`（200ms）・`--ease` で左へ送る。今の行（か状態の印）の左端を `--lyrics-row-anchor`（22px。719px 以下は 14px）にそろえる
- 並べる範囲がずれて左の要素が消えても跳ばないよう、前の並びと今の並びに共通する要素を画面上で動かない位置に置き直してから送る（`src\layout\LyricsRow.tsx` の `align`）。曲が変わったとき（共通の要素が無い）と幅が変わったときは、動かさずに置く
- 文字の色・薄さの変化は `--dur-hover`。文字の大きさ・太さは動かさずに切り替える（見本は要素を毎回作り直すので、実際には大きさは動いていない。大きさを動かすと、送り先の位置が動いている途中の大きさで測られてずれる）
- 動きを減らす設定（`prefers-reduced-motion`）では、列の移動・文字の変化・列の出し入れを即時にする

見た目（新しい色の値は足さない）：

| もの | 見た目 | 最大幅（広いとき／719px 以下） |
|---|---|---|
| 今の行 | `--fs-title`・700・`--c-primary`・左に `--c-accent` の縦線（2px×16px） | `min(72vw, 900px)`／`100vw − 96px` |
| 次の行・時刻なしの案内 | `--fs-body`・600・`--c-secondary`・やや薄く（0.88） | `min(38vw, 440px)`／`35vw` |
| その先 | `--fs-small`・`--c-secondary`・薄く（0.58） | `min(34vw, 380px)`／`30vw` |
| 歌い終わった行 | `--fs-small`・もっと薄く（0.24） | 同上 |
| 状態の印 | `--fs-body`・600・`--c-secondary`・左に `--c-accent` の点 | `min(54vw, 640px)`／`48vw` |

- 区切りは「›」（`--c-secondary`・薄く）。曲の最後の単位と、最後に置く印には付けない
- 長い行は省略記号で切る。今の行だけ見本より広くした（下の「括弧」の部分まで見えるようにするため。作者の指示）。今の行は列の左端にあるので、狭い幅でも次の行より先に幅を取る
- 列の背景はパネル色の不透明度 0.97、左右の端（18px・22px）はパネル色へぼかす

括弧の中（掛け合い・合いの手。v3.0.2、作者の指示）：

- 取り込み済みの時刻つき歌詞では、2人が同時に別の歌詞を歌う部分のほとんどが、1行の中の括弧で書かれている（作者のライブラリでは、時刻つき歌詞の約3分の1の曲に丸括弧があった）
- 括弧（半角 `( )`・全角 `（ ）`）とその中身を、同じ行の本体より一段薄く・一段小さく出す（`.lyric-sub`）。分け方は `splitParens`・`rangeParts`（画面に依存しない関数）
  - 一段は列の文字の段（`--fs-title` → `--fs-body` → `--fs-small`）と色の段（`--c-primary` → `--c-secondary`）。今の行の括弧は `--fs-body`・600・`--c-secondary`、次の行の括弧は `--fs-small`・薄さ 0.72 倍。いちばん下の段（その先・歌い終わった行、再生バーの1行）は大きさを変えず、色か薄さだけ下げる（`--fs-small` より小さい変数が無いため）
- 決まり（テストあり）：
  - 半角と全角は区別せず、開きと閉じの数で数える（`(…）` も閉じる）。入れ子は一番外が閉じるまで中。1行に複数あってもそれぞれ分ける
  - **閉じていない括弧は行末までを中とする。**掛け合いが行をまたいで書かれる（前の行で開き、次の行で閉じる）ため。何もしないと、続きの声が本体と同じ見た目になる
  - 同じ理由で、**開きの無い閉じ括弧は、行頭（か前の括弧の閉じ）からその閉じ括弧までを中とする**
  - ただし、開きの無い閉じ括弧の直前が `:` `;` `=` か数字（半角・全角）なら、括弧として扱わず本体のまま出す（顔文字「:)」・番号「1)」「１）」。直し1回目）。開いた括弧の中の閉じ括弧は、直前が何でも閉じる
  - 括弧は行ごとに数える。同じ時刻のまとまりで「 ／ 」でつないでも、閉じていない括弧が次の行へ漏れない
  - 括弧だけの行は、行全体が括弧の見た目になる。文字は1つも足し引きしない
- 再生バーの小さな1行（列がオフのとき）にも同じ分け方を当てる。今の行の括弧は `--c-accent` → `--c-secondary`、次の行の括弧は薄さだけ下げる。歌詞画面（LyricsView）は変えない

オン・オフ（見本から変えたこと。作者の指示）：

- ボタンは再生バーの既存の「歌詞」ボタン（`IconLyrics`）のすぐ左に1つだけ。列のオン・オフで位置は変わらない。押した状態（オン）は `aria-pressed` と既存の選択色（`.icon-btn.on` の `--c-accent`。シャッフルと同じ）で示す

## 10. 歌詞をネットから取る（v3.1.0）

作成：2026-11-12。取得の決まりは、先に作った非公開のスクリプト（検査を3回通したもの）から移した。定数・照合・再試行・応答の読み方は同じ値・同じ順序で Rust に移した（`src-tauri\src\lyrics\lrclib.rs`）。違えた点は 10.8。LRCLIB の API の事実は公式 https://lrclib.net/docs.md（作る間も検査でも、本物の lrclib.net へは通信していない）。

### 10.1 設定と入口

- 設定 `lyricsOnline`（Rust は `AppSettings::lyrics_online`）。**既定はオフ。**値の無い古い設定・v2 の書き出しはオフ。保存と書き出し（zip）に入る。**設定の zip を読み込んだときは、中の値にかかわらずオフ**（`settings::backup::import`。直し1回目：他人の zip で気づかないうちにオンにならないように）
- 設定画面に節「歌詞をネットから取る」を足した（ライブラリの節の次）。オン・オフと、送り先（lrclib.net）・送るもの（曲のタグの曲名・アーティスト名・アルバム名と長さ）・送らないもの（ファイルの場所・ファイル名・ほかの情報。タグに曲名が無い曲は送らない）を出す
- **オフのとき、通信の処理に一切たどり着かない。**歌詞を取る窓口（`lyrics_fetch_start`・`lyrics_fetch_track`）は、最初に `lyrics::online::begin` で設定を確かめ、オフなら `lyrics_online_disabled` で断る（通信のセッションも作らない）。画面のボタンを隠すだけにはしていない
- 走っている途中でオフにされたら、次の要求を送る前（`Client::get` の gate）と、受け取りの途中（WinHTTP の読み込みの合間）で止まる（`disabled`）
- 一括と1曲は同時に1つだけ（`lyrics_online_busy`）。要求の間隔は、操作をまたいでも空ける

### 10.2 通信の作り（`src-tauri\src\platform\windows\winhttp.rs`）

- Windows の WinHTTP（`windows` クレートに `Win32_Networking`・`Win32_Networking_WinHttp` の機能を足した。新しいクレートは無い）
- 宛先は `https://lrclib.net/api/get` と `https://lrclib.net/api/search` の2つだけ（`lrclib.rs` の `ALLOWED_URLS`）。照合は「クエリを除いた部分が完全一致、クエリは URL エンコード済みの文字だけ」。**URL を組むとき（`build_url`）と、送る直前（`WinHttpTransport::get` の頭の `path_and_query`）の2か所**で照合する
- HTTPS だけ（443・`WINHTTP_FLAG_SECURE`・TLS 1.2／1.3）。プロキシは使わない（`WINHTTP_ACCESS_TYPE_NO_PROXY`）。リダイレクトはたどらない（`WINHTTP_OPTION_REDIRECT_POLICY_NEVER` と `WINHTTP_DISABLE_REDIRECTS`。3xx は `http_301` などのエラー）。クッキー・自動の認証・資格情報の自動送信はしない
- 名札（User-Agent）は `PL-Player/<版> (https://github.com/rr2pp2/pl-player)`（v3.1.2 で `CONTACT_URL` に公開リポジトリの URL を入れた）。**個人を指すもの（メール・ユーザー名）は入れない**
- 見出しは `Accept: application/json` だけ足す。200 以外は本文を読まない（429・503 は `Retry-After` だけ読む。2KiB を超える見出しは読まない）
- 間隔・再試行・上限はスクリプトと同じ値：

| 項目 | 値 |
|---|---|
| 要求の間 | 300〜500ms（1つずつ順に） |
| 429 | `Retry-After`（秒か HTTP の日付）＋最大 30% のゆらぎ。無い・読めない（`²` など）ときは 5・10・20・40 秒。300 秒を超えたら待たずに全体を止める（`rate_limited_long_wait`）。5回続いたら全体を止める（`rate_limited_repeatedly`） |
| 503 | `Retry-After`（無ければ 1 秒）＋ゆらぎ。5回でその曲をエラー（`http_503`） |
| ほかの 5xx・通信エラー | 1・2・4・8 秒（＋ゆらぎ）。5回でその曲をエラー |
| タイムアウト | 名前解決・接続・送信・受信それぞれ 20 秒。1応答を読み切るまで 60 秒 |
| 応答の上限 | 16MiB（`Content-Length` が超えていれば読まない。読みながらでも超えたら止める） |
| 打ち切り | 曲のエラーが 5曲続いたら全体を止める（`too_many_errors`） |

- 別スレッドで動かす（一括は専用のスレッド、1曲は `spawn_blocking`）。再生と画面は止めない
- やめるボタン：待ち（50ms ごとに見る）・曲の間・送る直前・受け取りの合間で止まる。WinHTTP が送受信している1回の途中は止められないので、最長でタイムアウトの 20 秒かかることがある

### 10.3 送る曲（`src-tauri\src\lyrics\online.rs` の `run_batch`）

| 曲の状態 | 歌詞の無い曲だけ（既定） | 外部の歌詞を取り直す | 1曲（ネットから探す） |
|---|---|---|---|
| 手動の歌詞がある | 送らない | 送らない | 送らない（「手動の歌詞があるので探しませんでした」） |
| 外部の歌詞がある | 送らない | 送る | 送る |
| 歌詞が無い（手動・外部・タグのどれも無い） | 送る | 送る | 送る |
| 曲のタグに歌詞がある（外部・手動は無い） | 送らない | 送らない | 送る（ボタンは歌詞が無いときだけ出る） |
| 前に見つからない・instrumental・大きすぎ | 送らない（送った名前が変わっていれば送る） | 送る | 送る |
| 曲名かアーティスト名が空・512字超 | 送らない | 送らない | 送らない |
| 曲名がタグに無く、ファイル名から作った値（直し1回目） | 送らない | 送らない | 送らない |
| 一括の途中でライブラリから外された・手動の歌詞が付いた（直し1回目） | 送らない（件数「途中で…送らなかった」。エラーに数えない） | 同じ | ― |

- 曲のタグに歌詞がある曲を送らないのは、外部の歌詞を保存するとタグの歌詞より優先されてしまうため（スクリプトには無い決まり）
- 送るもの：曲名・アーティスト名（前後の空白を外す）・アルバム名（空でなく 512 字以下のとき）・長さ（ms を秒に四捨五入。1〜3600 のときだけ）。search は曲名とアーティスト名だけ
- 曲名がタグに無いとき（直し1回目、`online::title_is_file_name`）：取り込みは、タグに曲名が無い曲にファイル名（拡張子なし）を曲名として入れる。それを送るとファイル名が出ていくので、**曲名がファイル名と同じ曲は、曲のタグを読み直し、タグに曲名があるときだけ送る**。タグを読めないときは「無い」とみなして送らない。ファイル名と同じ曲名をタグに書いてある曲は、タグの値なので送る（一括・1曲とも。件数は「曲名（タグ）かアーティスト名が空で送らなかった」）
- 送る直前の確かめ直し（直し1回目）：一括は最初に送る曲の一覧を作るが、1曲ずつ送る直前に `store::fetch_candidate` で読み直す。ライブラリから外された曲・手動の歌詞が付いた曲は送らず、件数 `changedDuringRun` に数える（エラーにしない）。外部の歌詞の有無も読み直した値を使う

### 10.4 応答の読み方と保存

- get が 200：instrumental なら「歌詞なし」。時刻つきがあればそれ、無ければ全文。どちらも空なら search へ。404 なら search へ
- search：候補の先頭 50 件を見る。長さが ±2 秒以内で、曲名とアーティストの両方が一致か部分一致、instrumental でないもの。順位は時刻つき → 曲名が一致 → アーティストが一致 → 長さの差が小さい（同じなら先の候補）。候補が instrumental だけなら instrumental。手元の長さが 0 の曲は、名前が両方とも完全一致のものだけ。search が 404 なら見つからない
- 名前の照合：NFKC（Windows の `NormalizeString`）→ casefold → 文字と数字だけ残す（何も残らなければ空白を外したもの）。同じなら一致。部分一致は、短い方が3文字以上で、長い方に含まれ、長い方の半分以上の長さのときだけ
- 時刻つきが 1MiB を超えて全文が収まるなら全文。どちらも 1MiB を超えるなら「大きすぎ」
- 取れた歌詞は **external** として保存する。受け渡しフォルダの取り込みと同じ扱い（BOM を外し改行を LF、1MiB まで、中身に有効な時刻タグがあれば時刻つき、空・情報行だけは使わない）。**manual には書かない**
- 取り直しで、見つからない・instrumental・大きすぎ・エラーになったら、**今の外部の歌詞を消さずに残す**（件数は「今の歌詞を残した」）
- 見つからない・instrumental・大きすぎ は、移行 3 の表に覚える。取れたら消す。エラーは覚えない（次も聞く）

```sql
CREATE TABLE IF NOT EXISTS lyrics_fetch_misses (
    track_id   INTEGER PRIMARY KEY REFERENCES tracks(id) ON DELETE CASCADE,
    result     TEXT NOT NULL CHECK (result IN ('not_found', 'instrumental', 'too_large')),
    query_sig  TEXT NOT NULL,   -- 送った曲名・アーティスト名・アルバム名・長さの印（FNV-1a 64bit）
    checked_at TEXT NOT NULL
);
```

- 極端な応答で落ちない：16MiB 超・壊れた JSON・UTF-8 でない・形が違う → その曲のエラー（`response_too_large`・`bad_response`）。get の `duration` が数として読めない（巨大な整数・`1e999`・文字列など）→ `bad_response`。歌詞に単独サロゲート（`\ud800`）→ `bad_lyrics_text`（search ではその候補だけ外す）。深い入れ子の欄は、使わない欄なら読まずに飛ばす

### 10.5 窓口と通知

| 窓口 | 中身 |
|---|---|
| `lyrics_fetch_start(mode)` | 一括を別スレッドで始める。`mode` は `missing`（歌詞の無い曲だけ）か `refetch`（外部の歌詞を取り直す） |
| `lyrics_fetch_cancel()` | やめる |
| `lyrics_fetch_status()` | 今の進み具合（設定画面を開き直したとき） |
| `lyrics_fetch_track(track_id)` | 1曲だけ取る。結果は `synced`・`plain`・`instrumental`・`not_found`・`too_large`・`kept`・`no_metadata`・`manual`・`error`・`stopped` |

- 通知 `pl://lyrics-fetch-progress`（1曲ごと）と `pl://lyrics-fetch-done`（終わり。外部の歌詞が変わった曲 ID の一覧つき。表示中の曲なら画面が読み直す）
- 進み具合と結果は**件数・曲 ID・状態の記号だけ**。歌詞の本文と LRCLIB が返した曲名などは、画面にもログにも出さない。ログは一括の終わりに件数を1行、エラーの曲は「曲 ID と記号」、名前が部分一致の候補から選んだ曲は曲 ID だけ
- エラーの種類を2つ足した：`lyrics_online_disabled`（オフなので通信しなかった）・`lyrics_online_busy`（走っている途中）
- 打ち切りの文（直し1回目）：進み具合に `lastError`（最後にエラーになった曲の記号）を持つ。`too_many_errors` の文は、それで原因を分ける（`timeout`・`network_error` →「ネットにつながっているか」／`tls_error` →「PC の日付と時刻」／`http_5xx` →「混み合っているか止まっている」／ほかの `http_4xx` など →「要求を受け付けなかった」／`bad_response` など →「応答を読めなかった」／`write_failed` →「データベースに保存できなかった」。`src\messages\ja.ts` の `lyricsFetchAbortMessage`）
- 一括のスレッドが途中で落ちても（panic）、`online::DoneGuard` の drop が処理中の印を外し、進み具合を `running:false`・`aborted:internal_error` にして `pl://lyrics-fetch-done` を出す（直し1回目。設定画面のボタンが押せないまま残らない）
- 送る曲を選ぶ間（直し2回目）：進み具合に `preparing`・`prepareTotal`・`prepareDone` を足し、画面は「準備中 ◯曲中◯曲」と出す（`total` が 0 のままにしない。250ms ごと）。選ぶ間も、64曲ごとと、曲ファイルを読む直前に、やめるボタン・設定のオフを見る
- 選ぶ順（直し2回目）：外部の歌詞の有無 → 曲名・アーティスト名 → 覚えた結果（聞き直さない曲はここで外す）→ 最後に、曲名がファイル名と同じ曲だけ曲のタグを読む。**覚えた結果で聞き直さない曲のタグは読まない**
- 曲のタグを読む処理が panic しても止まらない（直し2回目）：`tags_read` の `open_tagged`・`read_values`・`read_lyrics` を `catch_unwind` で包み、panic は Err にする（チャンネル数 0 の Opus などで lofty が panic する。`docs\ペネトレーションテスト_v3.0.2.md` の3の読み取り側）。`online` でもタグを読む関数の呼び出しを包む。曲名を確かめる読み取りが panic した曲は「タグに曲名が無い」＝送らない（`no_metadata`）。歌詞のタグを確かめる読み取りが panic した曲は「タグに歌詞は無い」として扱う（歌詞画面も同じく歌詞なしと出す）

### 10.6 画面

- 設定 →「歌詞をネットから取る」：オン・オフ（説明つき）／取ってくる曲（「歌詞の無い曲だけ」「外部の歌詞を取り直す」）／「歌詞を取ってくる」ボタン（オフのときは押せない）／走っている間は「やめる」と進み具合（「◯曲中 ◯曲・取れた ◯・見つからない ◯」と細い進み具合の線）。終わったら件数を知らせる（右下）
- 歌詞画面の「この曲の歌詞はありません」：オンのときだけ「ネットから探す」を出す（探している間は「探しています…」）。見つかったら歌詞を読み直す
- 設定の読み込みの確認文と、バックアップの説明に「歌詞をネットから取る」のオン・オフが入ることを書いた

### 10.8 スクリプトとの違い（決めたことと理由）

| 違い | 理由 |
|---|---|
| 名札は `PL-Player/3.1.0`（スクリプトは `PL-Player-lyrics-batch/1.0`） | アプリ名と版だけにする要件。v3.1.2 で公開リポジトリの URL を足した（`PL-Player/3.1.2 (https://github.com/rr2pp2/pl-player)`。LRCLIB の求め） |
| 曲のタグに歌詞がある曲・手動の歌詞がある曲は送らない | 外部の歌詞はタグより優先されるため／手動は絶対に上書きしない要件 |
| 時刻つき・全文が情報行だけ（取り込みで「空」になる）なら、無いものとして扱う（全文 → search へ進む） | スクリプトは書き出してからアプリの取り込みで弾かれていた。アプリでは同じ読み方で先に判断できる |
| search の1件の中に読めない値（巨大な数など）があれば、その1件だけ外す | スクリプトは値ごとに判断する。違いが出るのは「手元の長さが 0 で、名前が完全一致で、長さだけ読めない候補」だけ |
| JSON として正しくない書き方（`NaN`・`Infinity`）は応答ごと `bad_response` | Python は読めるが、標準の JSON ではない |
| get で、使わない欄の深い入れ子は読まずに飛ばす（スクリプトは `bad_response`） | 落ちないことは同じ。使う欄だけを読む作りのため |
| 名前の「文字」は Rust の `is_alphanumeric`（Unicode の Alphabetic と数字）。casefold は `to_lowercase` に ß・ẞ・ς の折り返しを足したもの。NFKC は Windows の `NormalizeString` | 依存を足さないため。違いが出るのはインド系文字の母音記号など（Alphabetic に含まれる結合記号が残る）と、ß などのほかの特殊な折り返し。日本語・英語の名前では同じ結果（テストで全角・半角カナ・ß を確かめた） |
| HTTP の日付は、IMF-fixdate・RFC 850・asctime・数字の時差と主な時差名だけ読む | Retry-After に使われる形。読めなければ「見出しが無い」と同じ待ち方（スクリプトと同じ） |
| 曲のエラーで、取れていた歌詞がある曲も「エラー」に数える（スクリプトは「残した」に数えた） | 歌詞を消さないのは同じ。件数の分け方だけ |
| 大きすぎ（1MiB 超）も覚えて「歌詞の無い曲だけ」で聞き直さない | スクリプトも何も付けないときは聞き直さない（同じ）。要件の「見つからない・instrumental」に足した |
| 覚えた結果に送った名前の印を持つ。名前を直した曲は聞き直す | スクリプトの overrides と qsig の代わり（アプリには overrides が無く、曲の情報の編集で直すため） |
| パスで曲を突き合わせない（曲 ID で直接保存する） | 受け渡しフォルダを通らないため。v2 → v3 の移し替えの仕組みは要らない |
