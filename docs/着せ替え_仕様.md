## 1. できること・しないこと

**使うスキンは1つ。**スキンは4つの部品を、どれでも好きなだけ持てる。持っていない部品は今の見た目のまま。

| 部品 | 中身 |
|---|---|
| 色と文字 | 決めた CSS 変数だけ（4章）。Dark と Light を別に持てる。レイアウトの寸法は変えない |
| ボタンのアイコン | 34 個（5章。v3.6.0 で `IconRanking` を足した）。状態のあるものは状態ごと |
| アプリのアイコン | 起動中のウィンドウ・タスクバー・タスクトレイ（7章）。exe・ショートカット・スタートメニューは変わらない |
| 立ち絵 | 再生中・停止中の2つ（6章）。置き方は「右側に専用の幅を取る」だけ |

**3.2.0 では作らないもの**（`extensions` に予約だけ置く。書いてあれば読まずに警告）：自作 CSS・フォントのファイル・背景画像・音・SVG・スキンの重ね掛け・再生中のトレイのアイコンの切り替え・立ち絵の「右下に重ねる」置き方。

**既定のスキン `builtin:default`** は今の見た目そのもの。消せない・書き出せない。既定のスキンのときは、画面に何も足さず、CSS 変数も1つも当てない（3.1.2 と同じ画面。設定に「着せ替え」の欄が増えるだけ）。

## 2. スキンの形

1スキン＝1フォルダ。zip で配る。**zip のいちばん上に `skin.json` を置く。**フォルダごと zip にした形（エクスプローラーの「送る → 圧縮（zip 形式）フォルダー」でフォルダを圧縮したもの）も受ける：OS が足すファイル（下の表）を除いた項目が全部ただ1つのフォルダ `X\` の下にあり、`X\skin.json` があり、いちばん上に `skin.json` が無いときだけ、`X\` を外して読む。外したあとの名前は、下の決まりで今までどおり確かめる。`X` の名前は使わずに捨てるので、日本語でもよい（Shift_JIS でも UTF-8 でも）。確認画面に「フォルダ1つを外して読みました」と出す。外すフォルダの項目 `X/` そのものも、中身があれば・リンクなら断る（外さないときのフォルダの項目と同じ決まり）。フォルダが2つ以上・フォルダの中に `skin.json` が無い・フォルダが2段（`X\Y\skin.json`）の形は今までどおり断る。`X/skin.json` があるのにフォルダの外にも項目がある形は、「全部が1つのフォルダの下にない」（`skin.json is in X/, but … is outside it`。`X` が ASCII でないときは名前を出さない）と知らせて断る（危ない名前・リンク・実行ファイルなどが混ざっていれば、先にそちらで断る）。

```
<名前>.zip
├─ skin.json              必須
├─ preview.png            任意（一覧と確認画面の見本。.png・.webp・.gif）
├─ icons\                 ボタンのアイコン
├─ app\                   アプリ・トレイのアイコン
└─ character\             立ち絵
```

入れてよいのは、`skin.json`・`preview.<画像>`・`icons\`・`app\`・`character\` の中の画像（PNG・APNG・WebP・GIF）だけ。**skin.json が使っていない画像も断る**（知らないファイルを置かせない）。

パスの決まり：英数字と `.` `_` `-` だけ（先頭は英数字）・1段 64 文字まで・3段まで（`icons/IconStar/filled.png`）・区切りは `/`・Windows の予約名（`con` など）は不可。

**zip の中の名前の `\` は `/` に読み替えてから確かめる。**Windows 標準の PowerShell 5.1 の `Compress-Archive` と .NET Framework の `ZipFile.CreateFromDirectory` は、区切りを `\` で書く（zip の決まりは `/`。PowerShell 7 は `/`）。読み替えたあとの名前を、上の決まり・OS が足すファイル・フォルダごとの形・重複の全部に今までどおり通すので、`icons\..\..\x` は親フォルダへ出る名前、`\\server\x` は UNC、`C:\x` はドライブとして断る。`icons\a.png` と `icons/a.png` は同じ名前の重複になる。

読み替えるのは、名前が ASCII だけのときと、UTF-8 の印があるときだけ（UTF-8 では 0x5C は必ず `\`）。印の無い ASCII 以外の名前は Shift_JIS などのことがあり、0x5C が2バイトの文字の後ろ半分（「ソ」＝ 0x83 0x5C）のことがあるので読み替えない（`\` が残れば断る）。PowerShell 5.1 は ASCII 以外の名前に UTF-8 の印を付けるので、日本語のフォルダごとでも読み替わる（2026-11-13 に実物で確かめた）。skin.json の中に書くパスは読み替えない（`/` で書く）。

**ASCII だけにしている理由**：zip の名前の文字コードは、UTF-8 の印があるときだけ決まる（エクスプローラーは印を付けずに Shift_JIS で書くことがある）。読み違えると、同じ名前の重複・大文字小文字の重複・skin.json が指す名前との突き合わせがずれる。ASCII ならどの道具で作っても同じバイト列になる。

**OS が足すファイルは、断らずに飛ばす：**

| 名前 | 足すもの |
|---|---|
| `__MACOSX\` の下の全部 | macOS の「圧縮」（項目ごとに `._名前` の写しを足す） |
| `.DS_Store`（どの段でも） | macOS の Finder |
| `Thumbs.db`・`desktop.ini`（どの段でも。大文字小文字は区別しない） | Windows のエクスプローラー |

飛ばしたものは**戻さない・書かない・名前を画面に出さない**（確認画面には種類と数だけ。名前に向きを変える文字などを入れて画面を偽れないように）。項目の数（80）にも数えない。断らない理由：作る人が置いたものではなく、断ると「macOS で作った zip は全部取り込めない」になる一方、戻さないので中身がアプリに届く道が無い。似た名前（`Thumbs.db.png`・`a/__MACOSX/x` など）は飛ばさず、今までどおり確かめて断る。

取り込んだあとのフォルダはデータの場所の `skins\<id>\`。アプリはその中に `derived\` を作る（動く画像の最初の1コマと、確かめた結果の `info.json`）。`derived\` は zip から受け付けない・書き出しにも入れない。

## 3. skin.json（schemaVersion 1）

**知らない項目は警告して使わない。知っている項目の型・値が違えば断る。同じキーが2つある JSON・入れ子が 16 段を超える JSON は断る。**UTF-8（先頭の BOM は可）。

**確認画面の警告に出す、スキンの中から来た文字列**（知らない項目・変数・`extensions` のキー名、`minAppVersion`）は、そのまま出さない（`manifest.rs` の `shown`。警告はすべて `Ctx::warn` で作り、そこで通す）。下の「名前の見える文字」と U+0020 のほかは `[U+XXXX]` に置き換え（制御文字・見えない文字・1. の断る文字・私用領域・未割り当て・非文字・結合文字・U+0020 以外の空白）、置き換えたあとで 64 文字を超えれば切って `…` を付ける。キー名は名前の4欄と違って断らないので、ここで見え方を揃える（壊す担当の検査5回目：U+202E とタグ文字を入れたキー名・20 万文字のキー名・U+0007 や U+2028 を含むキー名が、そのまま確認画面に出ていた）。

**断るときの知らせ（エラーの `detail`）も同じ決まりで出す**（壊す担当の検査5回目のあとの直し）。`format`・`id`・`placement.mode` の値、アイコンの名前と状態・変数のキー名（項目の道筋に入る）、重複したキー、画像のパス、zip の中の名前（パスの検査で断る名前・リンク・フォルダの名前・暗号化の印など）は、断る文に入るので、そのまま出すと画面の通知に U+202E や 20 万文字が出る。

- 作る箇所ごとに通す：キー名・値・id は `from_skin`（64 文字まで）、zip の中の名前と画像のパスは `names::shown_name`・`shown_bytes`（正しい名前のいちばん長いもの 195 文字が切れない長さまで）。着せ替えのエラーは全部 `skin_error` で作り、`detail` 全体も `shown` に通す（512 文字まで）
- 入口の網：取り込み（`inspect_zip` の zip のファイルを読むところと `inspect_bytes`）と読み込み（`load`）は、OS や下位の部品（zip の読み方・画像の復号・JSON）の文、選んだ zip のファイルのパスを含めて、返す前に `guard` で `detail` を `shown` に通す。`shown` は何度通しても結果が変わらない
- zip の読み方（`settings::zip`）の文は名前ごと作られるので、名前だけを 195 文字で切れない（全体の 512 文字で切る）。この部品は設定の取り込みと共有で、設定の側の文は変えていない

**確認画面の警告の数**：種類（code）ごとに3件まで出し、超えた分は種類ごとに「ほか N 件」の1行にまとめる（`manifest.rs` の `WARNINGS_PER_CODE`。画面の並べ方は `src\skins\warnings.ts`）。全体で 20 件のような上限にしなかったのは、知らない項目を skin.json の頭に並べると、上限の中を `unknown_field` で埋めて、あとから出る `min_app_version_newer`・`extensions_ignored` を押し出せるため（知らない項目は `minAppVersion` より先に見る）。種類は7つで、うち4つは1件しか出ないので、行は多くても 3×3＋4＋「ほか」3行＝16 行。上限を超えた分は `detail` も作らない。

| 項目 | 型 | 必須 | 決まり |
|---|---|---|---|
| `format` | 文字 | 必須 | `"pl-player-skin"` |
| `schemaVersion` | 整数 | 必須 | `1` だけ。ほかの数は「この版で読めない形式」 |
| `id` | 文字 | 必須 | 英小文字・数字・`-`、1〜48 文字、先頭は英小文字か数字。フォルダの名前になる |
| `name` | 文字 | 必須 | 1〜48 文字。制御文字（Cc）は不可。見えない文字は下の「見えない文字の決まり」に従う（`author`・`description`・`version` も同じ）。見える文字が1つも無い名前は断る |
| `version` | 文字 | 必須 | 作者が付ける版。1〜32 文字（英数字と `. - +`） |
| `author` | 文字 | 任意 | 80 文字まで |
| `description` | 文字 | 任意 | 300 文字まで（改行は可）。画面では文字として出すだけ |
| `minAppVersion` | 文字 | 任意 | `3.2.0` の形。今のアプリより新しければ警告（取り込みはできる） |
| `preview` | パス | 任意 | 見本の画像 |
| `parts.appearance` | オブジェクト | 任意 | 4章 |
| `parts.icons` | オブジェクト | 任意 | 5章 |
| `parts.character` | オブジェクト | 任意 | 6章 |
| `parts.application` | オブジェクト | 任意 | 7章 |
| `extensions` | オブジェクト | 任意 | あとの版の予約。中に何かあれば警告して読まない |

`$schema` は書いてもよい（読まない）。

**見えない文字の決まり**（`src-tauri\src\skins\manifest.rs` の `is_format_char`・`check_invisible`）。`name`・`author`・`description`・`version` の4つに当てる。目的は2つ：**名前の見え方を偽れないようにする**（名前は確認の画面と一覧に出る）ことと、**見えない文字で運べる量を抑える**（作者が AI に skin.json を読ませると、見えない指示文が混ざる）こと。

**見えない文を作れなくする決まりではない。**空白や見える文字の並びを使えば、欄ごとに数十〜百数十バイトは運べる。空白（U+0020・00A0・1680・2000〜200A・202F・205F・3000・2800 の 18 種）はどれも正当な文字なので、種類の違いを読み分ければ1文字で約4ビットになる（壊す担当の検査5回目で、作って復元できた）。運べる量の目安：

| 欄 | 長さの上限 | 見える文字1つに異体字セレクタ1つ（2. の置き場所） | 18 種の空白を混ぜる |
|---|---|---|---|
| `name` | 48 文字 | 約 24 バイト | 約 25 バイト |
| `author` | 80 文字 | 約 40 バイト | 約 40 バイト |
| `description` | 300 文字 | 約 150 バイト | 約 150 バイト |

空白の連続などに新しい決まりは足さない（正当な使い方と見分けられないため）。見える文字なら文としてそのまま書けるので、ここでは抑えない。

**断る文字を1つずつ足すのをやめ、見えない文字ごとに置いてよい場所を決めて、それ以外を断る。**塞いだ穴の脇から次の穴が出続けたため（下の経緯）。

ことばの意味：

- **見えない文字**：Unicode の Default_Ignorable_Code_Point 全部（4174 文字）と、エジプトの聖刻文字の書式 U+13430〜13440。前者の出典は Unicode 18.0.0 の DerivedCoreProperties.txt で、`DEFAULT_IGNORABLE` に1行ずつ写した（数はテストで確かめる）。後者は同じファイルが「見えるべき」として外している範囲だが、単独では何も描かないので見えない文字に入れる
- **見える文字**：見えない文字・空白（全角空白 U+3000 を含む）・制御文字・点字の空白 U+2800 のどれでもない文字。結合文字（アクセント）・肌の色の修飾・旗の U+1F3F4 は見える文字に数える。2. と 3. の置き場所と数はこれで数える
- **名前の見える文字**（4. で使う。`is_name_base`）：見える文字のうち、Unicode の Grapheme_Base に入っていて、U+FFFC（置き換えの印）・U+1D159（空の音符）でないもの。Grapheme_Base の出典は上と同じ DerivedCoreProperties.txt（18.0.0）で、定義は「全部 − 制御 Cc − 書式 Cf − サロゲート − 私用領域 Co − 未割り当て Cn − 行・段落の区切り − Grapheme_Extend」。つまり結合文字（Mn・Me と、Grapheme_Extend に入る一部の Mc・半角の濁点 U+FF9E・FF9F）・私用領域・未割り当て・非文字（U+FFFE・FFFF・FDD0〜FDEF など。Cn）は入らない。U+16FE4（契丹小字の埋め字）は Mn なので入らない。`grapheme_base.rs` に、出典の 1819 行を続く範囲でつないだ 910 個として写した（数はテストで確かめる）

**1. 先に断る文字**（置き場所にかかわらず、理由を名指しして断る）

| 断るもの | 文字 | 理由 |
|---|---|---|
| 見え方の順番を変えるもの | U+202A〜202E（埋め込み・上書き）、U+2066〜2069（分離） | U+202E を前に置いた `gpj.exe` が `exe.jpg` に見えるなど、並びを偽れる |
| 幅の無い見えない文字のうち、名前では偽装にしか使い道がないもの | U+200B、U+2060〜2064、U+FEFF、U+180E、U+206A〜206F（廃止）、U+FFF9〜FFFB（注釈の印）、U+E0001（廃止の言語タグ） | 見た目を変えずに別の名前を作れるだけ。U+FFF9〜FFFB は Default_Ignorable ではないので、ここで断る |
| 行・段落の区切り | U+2028、U+2029 | 1行の欄の見え方を崩す（Default_Ignorable ではない） |

**2. 見えない文字を置いてよい場所**（ここに無い置き方は断る）

| 見えない文字 | 置いてよい場所 | 理由 |
|---|---|---|
| 異体字セレクタ：U+FE00〜FE0F・U+E0100〜E01EF、モンゴル文字の FVS U+180B〜180D・U+180F | 見える文字の直後に1つだけ | 1つで前の文字の字形を選ぶ（❤️・葛󠄀・キーキャップ）。続けて置く使い方は無い。続けて置けると、256 通りで1個1バイトを運べる（検査4回目：`A` のあとに 40 個） |
| ZWJ：U+200D | 見える文字か異体字セレクタの直後で、見える文字の直前に1つだけ。先頭・末尾・連続は不可 | 家族・職業・🏳️‍🌈 などの絵文字のつながり。肌の色の修飾は見える文字なので、そのあとにも置ける |
| ZWNJ：U+200C | 見える文字と見える文字の間に1つだけ | ペルシア語などの綴り。ZWJ と ZWNJ を続けて 0/1 の列にする形を断る（検査4回目） |
| ソフトハイフン：U+00AD | 見える文字と見える文字の間に1つだけ | 長い語の折り返しの位置 |
| 向きの印：LRM U+200E・RLM U+200F・ALM U+061C | 3つのどれとも隣り合わない（1か所に1つ） | アラビア文字・ヘブライ文字と数字を並べるときに1つずつ要る。並びは変えない（まわりの文字の向きを決めるだけ） |
| タグ文字：U+E0020〜E007F | U+1F3F4 ＋ `gbeng`・`gbsct`・`gbwls` のどれかのタグ ＋ U+E007F の並びの中だけ | イングランド・スコットランド・ウェールズの旗。Unicode が推奨として挙げる旗（emoji-sequences.txt 18.0 の RGI_Emoji_Tag_Sequence）はこの3つだけ。旗の形だけで許すと、7文字の語を旗の数だけ運べた（検査4回目：`ignore`＋U+E007F、旗を5つ並べた文）。ほかの地方の旗（`ustx` など）も断る |
| ほかの見えない文字：CGJ U+034F、ハングルの埋め草 U+115F・U+1160・U+3164・U+FFA0、クメール文字 U+17B4・U+17B5、速記の書式 U+1BCA0〜1BCA3、楽譜の書式 U+1D173〜1D17A、聖刻文字の書式 U+13430〜13440、未割り当ての U+2065・U+FFF0〜FFF8・U+E0000〜E0FFF の残り | どこにも置けない | 名前・作者・説明に要る使い道が無い。字形が無いので、空に見える名前や見えない印に使える（検査3回目・4回目） |

**3. 数の上限**：1つの欄の中で、ZWJ・ZWNJ・ソフトハイフン・向きの印の合計は、見える文字の数まで。

- **数えないもの**：異体字セレクタ（2. で見える文字1つに1つまでと決まっている。数えると、🏳️‍⚧️ のように1つで見えない文字が見える文字より多い絵文字を断ってしまう）と、許した旗の中のタグ文字（3通りしか無い）
- **数え方の例**：👨‍👩‍👧‍👦 は見える文字 4・数える文字 3 なので通す。LRM＋`a`＋LRM は見える文字 1・数える文字 2 なので断る
- **運べる量の目安**：見える文字1つにつき、異体字セレクタ1つ（約1バイト）と間の印1つまで。名前（48 文字）でおよそ 24 バイト、作者（80 文字）でおよそ 40 バイト、説明（300 文字）でおよそ 150 バイト。見えない文字で、見える文字を増やさずに増やす方法は無い（空白の種類を使う運び方は、この節の頭の表）。異体字セレクタを数えても、長さの上限のほうが先に効くので、この量は変わらない

**4. 名前が空**：名前の見える文字が1つも無い名前は `name: blank` で断る（空白・U+3164・U+2800・見えない文字だけの名前と、結合アクセントだけ・U+16FE4・私用領域 U+E000・未割り当て U+0378・非文字 U+FFFF・U+FFFC・U+1D159 だけの名前）。置き場所より先に確かめる。普通の文字の後ろの結合文字（`Cafe`＋結合アクセント・濁点 U+3099・インド系やタイ文字の母音記号）は今までどおり通す。間隔を取る結合文字（Mc。U+0903 など）は字形に幅があるので数える。作者・説明は今までどおり空でもよく、結合アクセントだけでも通す。

**通す例**（テストと壊す担当の zip で確かめた）：3つの旗（前後に文字があっても、並べても）・家族の絵文字（ZWJ）・肌の色つきの絵文字・❤️・キーキャップ・IVS（葛󠄀）・`Cafe`＋結合アクセント・日本語・ハングル・ペルシア語の ZWNJ・アラビア文字・LRM を1つ・ソフトハイフンを1つ・アラビア文字の数の印（U+0600〜0605。Default_Ignorable ではなく、字形がある）。

経緯（2026-11-13、壊す担当の検査）：2回目で ZWNJ・ソフトハイフン・旗の絵文字・LRM が断られた（Cf を全部断っていた）ので、断る文字を絞った。3回目で旗の外のタグ文字と、U+3164・U+2800 だけの名前が通ったので、旗の形と空に見える名前の決まりを足した。4回目で、旗の形に語を入れる形・異体字セレクタや ZWJ を並べる形・CGJ などだけの名前が通った。断る文字を足す形では次の穴が残るので、許す置き場所を決める形に作り直した（このとき、ハングルの埋め草 U+3164 などを文字の間に置く形も断るようになった）。5回目で、決まりの外の運び方（空白の種類・異体字セレクタを1文字に1つ）が残ることが分かったので、目的の書き方を「作れない」から「偽装を防ぎ、量を抑える」に直した。あわせて、結合アクセントだけ・空に近い見え方の字だけの名前を断るようにし、警告に出すキー名を置き換えるようにした。

## 6. 立ち絵

```json
"character": {
  "states": { "playing": "character/playing.webp", "stopped": "character/stopped.png" },
  "placement": { "mode": "right-rail", "widthPx": 180, "maxHeightPx": 420, "minWindowWidthPx": 920 }
}
```

| 項目 | 決まり |
|---|---|
| `states.playing`・`states.stopped` | 両方必須。再生中は playing、一時停止・停止・曲なしは stopped |
| `placement.mode` | `right-rail` だけ。ほかの値は「この版では使えない置き方」として断る |
| `widthPx` | 96〜280（既定 180） |
| `maxHeightPx` | 160〜520（既定 420） |
| `minWindowWidthPx` | 760〜1200（既定 920）。ウィンドウがこれより狭いと隠す |
| `hideOnLyrics` | 書いてもよい。`false` は警告（歌詞画面では常に隠す） |

**置き方：**中央の画面（上の検索の段より下）の右側に、`widthPx × 大きさ + 12px` の幅を取る。曲一覧などはその左で終わる（重ならない）。絵は下にそろえ、縦横比を保って幅と高さに収める。再生バー・流れる歌詞の列は別の枠なので重ならない。

**隠すとき：**スキンに立ち絵が無い・使う人が「立ち絵を出す」を切った・歌詞画面・ウィンドウの幅が `max(760, minWindowWidthPx)` 未満。隠すときは幅も取らない（画面は既定のスキンと同じ作り）。

**クリック・ドラッグ＆ドロップは下へ通す**（`pointer-events: none`。読み上げにも出さない）。使う人が変えられるのは、出す・出さないと大きさ（75〜125%）だけ。v3.3.0 から、再生中と停止中の画像を2枚とも読み込んだまま重ね、見せる方だけを切り替える（3.2.0 は表示する状態の画像だけを読み、状態が変わるたびに差し替えていたため、動く画像が最初のコマに戻っていた）。歌詞画面・狭い幅で隠すときも読み込んだまま見えなくし、戻ると続きから動く。「立ち絵を出す」を切った・スキンを替えた・立ち絵の無いスキンのときは画像を手放す。「動きを減らす」のときは、今の状態の止まった絵だけを読む。再生中と停止中が同じ画像なら1枚だけ読む（決まりは `src\skins\character.ts` の `characterStage`）。

## 7. アプリのアイコン

```json
"application": { "window": "app/window.png", "tray": "app/tray.png" }
```

`window` はウィンドウとタスクバー、`tray` はタスクトレイ（無ければ `window` の画像、それも無ければ組み込みのアイコン）。`tray` は `{"default": …, "playing": …}` とも書けるが、3.2.0 は再生中でも変えない（`playing` は確かめるが使わず、警告）。

**静止画だけ**（動く画像は断る）。Rust が読み、縦横比を保って透明で埋めた正方形（ウィンドウ 256px・トレイ 64px まで）にして差し替える。読めなければ組み込みのアイコンに戻して知らせる。

**変わらないもの：**exe・インストーラー・スタートメニュー・デスクトップのショートカットのアイコン（ビルドのときに exe に入れたもの）。設定の欄にもそう書く。

## 8. 動く画像

| 形式 | 拡張子 | 読み方（`image` 0.25.10。足した部品は無い） |
|---|---|---|
| GIF | `.gif` | 全部のコマを読む。1コマだけなら静止画として扱う |
| APNG | `.png` | 動く印（acTL）があれば全部のコマを読む |
| 動く WebP | `.webp` | 動く印があれば全部のコマを読む |

3つとも、今の部品で全部のコマを読めることをテストで確かめた（`animated_formats_first_frame`。テストの画像は、その場で作る図形だけ）。

**取り込みのとき、最初の1コマを PNG にして `derived\` に置く。**OS の「動きを減らす」（`prefers-reduced-motion: reduce`。Windows の「アニメーション効果」を切ったとき）のあいだは、画面はこの1コマだけを読み、動く本体は読まない。設定を途中で切り替えても、見張っているのですぐ変わる。

1コマの表示時間が 10ms 以下のものは、ブラウザと同じく 100ms として長さを数える。

## 9. 取り込みの手順

| 段 | 中身 |
|---|---|
| 1 | 設定の「＋ zip を取り込む…」。ファイルを選ぶ画面は Rust が出す（画面からパスを渡さない） |
| 2 | Rust が zip をメモリに読み（25MB まで）、項目の名前と大きさを全部確かめる（中身を戻す前） |
| 3 | 中身を戻す（申告の大きさを1バイトでも超えたら止める。deflate が使った入力と、圧縮後の大きさの申告が合わなければ断る）。skin.json を読み、使う画像が揃っているか・使っていないファイルが無いかを見る |
| 4 | 画像を1枚ずつ最後まで復号する（動く画像は全部のコマ）。最初の1コマを作る |
| 5 | データの場所の `skins-staging\<印>\` に書く（正式の場所 `skins\` には触らない。画面からは読めない場所） |
| 6 | 確認画面を出す。「このスキンを取り込む」まで入らない。確認待ちは1つだけ（取り込みの確かめは1本ずつ。確かめている間は「＋ zip を取り込む…」を押せない。新しく確かめるときは前の確認待ちの一時の場所を消す） |
| 7 | `skins\<id>\` へ名前を変えて移し、読み込んで確かめる。読めなければ一時の場所へ戻して断る（正式の場所に残さない）。**同じ id があれば上書きしない**（入っているほうを消してから取り込み直す） |
| 8 | 当てるのは別の操作（一覧の「適用」）。当てるときにもう一度読み込んで確かめる |

どの段で断っても、一時の場所は消し、正式の場所には何も作らない。確認の途中でアプリを閉じたときの残りは、次の起動で消す。

## 10. 取り込みの守りと上限

**上限**（`src-tauri\src\skins\mod.rs` の `limits`・`images.rs`・`manifest.rs`）

|---|---|---|
| `%APPDATA%\jp.local.plplayer3\skins\<id>\` | 入っているスキン | 読める（`tauri.conf.json` の `assetProtocol.scope` に `$APPDATA/skins/**` を足した） |
| `%APPDATA%\jp.local.plplayer3\skins-staging\` | 確認待ち | 読めない（確認画面の見本は、Rust が縮めて data: URL で渡す） |

`PL_PLAYER_DATA_DIR` を指定したときは、そのフォルダの `skins\` を、今の `artwork\`・`backgrounds\` と同じやり方（起動のときに `asset_protocol_scope().allow_directory`）で許す。CSP は変えていない（画像は今までどおり `asset:` と `data:` だけ）。

**画面から Rust にパスを渡す窓口は作っていない。**zip は Rust がファイルを選ぶ画面を出し、スキンは id、取り込みは確認の印（16 桁）で指す。画面へ渡す画像のパスは、Rust が `skins\<id>\` の中で確かめたもの（途中の段も含めてリンクを辿らない）だけ。画面はそれを `src\ipc\events.ts` の `fileUrl` で URL にするだけ。

使うスキンの id は設定（`skin.activeSkinId`）に置く。**変えるのは「適用」「既定に戻す」「削除」だけ**で、画面から来た設定の保存（`settings_set`）では変わらない。設定のバックアップ（zip）には入るが、読み込んでも今の値のまま（スキンそのものは入らないため）。

## 12. 逃げ道

| 方法 | 動き |
|---|---|
| 設定「既定の見た目に戻す」 | 既定のスキンを当てて保存する |
| タスクトレイの右クリック「既定の見た目に戻す」 | 同じ（画面が読めないときのため） |
| 設定「次の起動を既定の見た目にする」 | 次の起動だけ既定の見た目（セーフモード）。起動したら印は消える。保存しているスキンは変えない |
| 起動の指定 `--safe-mode` | 既定の見た目で起動する（セーフモード）。保存しているスキンは変えない |
| **もう起動しているときの `--safe-mode`** | 二重起動を防ぐ部品（tauri-plugin-single-instance）が、2つ目の起動の指定を前からあるアプリに渡す。前からあるアプリがセーフモードに切り替わり、ウィンドウを前に出す（閉じてもトレイに残る作りなので、これが無いと指定が届かない） |
| 前に選んでいたスキンが壊れていた | 起動のとき、画面が最初に描く前に確かめ、読めなければ既定に戻して保存し、知らせる（どのスキンか・何が読めなかったか） |

セーフモードの間は、設定の欄に「保存しているスキンに戻す」「既定の見た目のままにする」を出す。起動のときの確かめは、skin.json・`derived\info.json`・使う画像が在ること・大きさ・頭のバイト（拡張子と合うか、`MZ` でないか）・最初の1コマが在ること。画像の復号は取り込みのときに済ませてあるのでしない。

## 13. 画面

**設定の「着せ替え」の欄**（「表示」の次）：今のスキン／スキンのカード（見本・名前・作者と版・部品の札・適用・書き出す・削除。既定のスキンは「削除不可」）／「＋ zip を取り込む…」（確かめている間は押せない）「既定の見た目に戻す」／「次の起動を既定の見た目にする」と戻し方の説明／アプリのアイコンについての説明／立ち絵を出す・大きさ（75〜125%、5% 刻み）。使っているスキンを消すときは、先に既定に戻す（確認あり）。

**取り込みの確認画面**：手順（zip を選ぶ → 中身を確かめる → 取り込み）／見本・名前・作者・版・id・説明・部品の札／ファイル（skin.json・見本・フォルダごとの枚数と動く画像の数）／大きさ（zip・展開後・ファイルの数・いちばん大きい画像・動く画像のコマ数と長さ）／無視したファイル（OS が足すものの種類と数）とフォルダを外したことの知らせ／警告（skin.json の知らせは種類ごとに3件まで・超えた分は「ほか N 件」。色の読みやすさ）／同じ id があるときの知らせ。

どちらも今のアプリの部品（ボタン・欄・小窓）と変数だけで作った。
