# PL Player 3

Windows 向けのローカル音楽プレイヤーです。手元の音楽ファイルを管理しながら、背景画像とアルバムアートで見た目を自分好みに変えられます。歌詞の表示（時刻つき歌詞の自動追従・再生バーの下を流れる歌詞の列）に対応しています。

**既定では、アプリは外へ一切通信しません。**例外は設定の「歌詞をネットから取る」だけで、オンにしてボタンを押したときに限り、[LRCLIB](https://lrclib.net/)（無料の歌詞データベース）へ曲のタグの曲名・アーティスト名・アルバム名と曲の長さを送ります。ファイルの場所やファイル名は送りません。

この README は2つに分かれています。

| 読む人 | 読むところ |
|---|---|
| ダウンロードして使うだけの人 | [使う人へ](#使う人へ)（入手・起動・データの場所・着せ替え・表示を整える・曲をごみ箱へ移す・年間まとめ・歌詞・既知の制限・通信） |
| ソースから自分でビルドする人・改造する人 | [改造する人へ](#改造する人へソースからビルドする)（開発環境・ビルド・テスト・構成。作者が配るときの手順も末尾に） |

## できること

- 音楽ファイルの取り込みと管理（MP3・WAV・FLAC・M4A（AAC-LC/HE-AAC/ALAC）・AAC・OGG Vorbis・OPUS）
- 古い文字コード（Shift_JIS など）で書かれたタグの文字化けを、読むときに直す（曲ファイルは書き換えない。v3.1.2）。直らずに残った名前は、設定から読み直せる（v3.5.0）
- 曲一覧・アーティスト・アルバム・ジャンル・プレイリスト・キュー・お気に入り・検索
- タグの編集（曲名・アーティスト・アルバム・ジャケットなど。安全な差し替えで書き込み）
- 背景画像とテーマ（Dark / Light）、狭い幅に合わせて縮む画面
- 着せ替え（スキン。v3.2.0）：色と文字・ボタンのアイコン・ウィンドウとトレイのアイコン・キャラクターの立ち絵（動く画像も）を、スキンの zip で変える
- 立ち絵（v3.9.0）：画像（PNG・WebP・GIF。動く画像も）を選ぶだけで立ち絵を作り、何体も登録して、スキンとは別に選べる（ほかのスキンの立ち絵も選べる）。v3.9.1 から、見本の立ち絵「くじら」が最初から入っている
- 歌詞
  - 時刻つき歌詞（LRC）の自動追従、曲ごとの時刻補正、手入力
  - 再生バーの下を右から左へ流れる歌詞の列（オン・オフ可）。掛け合いの括弧は薄く表示
  - 曲ファイルに入っている歌詞・手で入れた歌詞・LRCLIB から取った歌詞の優先順
- Windows 連携：メディアキー（SMTC）・タスクバーのサムネイルボタン・トレイ・グローバルホットキー
- 再生中に出力デバイスを替えても、曲と位置を保つ
- 同時再生（v3.8.0）：3つまでの再生デバイスへ同じ曲を同時に流す。出力ごとの音量・遅らせ量・メーター。再生バーの出力ボタンと、上の帯の「詳細」の表示（ミキサー）で操作する
- 設定・プレイリスト・お気に入りの書き出しと読み込み（zip）。v3.8.0 から出力先（再生デバイス）の設定も入る。**再生デバイスの名前が入るので、人に渡すときは注意**。読み込むと一時停止して、出力先は全部オフで入る
- 使わない再生バーのボタン・サイドバーの項目を隠す、設定のタブを好きな順に並べる（v3.3.0）
- 曲ファイルを Windows のごみ箱へ移す（データの整理用。ライブラリの曲一覧の右クリックから。行のボタンは設定でオンにしたときだけ。v3.3.0）
- 曲一覧のコンパクト表示（ジャケットを出さず1行に詰める。いつも／窓が狭いときは自動で）・サイドバーのアイコンの大きさ（v3.4.0）。上の帯の右端の「通常／コンパクト」でも切り替えられる（v3.8.0）
- 年間まとめ：開いた時点から1年（365日）の間に、このプレイヤーで再生した回数の上位 100 曲（v3.6.0）

## 使う人へ

### 入手

[GitHub の Releases](https://github.com/rr2pp2/pl-player/releases) から、最新の版を落としてください。ソースからビルドする必要はありません。

| ファイル | 使い方 |
|---|---|
| `PL-Player-<版>-x64-setup.exe` | インストーラー。今のユーザーにだけ入れる（管理者権限は要らない）。スタートメニューに出る。消すときは Windows の「インストールされているアプリ」から |
| `PL-Player-<版>-x64-portable.exe` | インストールせずに、置いた場所からそのまま起動できる版。中身はインストーラーと同じ |
| `PL-Player-<版>.zip` | 上の2つと、使う人向けの README と、「見本」フォルダ（v3.9.1。立ち絵の見本「くじら」の絵2枚・スキンの見本「くもくじら」の zip・使い方）をまとめたもの。中の exe の名前は `PL Player 3_<版>_x64-setup.exe` と `PL Player 3（インストールせずに使う）.exe`（中身は上の2つと同じ） |
| `PL-Player-<版>.sha256.txt` | 上の3つの SHA256。落としたファイルが壊れていないか、差し替えられていないかを照らすときに使う |

どちらの exe を使っても、ライブラリ・設定は同じ場所に置かれます（下の「データの場所」）。

照らし方：落としたファイルと `PL-Player-<版>.sha256.txt` を同じフォルダに置き、そのフォルダで次のどちらかを打つ（`<版>` は落とした版の番号に）。名前を変えて保存したファイルは照らせません。

PowerShell（Windows に入っているもの）。落としたファイルごとに `OK` か `NG` が出る。一覧と同じ名前のファイルが1つも無いときは「照合できるファイルがありません」と出る：

```
$c = 0; Get-Content .\PL-Player-<版>.sha256.txt | ForEach-Object { $h, $n = $_ -split ' \*', 2; if (Test-Path -LiteralPath $n) { $c++; '{0}  {1}' -f $(if ((Get-FileHash -LiteralPath $n).Hash -eq $h) { 'OK' } else { 'NG' }), $n } }; if ($c -eq 0) { '照合できるファイルがありません（一覧と同じフォルダに、同じ名前で置いてください）' }
```

一覧の SHA256 は小文字、`Get-FileHash` が出す値は大文字で書かれるが、大文字小文字は問わない（同じ値。上の1行も大文字小文字を問わずに比べる）。目で照らすときは、英字の大小を無視して並びだけを見る。

Git Bash・WSL など `sha256sum` がある場所。落としていないファイルは飛ばす：

```
sha256sum -c --ignore-missing PL-Player-<版>.sha256.txt
```

### 「Windows によって PC が保護されました」と出たら

このアプリには、配った人を証明する署名（コード署名）を付けていません。そのため、初めて起動するときに Windows の青い画面（SmartScreen）が出ることがあります。画面の「詳細情報」を押し、下に出る「実行」を押すと起動します。

### 必要なもの

- Windows 10 / 11（x64）と WebView2 ランタイム（Windows 11 には標準で入っています）
- WebView2 は**入れる側の PC に既にある前提**です。インストーラーは WebView2 を取りに行きません。Windows 10 の古い環境などで WebView2 が無いと起動しないので、Microsoft の配布ページから WebView2 ランタイムを入れてください

### データの場所

- `%APPDATA%\jp.local.plplayer3\`（ライブラリの DB・アートの縮小版・背景画像・ログ・歌詞の受け渡しフォルダ `lyrics\`・取り込んだスキン `skins\`・追加した立ち絵 `avatars\`（v3.9.0））
- 音声ファイルはコピーしない。元の場所を参照する
- 3.0.0 以降の版は、どれも同じ場所を使う。版を上げても、ライブラリ・設定・歌詞はそのまま

うまく動かないときと、通信のことは、下の「[既知の制限](#既知の制限)」と「[通信について](#通信について)」を見てください。

### 着せ替え（v3.2.0）・立ち絵（v3.9.0）

スキンの zip を取り込んで、アプリの見た目を変えます。使うスキンは1つ。今までの見た目は「既定のスキン」として残り、消せません。v3.9.0 から、立ち絵はスキンとは別に選べます（画像を選んで追加することもできます）。**スキンを取り込んでも、立ち絵を追加しても、アプリは外へ通信しません。**

| やりたいこと | 操作 |
|---|---|
| スキンを取り込む | 「設定 → 着せ替え →＋ zip を取り込む…」で zip を選ぶ。中身を全部確かめてから確認の画面が出る（名前・作者・部品・ファイルの数・大きさ・色の読みやすさの警告）。「このスキンを取り込む」まで入らない。同じ id のスキンが入っていれば上書きしない |
| 当てる | 一覧のスキンの「適用」。取り込んだだけでは当たらない |
| 既定の見た目に戻す | 「既定の見た目に戻す」（設定）か、タスクトレイのアイコンの右クリック →「既定の見た目に戻す」。**立ち絵は残る**（v3.9.0。スキンだけを戻す） |
| 立ち絵を出さない（v3.9.0） | 「既定の見た目に戻す」の隣の「立ち絵を出さない」（設定）か、タスクトレイのアイコンの右クリック →「立ち絵を出さない」。追加した立ち絵は消えない（「立ち絵」の欄のカードか「使う」で戻せる）。立ち絵の画像で画面が崩れたときも、トレイから外せる |
| 人に渡す | スキンの「書き出す…」で zip にする（skin.json と、それが使う画像だけ） |
| 消す | スキンの「削除」（確認あり。使っているスキンなら先に既定に戻す） |
| 立ち絵を選ぶ（v3.9.0） | 「設定 → 着せ替え」の「立ち絵」の欄で、使うものの「使う」を押す。並びは「スキンの立ち絵」（当てているスキンの立ち絵。既定）・「出さない」・取り込んだスキンの立ち絵・追加した立ち絵。スキンを替えても、追加した立ち絵・ほかのスキンの立ち絵を選んでいればそのまま（「色はスキン A、立ち絵はスキン B」もできる。スキンの絵は写さずに指すだけ） |
| 立ち絵を追加する（v3.9.0） | 「＋ 立ち絵を追加…」→ 再生中の絵を選ぶ → 停止中の絵を選ぶ（選ばなければ、止めている間も再生中の絵）→ 名前（1〜40 文字。空のままなら再生中の絵のファイル名。使えない文字は外し、40 文字で切る。それでも空なら「立ち絵」）→「追加」。追加しただけでは出さない（カードか「使う」で出す）。30 体まで |
| 見本の立ち絵「くじら」（v3.9.1） | 最初から一覧に入っている。新しく入れた人は、初めて起動したときから使う立ち絵に選ばれている（右に出る）。前の版から上げた人は一覧に1体増えるだけで、今の選択と見た目は変わらない（30 体いっぱいなら増えない）。追加した立ち絵と同じに変更・削除でき、消したら次の起動でも版を上げても戻らない。同じ絵が配布の zip の「見本」フォルダにある（自分の絵に差し替えて「＋ 立ち絵を追加…」で入れる下敷き） |
| 使う（v3.9.0） | 一覧のカードのどこを押しても、その立ち絵に切り替わる（「使う」ボタンでも。キーボードはカードに移って Enter か Space） |
| 変更・削除（v3.9.0） | 追加した立ち絵の「変更」：今の再生中・停止中の絵と名前が出て、再生中だけ・停止中だけを差し替える・停止中を外す・名前を変える（差し替える画像の決まりは追加と同じ。「保存」を押すまで今の絵は変わらず、途中で失敗しても今の絵が残る。使っている立ち絵なら画面の絵もすぐ変わる）。「削除」は確認あり（使っている立ち絵を消すと「スキンの立ち絵」に戻る） |
| 立ち絵の大きさ | 75〜200%（v3.9.0。3.8.1 までは 125% まで。つまみの下に、その大きさで立ち絵が出る窓の幅と、今の窓で出せるかが出る）。立ち絵は右側に専用の幅を取って出す（曲一覧はその左まで）。v3.9.0 から専用の幅は**窓の幅で決まる**：窓の幅 × 18% × 大きさ を 140〜480px に収めたもの ＋ 12px（値は暫定）。ただし曲一覧の側に残す幅（ふだん 634px・詳細 360px）が足りないときは、隠す前にまず 140px まで縮め、それでも残らないときだけ隠す。どの立ち絵でも同じ窓・同じ大きさなら同じ幅なので、立ち絵を切り替えても曲一覧の幅は変わらない（スキンの立ち絵の幅の値は使わない）。絵は高さ（高さの上限 × 大きさ）に合わせて出し、横長の絵は左右のはみ出した分が切れる（スキンの立ち絵も同じ）。140px まで縮めても曲一覧の側に 634px 残らないとき（窓が狭いとき。大きさには関係しない）と歌詞画面では隠れる。**詳細の表示でも出す**（作者の決定）：詳細のときの境目は、詳細の配置が曲一覧に必ず残している 360px（立ち絵を出しているときは、曲一覧の列（アルバム・ジャンル）・ジャケット・行の高さ・自動のコンパクトを、立ち絵の幅を除いた曲一覧の実際の幅で決める。ミキサーを横に並べたときは、立ち絵は曲一覧とミキサーの間に出る。下に並べたときは曲一覧の右。曲一覧・ミキサー・立ち絵は重ならない。例：窓 1400px・100%・ミキサーを横に並べた詳細で出る）（634px は 3.8.1 で窓 920px のときに残っていた幅。例：ふだんの表示では窓 およそ 880px から出る。詳細では、ミキサーを横に並べ始める窓・サイドバーが開く窓で曲一覧の側そのものが狭くなるので、その少し先まで隠れることがある）。クリックは下の画面に届く。Windows の「アニメーション効果」を切っているときは、動く画像を止まった絵で出す |

**見た目が読めなくなったとき：**タスクトレイの「既定の見た目に戻す」（立ち絵は残る。立ち絵も外すときは、同じメニューの「立ち絵を出さない」）のほか、起動の指定 `--safe-mode` を付けて起動すると既定の見た目（セーフモード）で起動する（保存しているスキンは変えない。設定の「着せ替え」から戻せる）。**もう起動していても、`--safe-mode` を付けて起動すれば、動いているほうが既定の見た目に切り替わる。**設定の「次の起動を既定の見た目にする」は1回だけ効く。前に選んでいたスキンが壊れていたら、起動のときに既定に戻して知らせる。

**アイコン：**スキンで変わるのは、起動中のウィンドウ・タスクバー・タスクトレイのアイコンだけ。exe・スタートメニュー・ショートカットのアイコンは変わらない（変えたいときは、ショートカットのプロパティの「アイコンの変更」で）。

**スキンに入れられるもの：**skin.json と画像（PNG・APNG・WebP・GIF）だけ。実行ファイル・スクリプト・SVG・CSS・フォントの入った zip、フォルダの外を指す名前・リンクの入った zip、大きすぎる zip（25MB・展開後 80MB・ファイル 64 個・画像1つ 15MB・縦横 4096px・120 コマ・90 秒まで）は取り込まない。設定のバックアップ（zip）にスキンと立ち絵の画像は入らない（使うスキン・立ち絵の大きさなどの選択も、読み込んでも今のまま）。**ただし「使う立ち絵」の選択（v3.9.0）は zip の値になる。**読み込んだ PC に無い立ち絵・スキンを指していたら「スキンの立ち絵」に戻して知らせる。値が壊れていたら「スキンの立ち絵」。**3.8.1 までの zip（値が無い）では、今選んでいる立ち絵を変えない。**

**画像から追加する立ち絵（v3.9.0）：**使える画像は PNG・WebP・GIF（APNG・動く WebP・動く GIF も）。確かめ方と上限はスキンの立ち絵と同じ（1つ 15MB・縦横 4096px・120 コマ・90 秒まで。壊れた画像・拡張子と中身が違う画像・中身が実行ファイルのものは断り、理由を出す）。選んだ画像はデータのフォルダの `avatars\<id>\` へ写して置く（元のファイルは使い続けないので、消しても動かしてもよい）。高さの上限は 420px（× 大きさ）。専用の幅と隠す決まりは、どの立ち絵でも同じ（上の「立ち絵の大きさ」）。3.8.1 から上げたときは「スキンの立ち絵」（3.8.1 で「立ち絵を出す」を切っていたなら「出さない」）になり、見た目は変わらない。既定の見た目で動いている間（セーフモード）は、どれを選んでいても立ち絵を出さない。選んでいた立ち絵が起動のときに読めなければ（ファイルを消した など）、「スキンの立ち絵」に戻して知らせる。立ち絵を1体ずつ書き出す・取り込む機能は、この版には無い。

作り方は `docs\スキンの作り方.md`、決まりの全文は `docs\着せ替え_仕様.md`。

**動く立ち絵（v3.3.0）：**再生中と停止中の絵を2枚とも読み込んだまま重ね、見せる方だけを切り替える。だから、再生・一時停止を切り替えても、動く画像は最初から始まり直さない（見えていない間に裏で進むこともある）。歌詞画面と狭い幅で隠れる間も読み込んだままで、戻ると続きから動く。「出さない」を選んだとき・使う立ち絵やスキンを替えたときは画像を手放し、次に出すときは最初から。「動きを減らす」のときは、今の状態の止まった絵だけを読む。再生中と停止中が同じ画像なら1枚だけ読む。

### 表示を整える（v3.3.0・v3.4.0・v3.5.0・v3.6.0）

| やりたいこと | 操作 |
|---|---|
| 設定の項目を探す | 設定画面の上のタブ（表示・着せ替え・再生デバイス・ライブラリ・ネットの歌詞・キー操作・アプリ）。開いていたタブは、アプリを閉じるまで覚える |
| タブを並べ替える | タブをドラッグする。キーボードでは、タブで Space か Enter を押して持ち上げ、矢印キー（上下左右）で動かし、もう一度 Space か Enter で置く（Esc で取りやめ）。持ち上げていないときは、左右の矢印キーでタブを移る。並びは保存され、設定の zip にも入る。「元の順番に戻す」で、はじめの並びに戻る。ウィンドウが狭くて入りきらないときは、タブを複数行に折り返す（横には送らない。折り返していても、ドラッグとキーボードで行をまたいで並べ替えられる）。狭いとき、「元の順番に戻す」はタブの下の行へ回る |
| 再生バーのボタンを隠す | 「設定 → 表示 → 再生バーのボタン」のチェックを外す。隠せるのはシャッフル・リピート・出力先（出力ボタン。v3.8.0）・音量（ミュートと音量の帯）・流れる歌詞の列のオン・オフ・歌詞。**再生・一時停止・前の曲・次の曲・シークバーは隠せない**（隠すと操作できなくなるため）。隠しても、ショートカット（`Ctrl+L` など）はそのまま効く。隠したボタンは、下の「···」の中にも出ない（v3.8.0） |

### 同時再生と詳細の表示（v3.8.0）

3つまでの再生デバイス（有線のヘッドホン・スピーカー・仮想オーディオケーブルなど）へ、同じ曲を同時に流せます。3.7.0 から上げたときは、今選んでいるデバイスが出力先1にオンで入り、今までどおりに鳴ります。

| やりたいこと | 操作 |
|---|---|
| オン・オフと出力ごとの音量 | 再生バーの出力ボタン（全体の音量の左）を押すと、上に一覧が開く。行ごとに、チェック（オン／オフ）・アイコン・名前・その出力だけの音量・細いメーター。オフにした出力先はデバイスを手放す（ほかのアプリが使える）。出力ボタンには、オンの出力先が1つならそのアイコンと名前（切断中・開けません・重複のときは、名前とアイコンの代わりにその状態の文字。ボタンの縁が危険の色になり、2〜3 つのときや1段のときは、鳴らせない出力のアイコンの角に「!」が付く）、2〜3 ならアイコンが並び、0 なら「出力なし」と出る（1段のときはアイコンだけ）。マウスを乗せるかキーボードで移ると、オンの出力先の名前が全部出る |
| 出力先を足す・外す・詳しく見る | 上の帯の「詳細」。曲一覧の横（狭い窓・縦長の窓では下）に「出力」のミキサーが出る。行ごとに、名前・今の大きさ（dB）・左右のメーター（緑 -20 dB まで・黄 -20〜-9 dB・赤。OBS と同じく、上がるときはすぐ、下がるときは 1.7 秒で 40 dB の速さでゆっくり。直前の最大の線は 20 秒残る。0 dB に届くと「音割れ」と 2 秒出る）・音量・オン／オフ（スピーカーの印）・「…」。「＋ 出力先を追加」で足す（足した出力先はオフで入る）。「…」から、遅らせ量（0〜1000 ミリ秒。再生デバイスどうしを合わせるためのもので、映像に合わせるものではない）・全体の音量に従う・デバイスの差し替え・アイコンの選び直し・外す（確認なし。音量などは覚えておき、同じデバイスを足すと戻る） |
| 詳細の表示 | 曲一覧・キュー・歌詞・設定など、どの画面を開いてもミキサーは出したまま。歌詞の画面でも検索欄を出す（打ち始めると「すべての曲」へ移って探す）。窓の高さが足りず曲一覧が2行を切るときは、流れる歌詞の列を自動で隠す（設定は変えない）。詳細のまま終了すると、次も詳細で開く。ショートカット「詳細表示の切替」（設定 → キー操作。既定のキーは空。グローバルにもできる）で抜けると、入る前の通常／コンパクトに戻る |
| 音量の2組 | 全体の音量と出力ごとの音量は、「通常（コンパクトも同じ）」と「詳細」で別々に持つ。詳細で「全体の音量に従う」を外した出力先は、再生バーの音量とミュートで変わらない（行に「個別」と出る） |
| デバイスを選び直す | 「設定 → 再生デバイス」で、出力先ごとに選ぶ（出力先が2つ以上あれば、上の「出力先1・2・3」で切り替える）。ほかの出力先で使っているデバイスは一覧に出ない |
| 切断されたとき | その出力先だけ「切断中」になり、つながると自動で今の位置から戻る（「○○が戻りました」）。既定のデバイスへは移らない。オンの出力先が全部使えなくなったら一時停止し、戻っても自動では再生しない。つながっているのに開けないデバイスは「開けません」（マウスを乗せると理由）、既定のデバイスがほかの出力先と同じになったら「重複」 |
| ショートカット | 「出力1・2・3 のオン／オフ」（空いているいちばん小さい番号の枠。既定のキーは空。グローバルにもできる） |

**配信に使っている間は、再生中の曲のタグを書き換えないでください**（書き込むときに音が一瞬止まります）。

### 曲をごみ箱へ移す（v3.3.0。データの整理用）

**ライブラリの曲一覧**（すべての曲・最近追加・最近再生・年間まとめ（v3.6.0）・お気に入り・アーティスト／アルバム／ジャンルを開いたところ）で、曲の右クリックのメニューに「ライブラリから外す…」と並んで**いつも出る**（どちらも確認あり）。**行の右端のボタン（「ごみ箱」の列）は既定はオフ**で、「設定 → ライブラリ → データの整理」の「曲一覧に『ごみ箱』の列を出す」をオンにしたときだけ出る（列の見出しは「時間」「ジャンル」と同じ行に「ごみ箱」。行のボタンはアイコンだけで、読み上げと吹き出しで何をするかを伝える）。設定が決めるのは行のボタンだけ。**プレイリストとキューの一覧には出さない**（行のボタンも右クリックのメニューも。「プレイリストから削除」「キューから削除」と取り違えて、曲ファイルまで移さないため）。再生バーの曲名の右クリックにも出さない。**曲ファイルそのものを Windows のごみ箱へ移す**（ライブラリから外すだけの「ライブラリから外す…」とは別）。

| 項目 | 決まり |
|---|---|
| 対象 | 押した行が選んでいる行の中にあれば、選んでいる曲の全部。選んでいない行なら、その行だけ（右クリックのメニューと同じ決まり）。同じ曲は1回だけ。ライブラリの2つの行が同じファイルを別の綴り（大文字小文字だけが違う、など）で指していれば、ファイルは1回だけ移し、選んだ行を全部外す（選んでいない行は、ほかの消えたファイルと同じく「見つからない」曲として残る） |
| 確認 | 曲名とファイルの場所（6曲目からは「ほか N 曲」）・「ごみ箱から戻せます」・ごみ箱の無い場所では移さないこと・一緒に外れるもの（年間まとめの記録まで。v3.7.0）を出す。「ごみ箱へ移す」を押すまで何もしない。最初に選ばれているのは「キャンセル」（v3.7.0。誤って Enter を押しても移さない） |
| 移したあと | ライブラリ・プレイリスト・キュー・お気に入り・その曲の歌詞（手動・外部）と時刻の補正から外れる（「ライブラリから外す」と同じ）。ごみ箱から戻しても、ライブラリには自動では戻らない（取り込み直す。ライブラリに足したフォルダの中なら「再走査」でも入る。プレイリスト・お気に入りの印は戻らない）。ファイルは移せたのにライブラリから外せなかった曲（DB への書き込みの失敗）は、移した数とは別に知らせる（一覧に残るので「ライブラリから外す…」で外す） |
| 再生中の曲 | 先に止めてファイルを手放してから移す。鳴っているのが選んでいない別の綴りの行でも、同じファイルなら手放す。移せたら止まったまま（曲なし。鳴っていた別の綴りの行は、キューと今の並びから外れ、ライブラリには「見つからない」曲として残る）。移せなかったら、同じ位置から元の状態（再生中なら再生）に戻す |
| 移さないもの | **ごみ箱の無い場所**（USB メモリなどの取り外せるドライブ・CD・RAM ディスク。ドライブの文字ではなく、途中のジャンクション・リンクをたどった本当の置き場所のボリュームで決める。本当の置き場所がネットワーク上なら、それも断る）。ごみ箱を使わない設定にしたドライブや、ごみ箱に入らない大きさの曲も、Windows が完全に消そうとした時点で取りやめる（完全に消える操作はしない）。ネットワーク上の場所・ほかのアプリが使っている曲・権限の無い曲・見つからない曲も移せない。理由の種類ごとに知らせ、その曲はファイルもライブラリもそのまま |
| まとめて移すとき | 先に全部の曲を確かめ、ライブラリに無い・音声ファイルでない・ごみ箱の無い場所・ネットワーク上の場所・見つからない曲が1つでもあれば、どれも移さない。確かめを通ったあとは1曲ずつ移し、移せた曲だけをライブラリから外す（使用中などで移せなかった曲は残る）。一度に 1,000 曲まで（超えたら、確認の小窓を出す前に断る。何も移さない） |
| 守り | 画面からは曲の番号（id）だけを渡す。ファイルの場所はアプリがライブラリの DB から引き、ライブラリの曲であること（音声ファイルの拡張子・フォルダやリンクでない）を確かめてから移す。移す直前にも、通常のファイルかをもう一度確かめる（シェルを呼ぶ直前と、シェルが消す直前の `PreDeleteItem`。確かめたあとで同じ名前のフォルダに差し替えられても、それは移さない）。どこから押しても、画面は必ず確認を出す。移す処理の入口は設定を見ない（右クリックのメニューからは設定にかかわらず使うため。「どこから押したか」を画面から受けて分けることもしない。呼べるのは同じ画面だけで、名乗りを信じることになり守りにならないため）。設定の zip を読み込むと、行のボタンはオフに戻る（受け取った zip で気づかないうちに行に出ないように） |
| 作り | Windows のシェルの `IFileOperation`（ごみ箱へ移す指定）。完全に消える項目は、消す前の知らせ（`PreDeleteItem`）で取りやめる。通信しない |

### 年間まとめ（v3.6.0）

サイドバーの「年間まとめ」（「最近再生」の次）を開くと、**開いた時点から 365 日さかのぼって、このプレイヤーで再生した回数の多い順に、上位 100 曲**を並べる。

| 項目 | 決まり |
|---|---|
| 数え方 | 曲を再生し始めたら1回（途中で次の曲へ送っても1回。1曲リピートは繰り返すたびに1回）。曲ごとの再生回数（ライブラリの `play_count`）を +1 するのと同じ所・同じ時刻で、1回ずつ記録する（数え方を2か所で別々に持たない）。起動したときに前の曲を一時停止のまま読み戻す・タグの保存のあとに再開する・出力先を替える、は数えない |
| 期間 | 開いた時点の今から 365 日前まで（境目ちょうどは入る）。暦の1年（去年の同じ日付）にしないのは、記録の時刻が世界協定時のミリ秒（`last_played_at` と同じ表し方）で、日付で区切るには時差の決まりが要り、2月29日の「去年の同じ日」が決まらないため。365 日ならどの日に開いても同じ長さで数える（うるう年をまたぐときだけ、暦の1年より1日短い）。開き直す・ライブラリが変わる（曲を外す・タグを直す など）と数え直す。開いたまま再生した分は、開き直すと入る（「最近再生」と同じ） |
| 並び | 回数の多い順。同じ回数なら、期間の中で最後に再生した時刻の新しい順（今の好みに近い曲を上に）。それも同じなら曲の番号の小さい順（開くたびに並びが変わらないように）。順位は同じ回数でも1つずつ進める（上の決まりで並びが1通りに決まり、100 位の境目もあいまいにならない。回数は列に出る） |
| 一覧 | 曲一覧と同じ表。左端に「順位」、時間の前に期間中の「回数」の列を足す。ダブルクリック・Enter で再生（並びは年間まとめの順）・右クリックのメニュー（「ライブラリから外す…」「ごみ箱へ移す…」も）・ドラッグ・お気に入り・「ごみ箱」の列は、ライブラリの曲一覧と同じ。見出しを押しても並べ替えない。上の検索欄で絞ると、上位 100 曲の中で当たる曲だけを出す（順位は絞る前のまま） |
| 記録の始まり | **3.6.0 から貯め始める。**3.5.0 までに再生した分は入らない（曲ごとの再生回数はあるが、いつ再生したかが無いので、そこから記録を作ると嘘になる）。記録が1年に満たないうちは、見出しの下に「3.6.0 から数え始めたので、〜より前の再生は入っていません。」と出す（数え始めた日は、3.6.0 で最初に起動した時刻）。期間の中に1回も無ければ、一覧に「まだ再生の記録がありません。3.6.0 から、再生した回数を数え始めました…」 |
| 曲を外すと | 「ライブラリから外す」「ごみ箱へ移す」で、その曲の記録も消える（一覧に出ない。同じファイルを取り込み直しても、前の記録は戻らない） |
| 隠す | 「設定 → 表示 → サイドバーの項目」（上の「表示を整える」） |
| 通信 | しない |

### 歌詞（v3）

#### 使い方

| やりたいこと | 操作 |
|---|---|
| 歌詞を見る | 再生バーの右の「歌詞」ボタン（v3.8.0：入りきらない幅では「···」の中）、または `Ctrl+L`（設定の「ショートカット（アプリ内）」で変えられる）。中央の画面が歌詞に切り替わる |
| 閉じる | 歌詞画面の左上の戻るボタン、`Esc`、もう一度 `Ctrl+L`。開く前の画面へ戻る |
| 好きな行へ移動 | 時刻つきの歌詞の行をクリック（行にフォーカスして Enter でも） |
| 自動で追いかけるのを止める | ホイールやスクロールバーで動かすと止まり、上に「追従を止めています ／ 追従再開」が出る。最後に動かしてから 8 秒で戻る |
| 歌詞と音がずれる | 左の列の「−100ms」「+100ms」「リセット」。曲ごとに保存する。＋は歌詞を遅らせる |
| 歌詞を手で入れる・直す | 「歌詞を編集」。貼り付けると、時刻タグ（`[00:12.34]`）があれば時刻つき、無ければ時刻なしと判定して、保存前に行数・形式・警告を見せる。保存先はアプリの中（曲ファイルは変更しない） |
| 手で入れた歌詞を消す | 編集画面の「手動の歌詞を削除」（確認あり）。消すと外部の歌詞、次に曲のタグの歌詞に戻る |
| 外部ツールの歌詞を取り込む | 「設定 → ライブラリ → 外部歌詞を取り込む」（歌詞の無い曲の歌詞画面にも同じボタン）。取り込みはこのボタンを押したときだけ |
| 歌詞をネットから取る（v3.1.0） | 「設定 → 歌詞をネットから取る」でオンにしてから、「歌詞を取ってくる」（一括）か、歌詞の無い曲の歌詞画面の「ネットから探す」（1曲）。既定はオフ。下の「歌詞をネットから取る（v3.1.0）」 |
| 流れる歌詞の列を出す・隠す（v3.0.2） | 再生バーの「歌詞」ボタンのすぐ左のボタン（v3.8.0：入りきらない幅では「···」の中）、または `Ctrl+Shift+L`（設定の「ショートカット（アプリ内）」で変えられる）。オン・オフは保存され、次に起動したときも同じ。既定はオン |

**流れる歌詞の列（v3.0.2）**：再生バーの下に高さ 48px の列を出し、歌詞を横一列に並べる（今の行を左寄りに太く、右に次の行、その先を薄く）。行が変わったときだけ列全体が左へ流れる。曲の冒頭は「まもなく歌詞が始まります」、間奏は「♪ 間奏」、最後の「消す」合図の後は「♪ 後奏」、時刻なしは「時刻同期なし」、歌詞が無ければ「この曲には歌詞がありません」。歌詞画面を開いている間も出す（v3.8.0。3.7.0 までは隠れていた）。決まりの全文は `docs\歌詞機能_仕様.md` 6.5。

列と再生バーの1行では、括弧（`( )`・`（ ）`）とその中身（掛け合い・合いの手）を、同じ行の本体より一段薄く・小さく出す（v3.0.2）。閉じていない括弧は行末まで、開きの無い閉じ括弧は行頭からそこまでを括弧の中として扱う（行をまたぐ掛け合いのため。ただし顔文字「:)」や番号「1)」のように直前が `:` `;` `=` か数字なら本体のまま）。歌詞画面の見た目は変えていない。

**列がオフのときだけ**、再生バーの中に小さな歌詞の1行（v3.0.1）を出す：時刻つきのときアーティスト名の下に今の行を1行出し、その右に次の行を薄く出す（押すと歌詞画面）。次の行は「消す」合図と空の行を飛ばし、最後の行では出さない。入りきらない分は右から「…」で切る（次の行から隠れる）。再生バーが1段のとき（v3.8.0。上の「再生バーの形」）は出さない（3.7.0 までは、幅が 719px 以下のとき今の行だけを出していた）。時刻なしは「時刻同期なし」、歌詞が無ければ何も出さない。

#### 受け渡しフォルダの取り決め（外部ツール向け）

外部ツール（歌詞を集める一括スクリプトなど）は、次の形でファイルを置く。v3.1.0 からはアプリ自身も LRCLIB から取れる（下の「歌詞をネットから取る」。既定はオフ）が、受け渡しフォルダはそのまま使える。

| 項目 | 取り決め |
|---|---|
| 置き場所 | `%APPDATA%\jp.local.plplayer3\lyrics\inbox\`（`PL_PLAYER_DATA_DIR` を指定したときは `<そのフォルダ>\lyrics\inbox\`）。「設定 → ライブラリ → 受け渡しフォルダを開く」で作られて開く |
| 曲 ID | v3 のライブラリの `tracks.id`。`%APPDATA%\jp.local.plplayer3\library.db` を**読み取り専用**で開いて引く（例：`SELECT id, path, title, artist, album, duration_ms FROM tracks`）。**v2 の DB の ID とは別物** |
| ファイル名 | `{曲ID}.lrc`（時刻つき）か `{曲ID}.txt`（時刻なし）だけ。正規表現で `^[0-9]+\.lrc$` か `^[0-9]+\.txt$` に合うもの。拡張子は小文字。合わない名前のファイルは読まずに残す。名前が合っていても、フォルダ・ジャンクション・リンクは読まずに残し、「読まなかったもの」に数える（v3.1.1） |
| 書き方 | 一時的な名前（例：`123.lrc.tmp`）で書き終えてから、`123.lrc` へ名前を変える（書きかけを拾わせないため） |
| 中身 | UTF-8（BOM はあってもよい）。改行は CRLF・CR・LF のどれでもよい。1ファイル 1MiB まで（それより先は読まない）。空・空白だけ・情報行だけのものは取り込まない |
| 1曲1ファイル | 同じ曲 ID に `.lrc` と `.txt` の両方を置かない（両方とも取り込まない）。曲 ID は数として比べるので、`02.lrc` と `2.txt` も同じ曲 ID の重複になる |
| 時刻つきの判定 | 拡張子は目安。中身に有効な時刻タグがあれば時刻つきとして扱う |
| 取り込んだあと | `lyrics\processed\{曲ID}-{yyyyMMdd-HHmmss}.{拡張子}` へ移る（時刻はこの PC の時刻） |
| 取り込めなかったもの | `lyrics\rejected\` へ移る：曲 ID がライブラリに無い・`.lrc` と `.txt` の重複・UTF-8 でない・空・大きすぎ |
| 残るもの | DB への保存やファイルの読み込みに失敗したものは `inbox` に残る（もう一度押せば取り込み直す） |
| 手動の歌詞 | 上書きしない。外部の歌詞は保存するが、表示は手動のまま（結果の件数で「手動の歌詞が優先のため表示は変わりません」と分けて知らせる） |
| 同じ曲をもう一度 | 外部の歌詞を上書きする |

読める LRC の書き方：

- 時刻タグ `[m:ss]`・`[mm:ss]`・`[mm:ss.f]`・`[mm:ss.ff]`・`[mm:ss.fff]`。分は1桁以上（60 以上も可）、秒は 00〜59。1行に時刻を複数書ける（`[00:12.00][01:30.00]同じ行`）
- `[ti:]` `[ar:]` `[al:]` `[by:]` `[offset:]` などの情報行は表示しない。`[offset:+200]` は**歌詞を 200ms 早める**（正の値で早める）
- 時刻だけで本文の無い行（`[00:30.00]`）は「今の行を消す」合図
- 語ごとの時刻 `<00:07.25>` は表示から外す（原文には残る）
- 時刻の順でなくても並べ替えて出す。読めない時刻（秒が 60 以上・小数が4桁以上など）は使わず、原文は残す
- 表示する時刻は `max(0, 元の時刻 − offset + 曲ごとの補正)`
- 歌詞の行は 5,000 行まで（v3.1.1）。超えた分は表示せず、「先頭の 5,000行だけを表示しています」と警告を出す（取り込み・手動・曲のタグ・ネットから取った歌詞のどれも同じ。原文はそのまま残す）
- 1行に書ける時刻は 100 個まで。1行に時刻を複数書いたときの本文の複製は、合計 4MiB まで（超えた分の時刻は使わず、警告を出す。極端な入力でメモリを食い尽くさないため）

#### 歌詞をネットから取る（v3.1.0）

**既定はオフ。**オフの間、アプリは外へ一切通信しない（歌詞を取る窓口は、Rust の入口で設定を確かめて断る。画面のボタンを隠すだけにはしていない）。オンにしても、通信するのはボタンを押したときだけ。

| 項目 | 中身 |
|---|---|
| 送り先 | `https://lrclib.net/api/get`（最初に）と `https://lrclib.net/api/search`（get で見つからないとき）の2つだけ |
| 送るもの | 曲のタグの曲名・アーティスト名・アルバム名（空でなければ）と、曲の長さ（秒に丸めた整数。1〜3600 のときだけ。search では曲名とアーティスト名だけ） |
| 送らないもの | ファイルの場所・ファイル名・曲 ID・ほかの情報（再生の記録・ライブラリのほかの曲など）。**タグに曲名が無く、ファイル名を曲名として表示している曲は送らない**（曲名がファイル名と同じ曲は、曲のタグを読み直し、タグに曲名があるときだけ送る）。名札（User-Agent）は `PL-Player/<版> (https://github.com/rr2pp2/pl-player)`（アプリ名・版・公開リポジトリの URL。v3.1.2。メール・ユーザー名は入れない） |
| 通信の作り | Windows の WinHTTP。HTTPS（TLS 1.2／1.3）だけ。プロキシは使わない（システムの設定も読まない）。リダイレクトはたどらない。クッキー・自動の認証は使わない |
| 間隔と再試行 | 1つずつ順に。要求の間を 300〜500ms 空ける。429 は `Retry-After` に最大 30% のゆらぎを足して待つ（300 秒を超えるか 5回続いたら全体を止める）。503 は `Retry-After`（無ければ 1 秒）＋ゆらぎで待つ（5回でその曲をエラー）。ほかの 5xx・通信エラーは 1・2・4・8 秒で再試行。タイムアウトは送受信 20 秒・読み切るまで 60 秒。応答は 16MiB を超えたら読むのをやめる。曲のエラーが 5曲続いたら止める |
| 一括（設定画面の「歌詞を取ってくる」） | 「歌詞の無い曲だけ」（既定）：手動・外部・曲のタグのどれにも歌詞が無い曲。前に見つからなかった・instrumental・大きすぎだった曲は聞き直さない（曲名・アーティスト名・アルバム名・長さを直した曲は聞き直す）。「外部の歌詞を取り直す」：外部の歌詞がある曲と、前に見つからなかった曲も聞き直す。どちらも、手動の歌詞がある曲・曲のタグに歌詞がある曲・タグに曲名かアーティスト名が無い曲は送らない。1曲ずつ、送る直前にその曲がまだあるか・手動の歌詞が付いていないかを確かめ直す（途中で外した曲・手動の歌詞を保存した曲は送らない）。最初に送る曲を選ぶ間は「準備中 ◯曲中◯曲」を出し、その間も「やめる」と設定のオフが効く。進み具合（何曲中何曲・取れた・見つからない）を出し、「やめる」で止まる（次の待ち・次の要求の前で止まる。送っている途中の1回は最長 20 秒待つことがある）。終わったら件数を知らせる |
| 1曲（歌詞画面の「ネットから探す」） | 「この曲の歌詞はありません」のところに、オンのときだけ出る。押したときは、前に見つからなかった曲でも聞き直す |
| 取れた歌詞 | 外部（external）として保存する。受け渡しフォルダの取り込みと同じ扱い（改行を LF にそろえる・1MiB まで・中身に時刻タグがあれば時刻つき）。時刻つきがあればそれ、無ければ全文。instrumental は歌詞なし |
| 守ること | **手動の歌詞は上書きしない**（手動の歌詞がある曲は送りもしない）。取り直しで取れなかったときは、今の外部の歌詞を消さずに残す |
| 選び方 | get は LRCLIB が「曲名・アーティスト・アルバム・長さ ±2 秒」で照合する。search の候補は、長さが ±2 秒以内で、曲名とアーティストの両方が一致か部分一致（大文字小文字・全角半角・記号を無視）し、instrumental でないものから、時刻つき → 曲名が一致 → アーティストが一致 → 長さの差が小さい の順で選ぶ。部分一致は、正規化して短い方が3文字以上で、長い方の半分以上の長さのときだけ。手元の長さが 0 の曲は、名前が両方とも一致するものだけ |
| 画面・ログに出すもの | 件数・曲 ID・状態だけ。取ってきた歌詞の本文と、LRCLIB が返した曲名などは出さない |
| 設定 | `lyricsOnline`（既定オフ）。保存と書き出し（zip）に入る。**設定の zip を読み込んだときは、中の値にかかわらずオフになる**（他人から受け取った zip で気づかないうちにオンにならないように。オンにするのは設定画面でだけ）。3.0.2 までの設定と v2 の書き出しには値が無いので、オフになる |

取得の決まりの詳細は `docs\歌詞機能_仕様.md` 10章。

### v2 と並べて使うときの注意

v3 は v2 と別のアプリ（識別子・データの場所・インストール先が別）なので、同時に起動できる。互いのライブラリ・設定・歌詞は書き換えない。

- **グローバルホットキーがぶつかる**：同じキー（例：v2 で使っている `Ctrl+Alt+P`）を v3 にも割り当てると、**後から起動したほうは登録に失敗する**（設定画面でそのキーが赤くなり「このキーは他のアプリが使っています」と出る）。アプリの既定では1つも登録しないが、**v2 の設定を書き出して v3 で読み込むと、ホットキーも一緒に入る**。並べて使うなら、どちらか一方だけに割り当てる
- **メディアキー**：両方が Windows のメディア操作（SMTC）に登録する。Windows は最後に操作されたほうへ送る
- **タスクトレイ**：両方のアイコンが出る。v3 のヒントは「PL Player 3」
- **ライブラリは別**：v3 は空のライブラリで始まる。v2 の「設定 → 設定のバックアップ → 書き出す…」で作った zip を、v3 の「読み込む…」で読むと、テーマ・背景・ショートカット・プレイリスト・お気に入り・ライブラリのフォルダが入る（曲 ID は v3 で振り直しになる）
- **曲ファイルのタグ**：どちらで編集しても同じファイルに書かれる（歌詞はどちらも曲ファイルに書かない）
- **`Ctrl+L`**：v3 のアプリ内ショートカット。v2 には無い

### 既知の制限

- **HE-AAC**：Media Foundation で鳴らすのは「Symphonia がデコーダを作れない AAC」（m4a の HE-AAC など、合図がファイルの頭に書いてあるもの）だけ。合図が頭に無い形（暗黙の合図。ADTS の `.aac` の HE-AAC など）は、今までどおり Symphonia が AAC-LC の部分だけを鳴らす（高い音が欠けて聞こえる）。HE-AAC v2（PS）は手元で作れず、確かめていない。Media Foundation の無い Windows（N エディションで Media Feature Pack を入れていないもの）では、今までどおり「非対応形式」になる（`mfplat.dll`・`mfreadwrite.dll` は遅延読み込みなので、無くても起動はできる。N エディションの実機では確かめていない）
- **古い文字コードのタグ**：UTF-8 を Latin-1 で読んだ化け方は直さない。Big5 の香港の拡張（HKSCS）の文字は、Windows のコードページ 950 が私用領域の文字に読むため直せない（ファイル名とも一致しない）。かなが無い値は、ほかの文字コードの化けと見分けるため、次のものを直さない（数は v3.1.2 の検査で、よくある漢字の語と英単語を空白なしでつないだ約9千通りで数えたもの）
  - **漢字と英字が空白なしで並ぶ値は、多くが直らない。**漢字のすぐ後ろに英字が続く形（「愛Love」「新宿Live」「夏Remix」「君Ver」）は約9割、英字のすぐ後ろに漢字が続く形（「MV集」「A館」「DJ吉田」）は約半分が直らない。西欧の文字の並びと同じバイトの形になるため。直る形もある（「A面」「TV版」「東京DOME」）。間に空白があれば直る（「DJ 池田」「Love 夜」）
  - 第二水準・拡張の漢字が半分以上の値（「髙橋」）。壮・奏・租・僧・痴・稚・壇・知 のどれか1文字だけが漢字の値（「奏」。英語の「’s」「’t」「’d」「’m」と同じバイトの形）。それ以外の漢字1文字だけの値（「池」）は直す
  - “ と同じバイトの漢字で始まり、株・券・諸・飼 などで終わり、途中に2バイト目が英字の漢字（新・市など）がある値（「東新株」。まれ）。「東部」「投票数」「特別券」は直す

  逆に、西欧などの値を日本語として読み直してしまう（漢字の列に変える）ことがある（まれ）
  - ドイツ語などの下付きの引用符 ‚…‘ で囲んだ値と、‚ や ƒ のすぐ後ろに英字が続く値（「Adagio ‚Rain‘」「Jean‚s」）。‚ のすぐ後ろがアクセント付きの文字でも起きる（「‚Über‘」→「まber」）。全角英数・かなと同じバイトの形になるため
  - 引用符で囲んだ外国語の短い語の後ろに、記号や語が続く値（「“Bílá” Remix」→「釘匀癆 Remix」、「“Дом”…」、「„Hűség“」）
  - 西欧・東欧の語を、ダッシュ・中黒・アポストロフィ・三点リーダーでスペースなしにつないだ値（「été–été」「Čaj–Řád」「Love–Řád」「L’Ô」「Love——」）。スペース・ハイフン・コンマ・スラッシュ・括弧でつなぐ形では起きない

  **一度直らなかった値は、自動では見直されない**（あとの版で決まりを変えても、曲ファイルが変わらない限り再走査では読み直さない）。v3.5.0 から、「設定 → ライブラリ」の「古い文字コードのタグを読み直す…」で見直せる。ただし 3.5.0 の決まりは 3.1.2 と同じなので、3.5.0 で押しても、取り込み済みの曲で新しく直る値はない（決まりを良くした版で効く）。

  **読み直しは、誤って漢字に変わった値を元に戻せない**（DB にはもう元の文字が無いため。曲ファイルは読まない）。直らなかった値・誤って変わった値は、タグの編集画面で直して保存すれば曲ファイルに書かれる。

  **3.4.0 までに編集画面で保存した値には、手で直した印が無い。**3.5.0 の決まりでは読み直しで変わらない（保存のときに同じ決まりを通っている）が、決まりを変えた版で読み直すと、印の無い値は手で直した値と見分けられない（決まりを変える版で、どう扱うかを決め直す）
- **年間まとめの記録は 3.6.0 から。**3.5.0 までの再生は入らない。3.6.0 のあとで 3.5.0 に戻して使った間の再生も、記録されない（3.5.0 は記録の表を知らないため。曲ごとの再生回数は増える。記録そのものは消えず、3.6.0 に戻すと続きから貯まる）。PC の時計を戻すと、戻す前の時刻の記録は、時計がそこへ追いつくまで数えない（先の時刻の記録は入れないため）
- **再生の記録を書けなかったときは、再生回数も増えない。**再生回数の +1 と年間まとめの記録を1つのトランザクションで書くため（数え方を1か所にそろえ、2つが食い違わないようにした）。ディスクがいっぱいなど、DB に書けないときだけ起きる。再生そのものは止まらない
- **年間まとめの記録は、設定のバックアップ（zip）に入らない**（ライブラリの DB の中にあり、ライブラリそのものと同じ扱い）
- **手で直した印は、設定のバックアップ（zip）に入らない。**別の PC やデータフォルダへ設定を戻しても、印は付いてこない。今の決まりのままなら困らない（取り込み直しで同じ決まりを通る）が、決まりを変えた版では、戻した先の手で直した値を見分けられない
- **Light テーマ**：背景の暗さを 0〜30% に下げて暗い背景画像を使うと、UI の不透明度を 74〜82% 以上にしないと基準に届かない（`docs\テーマの色の根拠.md` 6章）
- **Dark テーマ（v3.7.0 でも残るもの）**：既定の設定（背景の暗さ 45%・UI の不透明度 70%）で明るい背景画像（白）を使うと、選んだ行の補助の文字（アーティスト名など。`--c-secondary`）が 4.40:1 で、本文の基準 4.5:1 にわずかに届かない（3.6.0 と同じ。v3.7.0 では、設計案が変えない変数とした `--c-secondary`・`--c-selected` を変えていない）。飾りの区切り線（`--c-border`）も 3:1 に届かないが、操作部の境目には v3.7.0 から `--c-outline` を使う。どちらも、背景の暗さか UI の不透明度を上げると読みやすくなる（`docs\テーマの色の根拠.md` 9章）
- **3.6.0 までのスキン（Dark）**：v3.7.0 で Dark のアクセントの上の文字（`--c-accent-contrast`）の既定が白から黒になった。`--c-accent` だけを暗い色に変えているスキンでは、ボタンの上の文字が読みにくくなる。操作部の輪郭も `--c-border` ではなく `--c-outline` を見る。スキン側で `--c-accent-contrast`・`--c-outline` も書けば直る（`docs\スキンの作り方.md` 4章）。すでに入れてあるスキンには警告が出ない
- **v3.8.0 から 3.7.0 に戻すと**：「使わない」＋「窓が狭いときは自動でコンパクトにする」は、3.7.0 では「使わない」として読まれる（3.7.0 は新しいチェックを知らないため。設定の zip も同じ）。3.7.0 で「ウィンドウが狭いときだけ」を選び直せば戻る
- **遅れを測る（v3.8.0）は、デバイスを開いてから 3 秒待ってからクリックを鳴らす。**仮想ケーブルの出口は、開いてから 1.3〜2.0 秒ごろに、届くまでの遅れが約 10ms 跳ぶことがあった（2026-11-19 の作者の実機の診断。待ち 0.5 秒では3回のうち2回跳び、3 秒では3回とも跳ばなかった）。そのため測るのに通常は約 6 秒かかる。ただし跳ぶ時刻は毎回同じではなく、同じ日の 30 分の計測では開いてから約 10 秒後に 33ms → 23ms と跳び、そのあと 30 分は変わらなかった。3 秒待っても、跳ぶ前の値を測ることがある（出る値が「だいたいの値」なのは、これも理由の1つ）
- **遅れを測る（v3.8.0）で録る仮想ケーブルの出口は、OBS とは別に開いた流れ。**作者の実機では、出口に届くまでの遅れが開くたびに 16〜33ms と変わった。OBS が出口を開いているかでも大きく変わり、作者の実機では、OBS を閉じていると 27〜36ms、開いていると 2〜16ms だった（各10回）。**測った値は、OBS が受け取る遅れと数ミリ秒ずれることがある。**作者の実機で OBS の録画の中のずれを調べると 4.8ms（18組でほぼ一定）で、同じときにアプリが出した値は 10ms だった（アプリは OBS とは別に出口を開き直して測るため、と見ている。OBS の中で測る手段はこの版に無い）。耳でずれと感じる量よりは小さい。合わないと感じたら、OBS を起動したままで測り直すか、遅らせ量を手で詰める
- **v3.9.0 から 3.8.1 に戻すと**：追加した立ち絵とほかのスキンの立ち絵は出ない（3.8.1 は知らないため。`avatars\` のフォルダは残り、3.9.0 に戻すと選び直せる）。「出さない」は「立ち絵を出す」のオフとして読まれる（同じ見た目）。追加した立ち絵を選んでいたときは、3.8.1 では当てているスキンの立ち絵が出る
- **v3.7.0 の新しい色を書いたスキン**：`--c-outline`・`--c-favorite` は 3.6.0 までの版では知らない名前として警告して使わない（ほかの色は当たる）。この2つが要るスキンは `minAppVersion` を 3.7.0 にする（`docs\スキンの作り方.md`）

## 改造する人へ（ソースからビルドする）

### 2. セットアップ

```
npm ci
cd src-tauri
cargo fetch
```

`.npmrc` は `ignore-scripts=true`（依存のインストール時にスクリプトを走らせない）にしています。

プロジェクトは浅いフォルダ（`C:\src\pl-player` など）に置いてください。深いフォルダに置くと、ビルドの途中のファイルのパスが Windows の長さの上限（260 文字）を超え、C のコード（libopus）を組む段で cmake が「C compiler identification is unknown」で止まることがあります。

CMake は Build Tools の中のものを PATH に足す（Git Bash の例）：

```
export PATH="$PATH:/c/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin"
```

### 7. 主要アーキテクチャ

**UI と音声エンジンを密結合させない。**画面・SMTC（メディアキー）・グローバルホットキー・サムネイルボタン・トレイの操作は、全部 `playback`（司令塔）を通る。`audio` は「次の曲」を知らず、渡された1曲を鳴らす・止める・位置を変える・出力先を変える、だけ。

| 部品 | 中身 |
|---|---|
| 音声 | Symphonia 0.6（MP3・WAV・FLAC・M4A（AAC-LC/ALAC）・AAC（ADTS）・OGG Vorbis）＋ libopus（OPUS）でデコード → rubato でデバイスのレートへ変換 → リングバッファ → cpal（WASAPI）で出力。**Symphonia が読めない AAC（HE-AAC）だけ**、Windows の Media Foundation（`windows` クレートの機能。v3.1.2）で PCM に戻す。どちらで読んでも、その先（変換・出力・位置・シーク・出力先の切り替え）は同じ |
| 再生位置 | 「実際に鳴らしたフレーム数」から出す。だから**出力先を変えても曲と位置が保たれる**（出力だけを作り直してシークし直す）。v3.8.0：出力と別の仮想の再生時計（QPC の上）が位置と曲の終わりを決める。速さは基準の出力1つに寄せ、ほかの出力は倍率を少しずつ動かして合わせる（`docs\アーキテクチャ案.md` 4-1） |
| デバイスの切断 | v3.8.0：その出力先だけ「切断中」にして手放し、戻ったら自動でつなぎ直して今の位置から入れる（既定のデバイスへは移らない）。オンの出力先が全部鳴らせなくなったら一時停止（戻っても自動では再生しない）。3.7.0 までは既定のデバイスへ切り替えて続けていた |
| ライブラリ | SQLite（WAL）。検索は3文字以上が FTS5 trigram、1〜2文字は LIKE。曲一覧は見えている行だけ描く |
| タグの書き込み | 同じフォルダに一時ファイル → 書く → 読み直して照合・頭を復号 → `ReplaceFileW` で差し替え。途中で失敗したら元は触らない |
| Windows 連携 | SMTC（メディアキー・クイック設定のメディア操作）、タスクバーのサムネイルボタン（前・再生/一時停止・次）、トレイ、二重起動の防止、グローバルホットキー。ホットキーの登録・解除はメインのスレッドだけで行い、押されたときの処理は専用のスレッドへ渡す（v3.8.1。設定の保存とキーを押す瞬間が重なると止まったため。決まりと理由は `src-tauri\src\platform\windows\hotkeys.rs` の頭） |
| 画面 | 背景画像 → 覆い＋ぼかし → UI の3層。色・文字・角丸・影・動きはテーマ変数。幅が狭いと「サイドバー → 列 → ジャケット → 行の高さ」の順に縮む（v3.8.0：サイドバーはウィンドウの幅、列・ジャケット・行の高さ・自動のコンパクトは曲一覧の側（`.main`）の幅を ResizeObserver で測って決める。再生バーは自分の幅に中身が入るかで3列か1段か） |
| 着せ替え（v3.2.0） | スキンの zip は Rust が一時の場所で全部確かめ（名前・大きさ・zip の作り・skin.json・画像の全部のコマ）、確認のあとで `skins\<id>\` へ移す。画面はスキンの id と確認の印しか渡さず、Rust が返した `skins\` の中の画像のパスを asset の URL にするだけ。色と文字は許した CSS 変数だけを、当てる前にもう一度確かめて `<html>` に当てる。既定のスキンでは何も当てず、画面の作りも変えない。v3.9.0：立ち絵はスキンから切り離した。画像は Rust がファイルを選ぶ画面を出して、スキンの立ち絵と同じ確かめ（`skins::images`）を通し、画面へは見本（data: URL）と印だけを返す（パスを返さない）。作るときに `avatars-staging\<id>\` へ書いてから `avatars\<id>\` へ移す。どの立ち絵を出すかは Rust が「使う立ち絵」（設定の `skin.avatar`）から解き（`skins::avatars::resolve`）、画面はその結果（`pl://skin` の `character`）を出すだけ |
| 歌詞をネットから取る（v3.1.0） | 既定はオフ。通信は Windows の WinHTTP だけ（依存は足していない）。宛先は `https://lrclib.net/api/get` と `/api/search` の2つだけで、コードに許可リストとして持ち、URL を組むときと送る直前に照合する。HTTPS のみ・プロキシなし・リダイレクトはたどらない。別スレッドで1曲ずつ、間を空けて送る |
| 年間まとめ（v3.6.0） | 再生を始めたときに `play_count` を +1 するのと同じトランザクションで、1回ずつ記録を貯める（`play_history`）。画面を開くたびに、索引で 365 日の分だけを読み、曲ごとに数えて上位 100 曲を返す。記録は曲を外すと消える |
| 歌詞（v3） | 優先順は「手動 ＞ 外部（受け渡しフォルダ）＞ 曲ファイルの歌詞タグ」。手動と外部は SQLite、タグは表示のたびに読む（曲ファイルには書かない）。再生位置は既存の通知（`pl://playback`・`pl://position`）を画面側で `requestAnimationFrame` で補い、今の行が変わったときだけ表示を更新する |

### 8. 作者が配るときの手順

GitHub Releases に置く物は、いつも配布用ビルド（`npm run release`）で作る。ビルドした PC のフォルダの場所を exe に残さないため。

#### 前に揃えておくもの

- `npm ci` と `cargo fetch` が済んでいる（配布用ビルドは `CARGO_NET_OFFLINE=true` で、依存を取りに行かない）
- NSIS が `%LOCALAPPDATA%\tauri\NSIS` にある（一度 `npx tauri build` を走らせると置かれる。配布用ビルドは取りに行かず、無ければ止まる）
- 7-Zip（`C:\Program Files\7-Zip\7z.exe`）。インストーラーの中身を取り出して検査するのに使う
- CMake は PATH に無ければ、Visual Studio（Build Tools）に入っているものを自動で足す

#### 手順

1. 版を上げる：`package.json`・`src-tauri\tauri.conf.json`・`src-tauri\Cargo.toml` の3つ（揃っていないと止まる）
2. 使う人向けの README の型 `scripts\release-README.md` の「## <版> で変えたこと」を、今の版の中身に書き換える（見出しの版が今の版でないと止まる。ほかの `{{VERSION}}` は自動で埋まる）
3. プロジェクトのフォルダで `npm run release`（毎回まるごと組み直すので、手元の PC で約6分かかる）。前の版の配布物を起動している・開いているときは、何も動かさずに止まる。閉じてから `npm run release -- --skip-build` で、ビルドと検査の済んだ物から組み立て直せる（ビルドしたあとにソースの中身を変えていたら止まる。コミットしただけなら止まらない。下の「ほかの指定」）
4. できた物（`release\` の直下）：`PL-Player-<版>.zip`・`PL-Player-<版>-x64-setup.exe`・`PL-Player-<版>-x64-portable.exe`・`PL-Player-<版>.sha256.txt`。あわせて `release\PL-Player-<版>\` に zip の中身と同じもの（日本語の名前の exe 2つと README.md と、v3.9.1 から `見本\`）。前の物があれば `release\控え\<日時>\` へ動かす（消さない）
5. GitHub Releases に置く：`release\` の直下の4つを、**名前を変えずに**置く。説明に「署名なし。『PC が保護されました』と出たら『詳細情報 → 実行』」を書く

Releases に置く物の名前を英数字と `.` `_` `-` だけにしているのは、GitHub が空白や英数字以外を含む資産の名前を変えるため（[GitHub の文書](https://docs.github.com/en/rest/releases/assets)。変え方の決まりは書かれていない）。名前が変わると、SHA256 の一覧の名前と合わなくなる。一覧はフォルダを付けない資産の名前で書くので、落とした人が同じフォルダに置いて `sha256sum -c` か PowerShell で照らせる（照らし方は「使う人へ」の「入手」）。zip の中の exe は Releases の exe と同じ中身なので、一覧を分けていない

#### 配布用ビルドがやること

| 段 | 中身 |
|---|---|
| 前の確かめ | 版が揃っているか。README の型を埋められるか（埋めた README に今の版と違う版番号があれば、行ごとに出す。止めない）。リポジトリのファイル（git の管理下と、まだ足していないもの）に、この PC のフォルダの場所が無いか。7-Zip・NSIS・Tauri の CLI が手元にあるか。`--out` が `src-tauri\target\` の下か。**ここで止まれば、前に作った物は消さない** |
| ビルド | rustc の `--remap-path-prefix` で、ユーザーのホーム → `/build/home`、一時フォルダ（`TEMP`・`TMP`） → `/build/tmp`、cargo のホーム → `/build/cargo`、rustup のホーム → `/build/rustup`、プロジェクト → `/build/src` に置き換える。パスは実行のときに環境変数（`USERPROFILE`・`CARGO_HOME`・`RUSTUP_HOME`・`TEMP`）とフォルダの実際の名前から求める（リポジトリには書かない）。`CARGO_ENCODED_RUSTFLAGS` で渡すので、空白を含むフォルダでも切れない。前からある `RUSTFLAGS` は残してうしろに足す。C のコード（libopus・SQLite）の `__FILE__` は、MSVC の `cl.exe` の `/d1trimfile:<フォルダ>/` で同じフォルダの頭を落とす（`CFLAGS`・`CXXFLAGS` に足す。Microsoft の文書には無い指定なので、効いたかは検査で確かめる。空白を含むフォルダは渡せない）。置き場所は `src-tauri\target\dist`（ふだんの開発のビルドと混ぜない）で、毎回まるごと消してから組む（opusic-sys のビルドスクリプトは `CFLAGS` が変わっても組み直さないので、残りを使うと置き換えていない libopus が入る）。`--no-clean` で残りを使えるが、検査の試し用。終わったら `src-tauri\target\dist\build-info.json` に、版・ビルドした時刻・git のコミット・ソースの中身の指紋（git が見ているファイル＝追跡しているもの・まだ足していないものの、名前と中身から作る SHA256。コミットしても中身が同じなら変わらない）・exe とインストーラーの SHA256 を書く。ビルドの間にリポジトリのファイルの中身が変わったら止まる |
| 検査 | 下の「検査の仕組み」。1つでも見つかれば止まり、`release\` には何も置かない |
| 組み立て | README を型から作り、zip の中身（日本語の名前の exe 2つと README と、v3.9.1 から「見本」フォルダ。見本は `samples\` から `scripts\release-samples.mts` が組む：くじらの絵2枚・くもくじらの zip・使い方（型は `scripts\release-samples-README.md`）。配る PNG に作った PC やソフトを書ける塊（tEXt・iTXt・zTXt・eXIf・tIME・iCCP）があれば、前の確かめで止まる）を `release\PL-Player-<版>\` に置いて zip（名前は UTF-8 の印つき、区切りは `/`）にする。インストーラーと exe を Releases 用の名前でも写し、zip とその2つの SHA256 の一覧を作る。一覧を読み直して、同じフォルダの物と照らす |
| zip の確かめ | Windows の `Expand-Archive` で展開し、名前と SHA256 が置いた物と同じかを確かめる。Windows PowerShell 5.1（`powershell.exe`）へは環境から `PSModulePath` を外して渡す（PowerShell 7 の中から `npm run release` を走らせると、受け継いだ値のせいで 5.1 が 7 用の Archive モジュールを読み、`ExtractToDirectory` の引数の数の誤りで止まったため） |

v3.1.2 で数えた結果：ふつうのビルド（`npx tauri build`）の exe には、ユーザーのホームを含むパスが 565 か所あった（Rust の依存のソースの場所 421・libopus の C のファイル名 144。どれも cargo のホームの下）。配布用ビルドの exe・インストーラー・インストーラーから取り出した中身は 0 か所。

PDB の場所は、rustc が MSVC のリンカーに `/PDBALTPATH:%_PDB%` を渡していて、exe にはファイル名（`pl_player.pdb`）だけが入る（rustc の既定。[rust-lang/rust#87825](https://github.com/rust-lang/rust/issues/87825)）。検査でもフォルダが付いていないかを確かめる。build.rs の遅延読み込み（`/DELAYLOAD`）には触らない。

#### 検査の仕組み（`scripts\release-scan.mts`）

| 項目 | 中身 |
|---|---|
| 探すもの | ユーザーのホーム・一時フォルダ・cargo のホーム・rustup のホーム・プロジェクトのフォルダ（どれもこの PC の値）と、ドライブを問わない `Users\<ユーザー名>`・`Documents and Settings\<ユーザー名>`・`home/<ユーザー名>`。ユーザー名が3文字以上なら、`\<ユーザー名>\` だけのフォルダも |
| 探し方 | 区切りは `\`・`/`・`\\`（文字列の中で書いた形）のどれでも。英字は大文字小文字を問わない。ASCII／UTF-8 と UTF-16LE（偶数・奇数のどちらの位置から始まっても）。前の文字は問わない（Rust の文字列は区切りなしで並ぶ）。名前の続き（`<ユーザー名>2` など）は別のフォルダとみなす |
| 見るファイル | インストールせずに使う exe、インストーラー（setup.exe そのもの）、7-Zip でインストーラーから取り出したもの全部（中の exe・NSIS の部品）、画面のビルド結果（`dist\`）、NSIS の台本（`installer.nsi` など） |
| PDB | exe のデバッグ情報（CodeView）の PDB の名前にフォルダが付いていたら失敗 |
| インストーラーの中の exe | インストールせずに使う exe と比べ、Tauri が書き込む印（`__TAURI_BUNDLE_TYPE_VAR_UNK` → `…_NSS` の3バイト）のほかが同じかを確かめる |
| 参考 | ほかのユーザーのフォルダに見える名前（`X:\Users\<名前>`）と、8.3 形式の短い名前に見えるもの（前が `\` か `/` で、英数字と `_` `-` が1〜6文字、`~`、数字。今のユーザー名から作られる形に見えるものは `<ユーザー名の短い形>` に伏せる）は、一覧に出すだけで止めない |

単独でも走らせられる：`node scripts/release-scan.mts <ファイルかフォルダ> ...`。終了コードは、見つからなければ 0、見つかれば 1、検査しきれなかったとき（指定なし・無いパス・ファイルが1つも無いフォルダ）は 2。無いパスが混ざっていても、あるものは検査して結果を出し、無いパスもあわせて出す。そのとき1つでも見つかれば 1 を返す（2 より先）。ファイルの名前は、今いるフォルダからの相対で出す。

ほかの指定：

| 指定 | 中身 |
|---|---|
| `--skip-build` | ビルドせず、`src-tauri\target\dist` にある物を検査して組み立てる（検査は毎回する）。ビルドしたときの記録（`build-info.json`）と今を比べ、版・ソースの中身・exe とインストーラーの SHA256 のどれかが違えば、どれが違うかを出して止まる（ソースを直したあとに、直す前の exe を配らないため）。ソースの中身は、git が見ているファイル（追跡しているもの・まだ足していないもの）の今の名前と中身で比べるので、**ビルドしたあとにコミットしただけなら止まらない**（「ビルド → コミット → 配布物が使用中で止まる → 閉じて `--skip-build`」の流れ）。記録が無い・記録が古い形（3.1.2 の作業中の形）・git が使えないときも止まる。`--no-clean` で作った物は、`--out` を付けた試しのときだけ通す |
| `--out=<フォルダ>` | `release\` の代わりにそこへ組み立てる。試し用。`src-tauri\target\` の下だけ（`target` そのもの・ビルドのたびに消える `src-tauri\target\dist` とその中・ほかの場所は断る。`.git`・`src` などを書き換えないため）。比べる前に、名前の末尾の `.` と空白を落とし（Windows は落とした名前として扱う）、8.3 形式の短い名前（`SRC-TA~1` など）とジャンクションは実際の場所に直す。使えない文字（`<` `>` `:` `"` `|` `?` `*`）・予約された名前（`CON`・`NUL`・`COM1` など）・末尾が `.` か空白の名前も断る。ビルドの前に確かめる |
| `--no-clean` | 前のビルドの残りを使う。試し用 |
| `--no-7zip` | 下の「限界」 |

#### 検査で止まったときの見方

報告の1行目が `NG <ファイル>（… バイト）見つかった場所 <件数> 件`。続く行に、探したものの種類ごとの件数と、見つかった場所の前後の文字が出る（この PC のパスは `<ユーザーのホーム>`・`<cargo のホーム>` などに伏せてある）。

| 出た種類 | よくある原因と塞ぎ方 |
|---|---|
| `<cargo のホーム>`・`<rustup のホーム>`・`<プロジェクト>` | 置き換えが効いていない。`CARGO_ENCODED_RUSTFLAGS` を上書きする設定（`.cargo\config.toml` の `build.rustflags` など）が無いか、フォルダの書き方（大文字小文字・`\\?\` 付き）が違わないかを見る。依存が `env!("CARGO_MANIFEST_DIR")` などで場所を文字として埋めているなら、置き換えでは消えないので、その依存の使い方を変える |
| 前後の文字が `…\opus\src\opus_decoder.c` など C のファイル名 | C のコードの `__FILE__`（libopus は `OPUS_HARDENING` で、確かめの失敗の文にファイル名を入れる）。`/d1trimfile` が効いていない。`--no-clean` で古い libopus が残っていないか、`CFLAGS` を上書きする設定が無いかを見る |
| `<一時フォルダ>`・`Users\<ユーザー名>` だけ | ビルドスクリプトが埋めたもの。前後の文字から、どの部品かを探す |
| `PDB の名前: フォルダ付き（失敗）` | `/PDBALTPATH` を上書きするリンカーの指定が入っていないかを見る |
| `NG …installer.nsi:<行>` | NSIS の台本で、パスがインストーラーを動かすときの文字に入っている（Tauri の版を上げたときなど） |

#### 限界

- インストーラーの台本の部分（7-Zip が「Headers」と呼ぶ圧縮された部分）は、7-Zip でも取り出せない。そこは元の台本（`installer.nsi` と `.nsh`）で、パスがビルドのときだけ使う命令（`!define`・`!include`・`!addplugindir`・`File` など）の外で使われていないかを確かめている。台本から作られた後の中身そのものは見ていない
- 7-Zip が無い PC では `npm run release -- --no-7zip` で進められるが、インストーラーの中身の検査を飛ばす（setup.exe そのものと台本の検査は残る）
- ユーザー名が1〜2文字のときは、`\<ユーザー名>\` だけのフォルダは探さない（圧縮されたデータの偶然の並びに当たるため）。`Users\<ユーザー名>` とホームのパスは探す
- 8.3 形式の短い名前（`ABCDEF~1`）で止めるのは、一時フォルダの環境変数に入っている形だけ。ほかの短い名前は「参考」に出すだけ
- URL の形に直したパス（`C%3A%5CUsers%5C…` のようなパーセントエンコード）と、日本語のユーザー名を Shift_JIS（CP932）のバイトで書いたものは探さない
- `--skip-build` の照らし合わせは、git が見ているファイルだけ。`.gitignore` で外したファイル（`node_modules` の中など）を変えても気づかない
