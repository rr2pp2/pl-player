# PL Player 3

Windows 向けのローカル音楽プレイヤーです。手元の音楽ファイルを管理しながら、背景画像とアルバムアートで見た目を自分好みに変えられます。歌詞の表示（時刻つき歌詞の自動追従・再生バーの下を流れる歌詞の列）に対応しています。

**既定では、アプリは外へ一切通信しません。**例外は設定の「歌詞をネットから取る」だけで、オンにしてボタンを押したときに限り、[LRCLIB](https://lrclib.net/)（無料の歌詞データベース）へ曲のタグの曲名・アーティスト名・アルバム名と曲の長さを送ります。ファイルの場所やファイル名は送りません。

この README は2つに分かれています。

| 読む人 | 読むところ |
|---|---|
| ダウンロードして使うだけの人 | [使う人へ](#使う人へ)（入手・起動・データの場所・歌詞・既知の制限・通信） |
| ソースから自分でビルドする人・改造する人 | [改造する人へ](#改造する人へソースからビルドする)（開発環境・ビルド・テスト・構成。作者が配るときの手順も末尾に） |

## できること

- 音楽ファイルの取り込みと管理（MP3・WAV・FLAC・M4A（AAC-LC/HE-AAC/ALAC）・AAC・OGG Vorbis・OPUS）
- 古い文字コード（Shift_JIS など）で書かれたタグの文字化けを、読むときに直す（曲ファイルは書き換えない。v3.1.2）
- 曲一覧・アーティスト・アルバム・ジャンル・プレイリスト・キュー・お気に入り・検索
- タグの編集（曲名・アーティスト・アルバム・ジャケットなど。安全な差し替えで書き込み）
- 背景画像とテーマ（Dark / Light）、狭い幅に合わせて縮む画面
- 歌詞
  - 時刻つき歌詞（LRC）の自動追従、曲ごとの時刻補正、手入力
  - 再生バーの下を右から左へ流れる歌詞の列（オン・オフ可）。掛け合いの括弧は薄く表示
  - 曲ファイルに入っている歌詞・手で入れた歌詞・LRCLIB から取った歌詞の優先順
- Windows 連携：メディアキー（SMTC）・タスクバーのサムネイルボタン・トレイ・グローバルホットキー
- 再生中に出力デバイスを替えても、曲と位置を保つ
- 設定・プレイリスト・お気に入りの書き出しと読み込み（zip）

## 使う人へ

### 入手

[GitHub の Releases](https://github.com/rr2pp2/pl-player/releases) から、最新の版を落としてください。ソースからビルドする必要はありません。

| ファイル | 使い方 |
|---|---|
| `PL-Player-<版>-x64-setup.exe` | インストーラー。今のユーザーにだけ入れる（管理者権限は要らない）。スタートメニューに出る。消すときは Windows の「インストールされているアプリ」から |
| `PL-Player-<版>-x64-portable.exe` | インストールせずに、置いた場所からそのまま起動できる版。中身はインストーラーと同じ |
| `PL-Player-<版>.zip` | 上の2つと、使う人向けの README をまとめたもの。中の exe の名前は `PL Player 3_<版>_x64-setup.exe` と `PL Player 3（インストールせずに使う）.exe`（中身は上の2つと同じ） |
| `PL-Player-<版>.sha256.txt` | 上の3つの SHA256。落としたファイルが壊れていないか、差し替えられていないかを照らすときに使う |

どちらの exe を使っても、ライブラリ・設定は同じ場所に置かれます（下の「データの場所」）。

照らし方：落としたファイルと `PL-Player-<版>.sha256.txt` を同じフォルダに置き、そのフォルダで次のどちらかを打つ（`<版>` は落とした版の番号に）。名前を変えて保存したファイルは照らせません。

PowerShell（Windows に入っているもの）。落としたファイルごとに `OK` か `NG` が出る。一覧と同じ名前のファイルが1つも無いときは「照合できるファイルがありません」と出る：

```
$c = 0; Get-Content .\PL-Player-<版>.sha256.txt | ForEach-Object { $h, $n = $_ -split ' \*', 2; if (Test-Path -LiteralPath $n) { $c++; '{0}  {1}' -f $(if ((Get-FileHash -LiteralPath $n).Hash -eq $h) { 'OK' } else { 'NG' }), $n } }; if ($c -eq 0) { '照合できるファイルがありません（一覧と同じフォルダに、同じ名前で置いてください）' }
```

一覧の SHA256 は小文字、`Get-FileHash` が出す値は大文字で書かれるが、大文字小文字は問わない（同じ値。上の1行も大文字小文字を問わずに比べる）。目で照らすときは、英字の大小を無視して並びだけを見る。

Git Bash・WSL など `sha256sum` がある場所。落としていないファイルは飛ばす：

```
sha256sum -c --ignore-missing PL-Player-<版>.sha256.txt
```

### 「Windows によって PC が保護されました」と出たら

このアプリには、配った人を証明する署名（コード署名）を付けていません。そのため、初めて起動するときに Windows の青い画面（SmartScreen）が出ることがあります。画面の「詳細情報」を押し、下に出る「実行」を押すと起動します。

### 必要なもの

- Windows 10 / 11（x64）と WebView2 ランタイム（Windows 11 には標準で入っています）
- WebView2 は**入れる側の PC に既にある前提**です。インストーラーは WebView2 を取りに行きません。Windows 10 の古い環境などで WebView2 が無いと起動しないので、Microsoft の配布ページから WebView2 ランタイムを入れてください

### データの場所

- `%APPDATA%\jp.local.plplayer3\`（ライブラリの DB・アートの縮小版・背景画像・ログ・歌詞の受け渡しフォルダ `lyrics\`）
- 音声ファイルはコピーしない。元の場所を参照する
- 3.0.0 以降の版は、どれも同じ場所を使う。版を上げても、ライブラリ・設定・歌詞はそのまま

うまく動かないときと、通信のことは、下の「[既知の制限](#既知の制限)」と「[通信について](#通信について)」を見てください。

### 歌詞（v3）

#### 使い方

| やりたいこと | 操作 |
|---|---|
| 歌詞を見る | 再生バーの右端の「歌詞」ボタン、または `Ctrl+L`（設定の「ショートカット（アプリ内）」で変えられる）。中央の画面が歌詞に切り替わる |
| 閉じる | 歌詞画面の左上の戻るボタン、`Esc`、もう一度 `Ctrl+L`。開く前の画面へ戻る |
| 好きな行へ移動 | 時刻つきの歌詞の行をクリック（行にフォーカスして Enter でも） |
| 自動で追いかけるのを止める | ホイールやスクロールバーで動かすと止まり、上に「追従を止めています ／ 追従再開」が出る。最後に動かしてから 8 秒で戻る |
| 歌詞と音がずれる | 左の列の「−100ms」「+100ms」「リセット」。曲ごとに保存する。＋は歌詞を遅らせる |
| 歌詞を手で入れる・直す | 「歌詞を編集」。貼り付けると、時刻タグ（`[00:12.34]`）があれば時刻つき、無ければ時刻なしと判定して、保存前に行数・形式・警告を見せる。保存先はアプリの中（曲ファイルは変更しない） |
| 手で入れた歌詞を消す | 編集画面の「手動の歌詞を削除」（確認あり）。消すと外部の歌詞、次に曲のタグの歌詞に戻る |
| 外部ツールの歌詞を取り込む | 「設定 → ライブラリ → 外部歌詞を取り込む」（歌詞の無い曲の歌詞画面にも同じボタン）。取り込みはこのボタンを押したときだけ |
| 歌詞をネットから取る（v3.1.0） | 「設定 → 歌詞をネットから取る」でオンにしてから、「歌詞を取ってくる」（一括）か、歌詞の無い曲の歌詞画面の「ネットから探す」（1曲）。既定はオフ。下の「歌詞をネットから取る（v3.1.0）」 |
| 流れる歌詞の列を出す・隠す（v3.0.2） | 再生バーの「歌詞」ボタンのすぐ左のボタン、または `Ctrl+Shift+L`（設定の「ショートカット（アプリ内）」で変えられる）。オン・オフは保存され、次に起動したときも同じ。既定はオン |

**流れる歌詞の列（v3.0.2）**：再生バーの下に高さ 48px の列を出し、歌詞を横一列に並べる（今の行を左寄りに太く、右に次の行、その先を薄く）。行が変わったときだけ列全体が左へ流れる。曲の冒頭は「まもなく歌詞が始まります」、間奏は「♪ 間奏」、最後の「消す」合図の後は「♪ 後奏」、時刻なしは「時刻同期なし」、歌詞が無ければ「この曲には歌詞がありません」。歌詞画面を開いている間は隠れる。決まりの全文は `docs\歌詞機能_仕様.md` 6.5。

列と再生バーの1行では、括弧（`( )`・`（ ）`）とその中身（掛け合い・合いの手）を、同じ行の本体より一段薄く・小さく出す（v3.0.2）。閉じていない括弧は行末まで、開きの無い閉じ括弧は行頭からそこまでを括弧の中として扱う（行をまたぐ掛け合いのため。ただし顔文字「:)」や番号「1)」のように直前が `:` `;` `=` か数字なら本体のまま）。歌詞画面の見た目は変えていない。

**列がオフのときだけ**、再生バーの中に小さな歌詞の1行（v3.0.1）を出す：時刻つきのときアーティスト名の下に今の行を1行出し、その右に次の行を薄く出す（押すと歌詞画面）。次の行は「消す」合図と空の行を飛ばし、最後の行では出さない。幅が狭いとき（719px 以下）は今の行だけ。時刻なしは「時刻同期なし」、歌詞が無ければ何も出さない。

#### 受け渡しフォルダの取り決め（外部ツール向け）

外部ツール（歌詞を集める一括スクリプトなど）は、次の形でファイルを置く。v3.1.0 からはアプリ自身も LRCLIB から取れる（下の「歌詞をネットから取る」。既定はオフ）が、受け渡しフォルダはそのまま使える。

| 項目 | 取り決め |
|---|---|
| 置き場所 | `%APPDATA%\jp.local.plplayer3\lyrics\inbox\`（`PL_PLAYER_DATA_DIR` を指定したときは `<そのフォルダ>\lyrics\inbox\`）。「設定 → ライブラリ → 受け渡しフォルダを開く」で作られて開く |
| 曲 ID | v3 のライブラリの `tracks.id`。`%APPDATA%\jp.local.plplayer3\library.db` を**読み取り専用**で開いて引く（例：`SELECT id, path, title, artist, album, duration_ms FROM tracks`）。**v2 の DB の ID とは別物** |
| ファイル名 | `{曲ID}.lrc`（時刻つき）か `{曲ID}.txt`（時刻なし）だけ。正規表現で `^[0-9]+\.lrc$` か `^[0-9]+\.txt$` に合うもの。拡張子は小文字。合わない名前のファイルは読まずに残す。名前が合っていても、フォルダ・ジャンクション・リンクは読まずに残し、「読まなかったもの」に数える（v3.1.1） |
| 書き方 | 一時的な名前（例：`123.lrc.tmp`）で書き終えてから、`123.lrc` へ名前を変える（書きかけを拾わせないため） |
| 中身 | UTF-8（BOM はあってもよい）。改行は CRLF・CR・LF のどれでもよい。1ファイル 1MiB まで（それより先は読まない）。空・空白だけ・情報行だけのものは取り込まない |
| 1曲1ファイル | 同じ曲 ID に `.lrc` と `.txt` の両方を置かない（両方とも取り込まない）。曲 ID は数として比べるので、`02.lrc` と `2.txt` も同じ曲 ID の重複になる |
| 時刻つきの判定 | 拡張子は目安。中身に有効な時刻タグがあれば時刻つきとして扱う |
| 取り込んだあと | `lyrics\processed\{曲ID}-{yyyyMMdd-HHmmss}.{拡張子}` へ移る（時刻はこの PC の時刻） |
| 取り込めなかったもの | `lyrics\rejected\` へ移る：曲 ID がライブラリに無い・`.lrc` と `.txt` の重複・UTF-8 でない・空・大きすぎ |
| 残るもの | DB への保存やファイルの読み込みに失敗したものは `inbox` に残る（もう一度押せば取り込み直す） |
| 手動の歌詞 | 上書きしない。外部の歌詞は保存するが、表示は手動のまま（結果の件数で「手動の歌詞が優先のため表示は変わりません」と分けて知らせる） |
| 同じ曲をもう一度 | 外部の歌詞を上書きする |

読める LRC の書き方：

- 時刻タグ `[m:ss]`・`[mm:ss]`・`[mm:ss.f]`・`[mm:ss.ff]`・`[mm:ss.fff]`。分は1桁以上（60 以上も可）、秒は 00〜59。1行に時刻を複数書ける（`[00:12.00][01:30.00]同じ行`）
- `[ti:]` `[ar:]` `[al:]` `[by:]` `[offset:]` などの情報行は表示しない。`[offset:+200]` は**歌詞を 200ms 早める**（正の値で早める）
- 時刻だけで本文の無い行（`[00:30.00]`）は「今の行を消す」合図
- 語ごとの時刻 `<00:07.25>` は表示から外す（原文には残る）
- 時刻の順でなくても並べ替えて出す。読めない時刻（秒が 60 以上・小数が4桁以上など）は使わず、原文は残す
- 表示する時刻は `max(0, 元の時刻 − offset + 曲ごとの補正)`
- 歌詞の行は 5,000 行まで（v3.1.1）。超えた分は表示せず、「先頭の 5,000行だけを表示しています」と警告を出す（取り込み・手動・曲のタグ・ネットから取った歌詞のどれも同じ。原文はそのまま残す）
- 1行に書ける時刻は 100 個まで。1行に時刻を複数書いたときの本文の複製は、合計 4MiB まで（超えた分の時刻は使わず、警告を出す。極端な入力でメモリを食い尽くさないため）

#### 歌詞をネットから取る（v3.1.0）

**既定はオフ。**オフの間、アプリは外へ一切通信しない（歌詞を取る窓口は、Rust の入口で設定を確かめて断る。画面のボタンを隠すだけにはしていない）。オンにしても、通信するのはボタンを押したときだけ。

| 項目 | 中身 |
|---|---|
| 送り先 | `https://lrclib.net/api/get`（最初に）と `https://lrclib.net/api/search`（get で見つからないとき）の2つだけ |
| 送るもの | 曲のタグの曲名・アーティスト名・アルバム名（空でなければ）と、曲の長さ（秒に丸めた整数。1〜3600 のときだけ。search では曲名とアーティスト名だけ） |
| 送らないもの | ファイルの場所・ファイル名・曲 ID・ほかの情報（再生の記録・ライブラリのほかの曲など）。**タグに曲名が無く、ファイル名を曲名として表示している曲は送らない**（曲名がファイル名と同じ曲は、曲のタグを読み直し、タグに曲名があるときだけ送る）。名札（User-Agent）は `PL-Player/<版> (https://github.com/rr2pp2/pl-player)`（アプリ名・版・公開リポジトリの URL。v3.1.2。メール・ユーザー名は入れない） |
| 通信の作り | Windows の WinHTTP。HTTPS（TLS 1.2／1.3）だけ。プロキシは使わない（システムの設定も読まない）。リダイレクトはたどらない。クッキー・自動の認証は使わない |
| 間隔と再試行 | 1つずつ順に。要求の間を 300〜500ms 空ける。429 は `Retry-After` に最大 30% のゆらぎを足して待つ（300 秒を超えるか 5回続いたら全体を止める）。503 は `Retry-After`（無ければ 1 秒）＋ゆらぎで待つ（5回でその曲をエラー）。ほかの 5xx・通信エラーは 1・2・4・8 秒で再試行。タイムアウトは送受信 20 秒・読み切るまで 60 秒。応答は 16MiB を超えたら読むのをやめる。曲のエラーが 5曲続いたら止める |
| 一括（設定画面の「歌詞を取ってくる」） | 「歌詞の無い曲だけ」（既定）：手動・外部・曲のタグのどれにも歌詞が無い曲。前に見つからなかった・instrumental・大きすぎだった曲は聞き直さない（曲名・アーティスト名・アルバム名・長さを直した曲は聞き直す）。「外部の歌詞を取り直す」：外部の歌詞がある曲と、前に見つからなかった曲も聞き直す。どちらも、手動の歌詞がある曲・曲のタグに歌詞がある曲・タグに曲名かアーティスト名が無い曲は送らない。1曲ずつ、送る直前にその曲がまだあるか・手動の歌詞が付いていないかを確かめ直す（途中で外した曲・手動の歌詞を保存した曲は送らない）。最初に送る曲を選ぶ間は「準備中 ◯曲中◯曲」を出し、その間も「やめる」と設定のオフが効く。進み具合（何曲中何曲・取れた・見つからない）を出し、「やめる」で止まる（次の待ち・次の要求の前で止まる。送っている途中の1回は最長 20 秒待つことがある）。終わったら件数を知らせる |
| 1曲（歌詞画面の「ネットから探す」） | 「この曲の歌詞はありません」のところに、オンのときだけ出る。押したときは、前に見つからなかった曲でも聞き直す |
| 取れた歌詞 | 外部（external）として保存する。受け渡しフォルダの取り込みと同じ扱い（改行を LF にそろえる・1MiB まで・中身に時刻タグがあれば時刻つき）。時刻つきがあればそれ、無ければ全文。instrumental は歌詞なし |
| 守ること | **手動の歌詞は上書きしない**（手動の歌詞がある曲は送りもしない）。取り直しで取れなかったときは、今の外部の歌詞を消さずに残す |
| 選び方 | get は LRCLIB が「曲名・アーティスト・アルバム・長さ ±2 秒」で照合する。search の候補は、長さが ±2 秒以内で、曲名とアーティストの両方が一致か部分一致（大文字小文字・全角半角・記号を無視）し、instrumental でないものから、時刻つき → 曲名が一致 → アーティストが一致 → 長さの差が小さい の順で選ぶ。部分一致は、正規化して短い方が3文字以上で、長い方の半分以上の長さのときだけ。手元の長さが 0 の曲は、名前が両方とも一致するものだけ |
| 画面・ログに出すもの | 件数・曲 ID・状態だけ。取ってきた歌詞の本文と、LRCLIB が返した曲名などは出さない |
| 設定 | `lyricsOnline`（既定オフ）。保存と書き出し（zip）に入る。**設定の zip を読み込んだときは、中の値にかかわらずオフになる**（他人から受け取った zip で気づかないうちにオンにならないように。オンにするのは設定画面でだけ）。3.0.2 までの設定と v2 の書き出しには値が無いので、オフになる |

取得の決まりの詳細は `docs\歌詞機能_仕様.md` 10章。

#### 歌詞のデータ

| 種類 | 置き場所 |
|---|---|
| 手動（manual） | `library.db` の `lyrics_sources`（`source_kind = 'manual'`） |
| 外部（external） | `library.db` の `lyrics_sources`（`source_kind = 'external'`） |
| 曲ごとの補正 | `library.db` の `track_lyrics_settings` |
| ネットで見つからなかった曲（v3.1.0） | `library.db` の `lyrics_fetch_misses`（曲・結果（見つからない／instrumental／大きすぎ）・送った名前の印・日時）。「歌詞の無い曲だけ」で聞き直さないため |
| 曲ファイルの歌詞タグ | 保存しない。表示のたびに読む（MP3 の USLT、M4A の `©lyr` など。空でない最初の1件）。1MiB を超えるものは読み解かず、歌詞なし＋警告にする |

歌詞の原文は、受け渡しフォルダ・編集画面の見本・手動保存・曲のタグのどれも、1MiB を超えたら読み解かない。

曲をライブラリから外すと、その曲の手動・外部の歌詞と補正も消える。設定の書き出し（zip）に歌詞は入らない。

### 守りの決まり（v3.1.1）

ペネトレーションテスト（`docs\ペネトレーションテスト_v3.0.2.md`）の直し。ふだんの使い方は変わらない。

| 場面 | 決まり |
|---|---|
| 設定の読み込み（zip） | 96MB を超える zip・項目のデータが重なる zip・`settings.json` が無い／壊れている zip・ほかの JSON が壊れている zip は、何も変えずに断る。背景は画像として最後まで読めるものだけを `bg-<鍵>.<形式>` の名前で入れる。ライブラリのフォルダのうち、ネットワーク上の場所は入れない（件数を知らせる） |
| 設定の書き出し | 背景はデータフォルダの `backgrounds\` にあるものだけを入れる（`CON`・`NUL.png` などの予約デバイス名と、`:` を含む名前は使わない） |
| ネットワーク上の場所 | `\\` で始まる場所（UNC）とネットワークドライブは、取り込み・起動時の再走査・設定 zip のライブラリのフォルダ・「エクスプローラーで開く」で使わない。文字とドライブの種類だけで決め、そこへはつながない。USB メモリなどの取り外せるドライブは使える |
| 画像 | アルバムアート・背景・曲に埋め込む表紙は 50MB まで。最後まで画像として読めるものだけ。読むときのメモリは 128MiB まで |
| 細工した音声ファイル | サンプルレート 0 の WAV は非対応形式。取り込み・再生・タグの書き込みで部品が落ちても、その曲だけをエラーにして続ける（タグの一時ファイルは必ず消し、再生は再開する） |
| 歌詞 | 曲のタグの歌詞は 8MB を超える項目を読まない（MP3・AAC の頭の ID3v2 は、先頭の 0x00 を飛ばし、続くタグも全部確かめる（タグ 64 個・項目 10,000 個まで。超えたら読まない）。読んだあとにも大きさを確かめる。表紙が約 8MB を超える M4A・OGG は、歌詞のタグを読めず警告になる）。表示は 5,000 行まで |
| 画面の権限 | 画面に許すのは通知を受ける操作（listen・unlisten）だけ。画面が読める画像は `artwork\` と `backgrounds\` だけ |

**グローバルホットキーの注意**：修飾キー無しのキー（例：`A`）や `Ctrl+C` などを割り当てると、ほかのアプリでそのキーが効かなくなります（このアプリが先に受け取るため）。Ctrl・Alt・Shift を組み合わせた、ほかで使っていないキーにしてください。設定画面のホットキーの欄にも同じ注意を出しています（設定の zip から入ったものも同じ）。

### v2 と並べて使うときの注意

v3 は v2 と別のアプリ（識別子・データの場所・インストール先が別）なので、同時に起動できる。互いのライブラリ・設定・歌詞は書き換えない。

- **グローバルホットキーがぶつかる**：同じキー（例：v2 で使っている `Ctrl+Alt+P`）を v3 にも割り当てると、**後から起動したほうは登録に失敗する**（設定画面でそのキーが赤くなり「このキーは他のアプリが使っています」と出る）。アプリの既定では1つも登録しないが、**v2 の設定を書き出して v3 で読み込むと、ホットキーも一緒に入る**。並べて使うなら、どちらか一方だけに割り当てる
- **メディアキー**：両方が Windows のメディア操作（SMTC）に登録する。Windows は最後に操作されたほうへ送る
- **タスクトレイ**：両方のアイコンが出る。v3 のヒントは「PL Player 3」
- **ライブラリは別**：v3 は空のライブラリで始まる。v2 の「設定 → 設定のバックアップ → 書き出す…」で作った zip を、v3 の「読み込む…」で読むと、テーマ・背景・ショートカット・プレイリスト・お気に入り・ライブラリのフォルダが入る（曲 ID は v3 で振り直しになる）
- **曲ファイルのタグ**：どちらで編集しても同じファイルに書かれる（歌詞はどちらも曲ファイルに書かない）
- **`Ctrl+L`**：v3 のアプリ内ショートカット。v2 には無い

#### 古い文字コードのタグ（v3.1.2）

**曲ファイルは書き換えない。**読むたびに直す（編集画面で保存したときだけ、直した値が書かれる）。直すのは曲名・アーティスト・アルバム・アルバムアーティスト・ジャンル・作曲者・コメント（歌詞のタグは直さない）。

| 段 | 決まり |
|---|---|
| 1 | 値が U+0000〜U+00FF の文字だけでできている（1バイト1文字で読まれた形） |
| 2 | U+0080〜U+009F（C1 制御文字）を含む、または U+0080〜U+00FF の文字が3つ以上ある |
| 3 | バイトに戻して Shift_JIS（CP932）として読める。末尾の2バイト文字が切れて 1〜2 バイト足りないときは、そこを落として読む |
| 4 | 読んだ結果に私用領域の文字・置換文字（U+FFFD）・制御文字が無く、半角カナが2つ以上混ざらず、ASCII 以外の文字が1つはある |
| 守り | UTF-8 のバイトとして正しく読める値（UTF-8 を Latin-1 で読んだ別の化け方）は Shift_JIS として読まない。読んだ結果に、かな・全角英数が無いとき（漢字と英数字だけ）は、次のどれかに当たれば直さない：漢字が、第二水準・拡張の漢字（1・2バイト目とも 0x80 以上で、1バイト目が 0xE0 以上）と半角カナ・全角のギリシャ文字・キリル文字を合わせた数より多くない／値の全体が “…” か ‘…’ で囲まれ、閉じの ” ’ が西欧などの文字の並びの終わりに見える（閉じが前の文字と組にならずに残る、または前のアクセント付きの文字・キリル文字・ギリシャ文字のバイトと組になる。大文字の Š・Œ・Ž など、日本語の「株」「券」の1バイト目と同じバイトと組になるときは、ほかにも西欧などの文字の並びに見える文字があるときだけ）／漢字が英字と隣り合い、そのバイトが西欧・東欧の文字の並びに見える（2バイト目が ASCII の漢字の前か後ろに英字、2バイト目がアクセント付きの文字のバイトの漢字の後ろに英字、1バイト目がアクセント付きの文字のバイトの漢字の前に英字）／末尾を落として読んだのに漢字が1文字だけ／漢字がちょうど1つで、それが ‘ ’（0x91・0x92）＋小文字の s・t・d・m の形（英語の「’s」「’t」）。ほかの文字コードの化け（ロシア語「Небо」・ギリシャ語「Αθήνα」・東欧「Škoda Čaj」「pieśń」・韓国語「사랑」）や西欧の言葉（「Démon Épée」「Don’t Stop」「L’été」「—Élan」「“A”」「80’s」）を漢字に変えないため。「A面」「TV版」「LIVE武道館」「東京DOME」のように英字と空白なしで並ぶ日本語の一部と、“ ‘ と同じバイトの漢字で始まり ” ’ と同じバイトで終わる日本語（「東部」「投票数」「特別券」。“ は東・南・内・投・登・得・読などの1バイト目、” は部・数・株・券・灯などの2バイト目と同じ）は直す |
| ほかの文字コード | Shift_JIS で読めないときだけ、EUC-JP・GBK・Big5 も試す。誤りやすいので、読んだ結果がファイル名（拡張子と先頭の曲順の数字を除いたもの、または拡張子だけ除いたもの）と同じときだけ採る |
| 変えないもの | 本物のアクセント付きの名前（「Raison d'être」）、「×」を含む名前、ふつうの英語。1MiB を超える値は見ない |

変換は Windows の `MultiByteToWideChar`（コードページ 932・20932・936・950）。新しい部品は足していない。

### 既知の制限

- **HE-AAC**：Media Foundation で鳴らすのは「Symphonia がデコーダを作れない AAC」（m4a の HE-AAC など、合図がファイルの頭に書いてあるもの）だけ。合図が頭に無い形（暗黙の合図。ADTS の `.aac` の HE-AAC など）は、今までどおり Symphonia が AAC-LC の部分だけを鳴らす（高い音が欠けて聞こえる）。HE-AAC v2（PS）は手元で作れず、確かめていない。Media Foundation の無い Windows（N エディションで Media Feature Pack を入れていないもの）では、今までどおり「非対応形式」になる（`mfplat.dll`・`mfreadwrite.dll` は遅延読み込みなので、無くても起動はできる。N エディションの実機では確かめていない）
- **古い文字コードのタグ**：UTF-8 を Latin-1 で読んだ化け方は直さない。Big5 の香港の拡張（HKSCS）の文字は、Windows のコードページ 950 が私用領域の文字に読むため直せない（ファイル名とも一致しない）。かなが無い値は、ほかの文字コードの化けと見分けるため、次のものを直さない（数は v3.1.2 の検査で、よくある漢字の語と英単語を空白なしでつないだ約9千通りで数えたもの）
  - **漢字と英字が空白なしで並ぶ値は、多くが直らない。**漢字のすぐ後ろに英字が続く形（「愛Love」「新宿Live」「夏Remix」「君Ver」）は約9割、英字のすぐ後ろに漢字が続く形（「MV集」「A館」「DJ吉田」）は約半分が直らない。西欧の文字の並びと同じバイトの形になるため。直る形もある（「A面」「TV版」「東京DOME」）。間に空白があれば直る（「DJ 池田」「Love 夜」）
  - 第二水準・拡張の漢字が半分以上の値（「髙橋」）。壮・奏・租・僧・痴・稚・壇・知 のどれか1文字だけが漢字の値（「奏」。英語の「’s」「’t」「’d」「’m」と同じバイトの形）。それ以外の漢字1文字だけの値（「池」）は直す
  - “ と同じバイトの漢字で始まり、株・券・諸・飼 などで終わり、途中に2バイト目が英字の漢字（新・市など）がある値（「東新株」。まれ）。「東部」「投票数」「特別券」は直す

  逆に、西欧などの値を日本語として読み直してしまう（漢字の列に変える）ことがある（まれ）
  - ドイツ語などの下付きの引用符 ‚…‘ で囲んだ値と、‚ や ƒ のすぐ後ろに英字が続く値（「Adagio ‚Rain‘」「Jean‚s」）。‚ のすぐ後ろがアクセント付きの文字でも起きる（「‚Über‘」→「まber」）。全角英数・かなと同じバイトの形になるため
  - 引用符で囲んだ外国語の短い語の後ろに、記号や語が続く値（「“Bílá” Remix」→「釘匀癆 Remix」、「“Дом”…」、「„Hűség“」）
  - 西欧・東欧の語を、ダッシュ・中黒・アポストロフィ・三点リーダーでスペースなしにつないだ値（「été–été」「Čaj–Řád」「Love–Řád」「L’Ô」「Love——」）。スペース・ハイフン・コンマ・スラッシュ・括弧でつなぐ形では起きない

  **一度直らなかった値は、3.1.2 を最初に起動したとき（DB の移行 4）のあとは自動では見直されない**（あとの版で決まりを変えても、曲ファイルが変わらない限り再走査でも読み直さないので、今の表示のまま）。直らなかった値・誤って変わった値は、タグの編集画面で直して保存すれば曲ファイルに書かれる
- **Light テーマ**：背景の暗さを 0〜30% に下げて暗い背景画像を使うと、UI の不透明度を 74〜82% 以上にしないと基準に届かない（`docs\テーマの色の根拠.md` 6章）

```

`.npmrc` は `ignore-scripts=true`（依存のインストール時にスクリプトを走らせない）にしています。

export PATH="$PATH:/c/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin"
```

### 7. 主要アーキテクチャ

**UI と音声エンジンを密結合させない。**画面・SMTC（メディアキー）・グローバルホットキー・サムネイルボタン・トレイの操作は、全部 `playback`（司令塔）を通る。`audio` は「次の曲」を知らず、渡された1曲を鳴らす・止める・位置を変える・出力先を変える、だけ。

| 部品 | 中身 |
|---|---|
| 音声 | Symphonia 0.6（MP3・WAV・FLAC・M4A（AAC-LC/ALAC）・AAC（ADTS）・OGG Vorbis）＋ libopus（OPUS）でデコード → rubato でデバイスのレートへ変換 → リングバッファ → cpal（WASAPI）で出力。**Symphonia が読めない AAC（HE-AAC）だけ**、Windows の Media Foundation（`windows` クレートの機能。v3.1.2）で PCM に戻す。どちらで読んでも、その先（変換・出力・位置・シーク・出力先の切り替え）は同じ |
| 再生位置 | 「実際に鳴らしたフレーム数」から出す。だから**出力先を変えても曲と位置が保たれる**（出力だけを作り直してシークし直す） |
| デバイスの切断 | 既定のデバイスへ切り替えて続け、「◯◯が切断されたので、△△で再生を続けます」と知らせる。既定も無ければ一時停止 |
| ライブラリ | SQLite（WAL）。検索は3文字以上が FTS5 trigram、1〜2文字は LIKE。曲一覧は見えている行だけ描く |
| タグの書き込み | 同じフォルダに一時ファイル → 書く → 読み直して照合・頭を復号 → `ReplaceFileW` で差し替え。途中で失敗したら元は触らない |
| Windows 連携 | SMTC（メディアキー・クイック設定のメディア操作）、タスクバーのサムネイルボタン（前・再生/一時停止・次）、トレイ、二重起動の防止 |
| 画面 | 背景画像 → 覆い＋ぼかし → UI の3層。色・文字・角丸・影・動きはテーマ変数。幅が狭いと「サイドバー → 列 → ジャケット → 行の高さ」の順に縮む |
| 歌詞をネットから取る（v3.1.0） | 既定はオフ。通信は Windows の WinHTTP だけ（依存は足していない）。宛先は `https://lrclib.net/api/get` と `/api/search` の2つだけで、コードに許可リストとして持ち、URL を組むときと送る直前に照合する。HTTPS のみ・プロキシなし・リダイレクトはたどらない。別スレッドで1曲ずつ、間を空けて送る |
| 歌詞（v3） | 優先順は「手動 ＞ 外部（受け渡しフォルダ）＞ 曲ファイルの歌詞タグ」。手動と外部は SQLite、タグは表示のたびに読む（曲ファイルには書かない）。再生位置は既存の通知（`pl://playback`・`pl://position`）を画面側で `requestAnimationFrame` で補い、今の行が変わったときだけ表示を更新する |

### 8. 作者が配るときの手順

GitHub Releases に置く物は、いつも配布用ビルド（`npm run release`）で作る。ビルドした PC のフォルダの場所を exe に残さないため。

#### 前に揃えておくもの

- `npm ci` と `cargo fetch` が済んでいる（配布用ビルドは `CARGO_NET_OFFLINE=true` で、依存を取りに行かない）
- NSIS が `%LOCALAPPDATA%\tauri\NSIS` にある（一度 `npx tauri build` を走らせると置かれる。配布用ビルドは取りに行かず、無ければ止まる）
- 7-Zip（`C:\Program Files\7-Zip\7z.exe`）。インストーラーの中身を取り出して検査するのに使う
- CMake は PATH に無ければ、Visual Studio（Build Tools）に入っているものを自動で足す

#### 手順

1. 版を上げる：`package.json`・`src-tauri\tauri.conf.json`・`src-tauri\Cargo.toml` の3つ（揃っていないと止まる）
2. 使う人向けの README の型 `scripts\release-README.md` の「## <版> で変えたこと」を、今の版の中身に書き換える（見出しの版が今の版でないと止まる。ほかの `{{VERSION}}` は自動で埋まる）
3. プロジェクトのフォルダで `npm run release`（毎回まるごと組み直すので、手元の PC で約6分かかる）。前の版の配布物を起動している・開いているときは、何も動かさずに止まる。閉じてから `npm run release -- --skip-build` で、ビルドと検査の済んだ物から組み立て直せる（ビルドしたあとにソースの中身を変えていたら止まる。コミットしただけなら止まらない。下の「ほかの指定」）
4. できた物（`release\` の直下）：`PL-Player-<版>.zip`・`PL-Player-<版>-x64-setup.exe`・`PL-Player-<版>-x64-portable.exe`・`PL-Player-<版>.sha256.txt`。あわせて `release\PL-Player-<版>\` に zip の中身と同じもの（日本語の名前の exe 2つと README.md）。前の物があれば `release\控え\<日時>\` へ動かす（消さない）
5. GitHub Releases に置く：`release\` の直下の4つを、**名前を変えずに**置く。説明に「署名なし。『PC が保護されました』と出たら『詳細情報 → 実行』」を書く

Releases に置く物の名前を英数字と `.` `_` `-` だけにしているのは、GitHub が空白や英数字以外を含む資産の名前を変えるため（[GitHub の文書](https://docs.github.com/en/rest/releases/assets)。変え方の決まりは書かれていない）。名前が変わると、SHA256 の一覧の名前と合わなくなる。一覧はフォルダを付けない資産の名前で書くので、落とした人が同じフォルダに置いて `sha256sum -c` か PowerShell で照らせる（照らし方は「使う人へ」の「入手」）。zip の中の exe は Releases の exe と同じ中身なので、一覧を分けていない

#### 配布用ビルドがやること

| 段 | 中身 |
|---|---|
| 前の確かめ | 版が揃っているか。README の型を埋められるか（埋めた README に今の版と違う版番号があれば、行ごとに出す。止めない）。リポジトリのファイル（git の管理下と、まだ足していないもの）に、この PC のフォルダの場所が無いか。7-Zip・NSIS・Tauri の CLI が手元にあるか。`--out` が `src-tauri\target\` の下か。**ここで止まれば、前に作った物は消さない** |
| ビルド | rustc の `--remap-path-prefix` で、ユーザーのホーム → `/build/home`、一時フォルダ（`TEMP`・`TMP`） → `/build/tmp`、cargo のホーム → `/build/cargo`、rustup のホーム → `/build/rustup`、プロジェクト → `/build/src` に置き換える。パスは実行のときに環境変数（`USERPROFILE`・`CARGO_HOME`・`RUSTUP_HOME`・`TEMP`）とフォルダの実際の名前から求める（リポジトリには書かない）。`CARGO_ENCODED_RUSTFLAGS` で渡すので、空白を含むフォルダでも切れない。前からある `RUSTFLAGS` は残してうしろに足す。C のコード（libopus・SQLite）の `__FILE__` は、MSVC の `cl.exe` の `/d1trimfile:<フォルダ>/` で同じフォルダの頭を落とす（`CFLAGS`・`CXXFLAGS` に足す。Microsoft の文書には無い指定なので、効いたかは検査で確かめる。空白を含むフォルダは渡せない）。置き場所は `src-tauri\target\dist`（ふだんの開発のビルドと混ぜない）で、毎回まるごと消してから組む（opusic-sys のビルドスクリプトは `CFLAGS` が変わっても組み直さないので、残りを使うと置き換えていない libopus が入る）。`--no-clean` で残りを使えるが、検査の試し用。終わったら `src-tauri\target\dist\build-info.json` に、版・ビルドした時刻・git のコミット・ソースの中身の指紋（git が見ているファイル＝追跡しているもの・まだ足していないものの、名前と中身から作る SHA256。コミットしても中身が同じなら変わらない）・exe とインストーラーの SHA256 を書く。ビルドの間にリポジトリのファイルの中身が変わったら止まる |
| 検査 | 下の「検査の仕組み」。1つでも見つかれば止まり、`release\` には何も置かない |
| 組み立て | README を型から作り、zip の中身（日本語の名前の exe 2つと README）を `release\PL-Player-<版>\` に置いて zip（名前は UTF-8 の印つき、区切りは `/`）にする。インストーラーと exe を Releases 用の名前でも写し、zip とその2つの SHA256 の一覧を作る。一覧を読み直して、同じフォルダの物と照らす |
| zip の確かめ | Windows の `Expand-Archive` で展開し、名前と SHA256 が置いた物と同じかを確かめる |

v3.1.2 で数えた結果：ふつうのビルド（`npx tauri build`）の exe には、ユーザーのホームを含むパスが 565 か所あった（Rust の依存のソースの場所 421・libopus の C のファイル名 144。どれも cargo のホームの下）。配布用ビルドの exe・インストーラー・インストーラーから取り出した中身は 0 か所。

PDB の場所は、rustc が MSVC のリンカーに `/PDBALTPATH:%_PDB%` を渡していて、exe にはファイル名（`pl_player.pdb`）だけが入る（rustc の既定。[rust-lang/rust#87825](https://github.com/rust-lang/rust/issues/87825)）。検査でもフォルダが付いていないかを確かめる。build.rs の遅延読み込み（`/DELAYLOAD`）には触らない。

#### 検査の仕組み（`scripts\release-scan.mts`）

| 項目 | 中身 |
|---|---|
| 探すもの | ユーザーのホーム・一時フォルダ・cargo のホーム・rustup のホーム・プロジェクトのフォルダ（どれもこの PC の値）と、ドライブを問わない `Users\<ユーザー名>`・`Documents and Settings\<ユーザー名>`・`home/<ユーザー名>`。ユーザー名が3文字以上なら、`\<ユーザー名>\` だけのフォルダも |
| 探し方 | 区切りは `\`・`/`・`\\`（文字列の中で書いた形）のどれでも。英字は大文字小文字を問わない。ASCII／UTF-8 と UTF-16LE（偶数・奇数のどちらの位置から始まっても）。前の文字は問わない（Rust の文字列は区切りなしで並ぶ）。名前の続き（`<ユーザー名>2` など）は別のフォルダとみなす |
| 見るファイル | インストールせずに使う exe、インストーラー（setup.exe そのもの）、7-Zip でインストーラーから取り出したもの全部（中の exe・NSIS の部品）、画面のビルド結果（`dist\`）、NSIS の台本（`installer.nsi` など） |
| PDB | exe のデバッグ情報（CodeView）の PDB の名前にフォルダが付いていたら失敗 |
| インストーラーの中の exe | インストールせずに使う exe と比べ、Tauri が書き込む印（`__TAURI_BUNDLE_TYPE_VAR_UNK` → `…_NSS` の3バイト）のほかが同じかを確かめる |
| 参考 | ほかのユーザーのフォルダに見える名前（`X:\Users\<名前>`）と、8.3 形式の短い名前に見えるもの（前が `\` か `/` で、英数字と `_` `-` が1〜6文字、`~`、数字。今のユーザー名から作られる形に見えるものは `<ユーザー名の短い形>` に伏せる）は、一覧に出すだけで止めない |

単独でも走らせられる：`node scripts/release-scan.mts <ファイルかフォルダ> ...`。終了コードは、見つからなければ 0、見つかれば 1、検査しきれなかったとき（指定なし・無いパス・ファイルが1つも無いフォルダ）は 2。無いパスが混ざっていても、あるものは検査して結果を出し、無いパスもあわせて出す。そのとき1つでも見つかれば 1 を返す（2 より先）。ファイルの名前は、今いるフォルダからの相対で出す。

ほかの指定：

| 指定 | 中身 |
|---|---|
| `--skip-build` | ビルドせず、`src-tauri\target\dist` にある物を検査して組み立てる（検査は毎回する）。ビルドしたときの記録（`build-info.json`）と今を比べ、版・ソースの中身・exe とインストーラーの SHA256 のどれかが違えば、どれが違うかを出して止まる（ソースを直したあとに、直す前の exe を配らないため）。ソースの中身は、git が見ているファイル（追跡しているもの・まだ足していないもの）の今の名前と中身で比べるので、**ビルドしたあとにコミットしただけなら止まらない**（「ビルド → コミット → 配布物が使用中で止まる → 閉じて `--skip-build`」の流れ）。記録が無い・記録が古い形（3.1.2 の作業中の形）・git が使えないときも止まる。`--no-clean` で作った物は、`--out` を付けた試しのときだけ通す |
| `--out=<フォルダ>` | `release\` の代わりにそこへ組み立てる。試し用。`src-tauri\target\` の下だけ（`target` そのもの・ビルドのたびに消える `src-tauri\target\dist` とその中・ほかの場所は断る。`.git`・`src` などを書き換えないため）。比べる前に、名前の末尾の `.` と空白を落とし（Windows は落とした名前として扱う）、8.3 形式の短い名前（`SRC-TA~1` など）とジャンクションは実際の場所に直す。使えない文字（`<` `>` `:` `"` `|` `?` `*`）・予約された名前（`CON`・`NUL`・`COM1` など）・末尾が `.` か空白の名前も断る。ビルドの前に確かめる |
| `--no-clean` | 前のビルドの残りを使う。試し用 |
| `--no-7zip` | 下の「限界」 |

#### 検査で止まったときの見方

報告の1行目が `NG <ファイル>（… バイト）見つかった場所 <件数> 件`。続く行に、探したものの種類ごとの件数と、見つかった場所の前後の文字が出る（この PC のパスは `<ユーザーのホーム>`・`<cargo のホーム>` などに伏せてある）。

| 出た種類 | よくある原因と塞ぎ方 |
|---|---|
| `<cargo のホーム>`・`<rustup のホーム>`・`<プロジェクト>` | 置き換えが効いていない。`CARGO_ENCODED_RUSTFLAGS` を上書きする設定（`.cargo\config.toml` の `build.rustflags` など）が無いか、フォルダの書き方（大文字小文字・`\\?\` 付き）が違わないかを見る。依存が `env!("CARGO_MANIFEST_DIR")` などで場所を文字として埋めているなら、置き換えでは消えないので、その依存の使い方を変える |
| 前後の文字が `…\opus\src\opus_decoder.c` など C のファイル名 | C のコードの `__FILE__`（libopus は `OPUS_HARDENING` で、確かめの失敗の文にファイル名を入れる）。`/d1trimfile` が効いていない。`--no-clean` で古い libopus が残っていないか、`CFLAGS` を上書きする設定が無いかを見る |
| `<一時フォルダ>`・`Users\<ユーザー名>` だけ | ビルドスクリプトが埋めたもの。前後の文字から、どの部品かを探す |
| `PDB の名前: フォルダ付き（失敗）` | `/PDBALTPATH` を上書きするリンカーの指定が入っていないかを見る |
| `NG …installer.nsi:<行>` | NSIS の台本で、パスがインストーラーを動かすときの文字に入っている（Tauri の版を上げたときなど） |

#### 限界

- インストーラーの台本の部分（7-Zip が「Headers」と呼ぶ圧縮された部分）は、7-Zip でも取り出せない。そこは元の台本（`installer.nsi` と `.nsh`）で、パスがビルドのときだけ使う命令（`!define`・`!include`・`!addplugindir`・`File` など）の外で使われていないかを確かめている。台本から作られた後の中身そのものは見ていない
- 7-Zip が無い PC では `npm run release -- --no-7zip` で進められるが、インストーラーの中身の検査を飛ばす（setup.exe そのものと台本の検査は残る）
- ユーザー名が1〜2文字のときは、`\<ユーザー名>\` だけのフォルダは探さない（圧縮されたデータの偶然の並びに当たるため）。`Users\<ユーザー名>` とホームのパスは探す
- 8.3 形式の短い名前（`ABCDEF~1`）で止めるのは、一時フォルダの環境変数に入っている形だけ。ほかの短い名前は「参考」に出すだけ
- URL の形に直したパス（`C%3A%5CUsers%5C…` のようなパーセントエンコード）と、日本語のユーザー名を Shift_JIS（CP932）のバイトで書いたものは探さない
- `--skip-build` の照らし合わせは、git が見ているファイルだけ。`.gitignore` で外したファイル（`node_modules` の中など）を変えても気づかない
